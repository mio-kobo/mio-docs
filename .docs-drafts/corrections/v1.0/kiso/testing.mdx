仅 mio test 注册测试报告 MMA 接口。普通 check/run 的注册表没有该接口，不能将 import 成功当作普通程序支持。测试文件名以 _test.mio 结束，顶层函数名以 test_ 开头，零参数、非泛型、返回 unit。

支持范围：本页示例通过 Go 引导 CLI / Mochi VM 验证；错误分支覆盖范围见 [验证报告](/docs/v1.0/tooling/verification)，不表示每个函数的每条分支均实测。Native AOT 与纯 Mio 后端需按 [当前阶段](/docs/v1.0/internals/native-aot) 单独评估。

## 函数

签名中的参数名及类型保持源码原样；下文说明参数含义、返回值及错误。除明确返回错误值的路径外，数组分配、转换和 VM 指令预算等资源限制仍可能导致运行时错误。

### expect

```text
koukai waza expect(condition: bool, message: string) -> unit
```

参数：`condition`：断言条件；`message`：失败时记录的说明。

condition 为 iie 时记录 message 失败；不会通过异常中断当前函数。

### fail

```text
koukai waza fail(message: string) -> unit
```

参数：`message`：失败时记录的说明。

无条件记录 message 失败。

## 完整示例

保存为 `example_test.mio`，在该目录执行 `mio test . --format=json --lang=en-US`。测试发现并通过 `test_answer`。JSON 的 duration 字段随运行变化，报告以结构化 summary.passed=1、failed=0 验证；该代码是测试包，仅由 mio test 执行。

```mio mode="test" title="example_test.mio"
yobu "kiso/testing";
waza test_answer() -> unit { testing.expect(6 * 7 == 42, "answer"); }
```
