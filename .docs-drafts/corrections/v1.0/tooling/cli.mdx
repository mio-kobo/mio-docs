**版本范围：v1.0 · Stable**，固定提交 `51f1ba883767c1fc08ba415fbb0075316ff03106`；Go 引导 CLI / Mochi VM。此页不描述其他提交或未提交开发接口。

本页描述快照中的 Go 引导 CLI，版本字符串为 `Mio 1.0.0-beta.2`。命令由 `cmd/mio/main.go`、`test_command.go` 解析，不据帮助标题推断未实现参数。

## 命令

| 命令 | 行为 |
| --- | --- |
| `mio version` | 输出版本字符串 |
| `mio help`、`mio -h`、`mio --help` | 输出用法 |
| `mio check <file-or-directory>` | 加载包、折叠常量、解析名称、检查类型；成功输出 `check passed` |
| `mio run <file-or-directory>` | 同上，再生成字节码并在 VM 中运行 |
| `mio build <source> [-o <file.mochi>]` | 验证并原子写入 Mochi 文件，成功无 stdout；也接受 `build -o <output> <source>` |
| `mio exec <file.mochi>` | 解码验证并在 VM 执行 |
| `mio disasm <file.mochi>` | 解码验证，输出 globals、constants、instructions、functions/captures |
| `mio test <directory-or-./...>` | 发现并运行 Mio 测试包 |

build 不指定 -o 时，用入口路径去掉扩展名后加 `.mochi`。输出目录必须存在。这里的 build 生成字节码；生成 ARM64 Mach-O 使用下文独立工具。

run/exec 除 chant 外，还会打印 VM 最后保存的普通表达式值；不要把任意表达式语句当作完全没有 stdout 的操作。run 不接受入口之后的程序参数。没有 `mio native`、`--release`、`--watch`、`--heap-mib` 等推断出的主 CLI 参数。

本版未提供 `mio lsp` 命令；以该命令启动会输出用法并退出 2。语言服务来自后续开发线，不能按 V2 文档配置为 V1 内置能力。

## 诊断

check/run 支持以下精确写法，可放在路径前后：

```sh
mio check --format=json --color=never main.mio
mio run main.mio --format=short --verbose
```

- `--color=auto|always|never`
- `--format=human|short|json`
- `--verbose`

这是 `--name=value` 形式，不能擅自改为两个参数。build/exec/disasm 没有接入这些选项。诊断写 stderr，正常输出写 stdout。JSON 含 code、severity、message、location，以及存在时的 path、labels、notes、helps、expected/actual；当前只报告第一条失败，不能假定总有可靠成员源文件位置。

主 CLI：成功 exit 0，编译/加载/执行错误 exit 1，未知命令、缺参数或不合法命令结构 exit 2。test 发现不到测试可 exit 0 且 summary.status=no_tests；因此不能只凭 exit 0 声称测试执行过。

## 测试

```sh
mio test ./bunko/kiso/math --run='^test_' --lang=en-US --format=json
```

参数支持 `--run=<regexp>`、`--lang=zh-CN|ja-JP|en-US` 及上述诊断选项；recursive 目标使用 `./...`。函数发现与测试专用宿主接口见 [kiso/testing](/docs/v1.0/kiso/testing)。JSON 报告含 schema_version、packages 与 summary；duration 随执行变化。实际命中数量、failed 和 status 必须共同检查。

## Bunko 根目录

优先使用环境变量 `MIO_BUNKO`。否则从入口路径所在目录向祖先查找存在的 `bunko/`；没有则使用工作目录相对路径 `bunko`。导入始终写 `kiso/...`，环境变量应指向包含 kiso 的物理根。

```sh
MIO_BUNKO=/absolute/path/to/mio/bunko mio run main.mio
```

## 从源码构建

在对应 Mio 核心源码目录执行：

```sh
go build -o /tmp/mio ./cmd/mio
/tmp/mio version
/tmp/mio check examples/recursion.mio
```

go.mod 声明 `go 1.22.2`；本轮实际使用的 Go/OS/架构及二进制 SHA256 见 [验证报告](/docs/v1.0/tooling/verification)。这是构建所核验的源码，不代表所有发布资产具有相同文件布局。

## 原生工具链支持边界

本正式标签没有 `cmd/mochi-aot`、`internal/aot` 或 `kiso/aot`。不要执行 V2 开发文档中的 Go AOT 构建命令，也不要把 `mio build` 生成的 Mochi 文件当作系统可执行文件。V1 的可重现执行路径是 `mio run` 或 `build → exec`，均使用 Go 引导 CLI / Mochi VM。
