## 本轮复跑

在 mio-docs 根目录执行，需 Python 3.12+（tarfile 安全过滤）、Git、Go 和 Node.js；核心仓库只用于读取已存在的提交对象：

```sh
python3 scripts/check-content-quality.py --core /absolute/path/to/mio
npm run check:versions
npm run check:links
```

验证器用 `git archive` 分别取 V1/V2 精确提交，在系统临时目录构建 CLI，设置指向该归档的 `MIO_BUNKO`。不读取工作树未提交编译器改动，不更新历史冻结锁。已有的技术验证器 `check-reference.py` 对应另一份来源，不能用其工作树结果替代这里的版本证据。

## 检查对象与判定

- 普通完整 Mio 代码块：依次执行 check、run、build、exec、disasm。run/exec 与页面期望 stdout 逐字节匹配，包括末尾换行。
- 标记 `mode="test"` 的测试代码块：保存 `_test.mio`，执行 mio test，读取结构化数量与状态。动态 duration 不假装固定输出。
- 练习：原五课变换及新增练习独立运行；故意失败的断言另验证退出码与 failed 数量。
- 拒绝/运行时失败反例：按 fixture 的实际退出码、JSON 诊断和消息片段检查；预期失败与验证器故障分开。
- API：遍历固定提交公开声明，逐条核对本版本页面里的原始签名。声明一致不是全部参数组合或所有错误分支已通过。
