**版本范围：V2.0.0 · RC4 审阅快照（尚未发布）**。来源为 RC4 的 source-manifest 与包内 BUILD-INFO；HEAD 加未提交来源共同构成候选，不能只检出 HEAD。正文示例默认走包内 CLI / VM。

固定宽度大小端与 LEB128、游标 Reader 和有容量上限 Writer；使用 []uint8，不增加 Core uint64。失败先检查 error；结果 value 可能是占位值，不能忽略错误。

支持范围：本页示例通过 Go 引导 CLI / Mochi VM 验证；错误分支覆盖范围见 [验证报告](/docs/v2.0.0/tooling/verification)，不表示每个函数的每条分支均实测。Native AOT 与纯 Mio 后端需按 [当前阶段](/docs/v2.0.0/internals/native-aot) 单独评估。

## 函数

签名中的参数名及类型保持源码原样；下文说明参数含义、返回值及错误。除明确返回错误值的路径外，数组分配、转换和 VM 指令预算等资源限制仍可能导致运行时错误。

### read_u8

```text
koukai waza read_u8(data: []uint8, offset: int64) -> U8Result
```

参数：`data`：输入字节数组；是否复制见返回语义；`offset`：从起点计数的字节偏移，起点为 0。

从 data 的 offset 按指定端序读取固定宽度值，返回对应 Result；负 offset 为 InvalidOffset，剩余不足为 InsufficientData，不复制整个输入。

### write_var_u32

```text

```

## 完整示例

```mio fixture="binary"
yobu "kiso/array";
yobu "kiso/encoding/binary";
kaku data = array.make[uint8](8, uint8(0));
kaku error = binary.write_i64_be(data, 0, -42);
chant(error == mu);
kaku result = binary.read_i64_be(data, 0);
chant(result.value);
kaku bad = binary.read_u32_le(data, 6);
chant(bad.error != mu);
kaku writer = binary.writer(16);
kaku write_error = binary.writer_write_u32_be(writer, uint32(42));
chant(write_error == mu);
kaku reader = binary.reader(binary.writer_bytes(writer));
kaku read_result = binary.reader_read_u32_be(reader);
chant(read_result.value);
```

预期 stdout（逐字节匹配，末尾有换行）：

```text title="output"
hai
-42
hai
hai
42
```

公开 data/state 字段可被调用方修改；以上游标保证以保持构造器建立的不变式为前提。BinaryError 的 Overflow 与 MalformedVarint 由对应函数返回，不能将所有错误统一当作 InsufficientData。
