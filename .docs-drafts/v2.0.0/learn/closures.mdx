## 学习目标与前置

把行为存进变量，理解捕获变量的生命周期。 前置：[上课：结构体、枚举与分支覆盖](/docs/v2.0.0/learn/models)。本章使用固定版本的 Go 引导 CLI / Mochi VM。

## 为什么需要

普通参数能给函数传数据；函数值让你保存或传递下一步要执行的行为。计数器需要跨多次调用保留状态，闭包把函数和它所捕获的环境联系起来。

## 保存与运行

在安装页的 `项目` 目录保存为 `closures.mio`，使用该版本构建的 CLI 和同一份 `bunko/`：

```sh
mio check closures.mio
mio run closures.mio
```

`check` 成功报告 `check passed`。下面是完整程序与 `run` 的标准输出，末尾包含换行。

```mio title="closures.mio"
waza counter() -> () -> int64 {
    kaku n = 0;
    kaesu waza () -> int64 { n = n + 1; kaesu n; };
}
kaku next = counter();
chant(next());
chant(next());
```

```text title="output"
1
2
```

## 逐段理解

`counter` 的返回类型是 `() -> int64`，也就是“无参数、返回整数的函数”。第一次调用 `counter()` 先创建局部变量 `n=0`，再返回匿名 `waza`。返回的是函数值，此时并没有执行匿名函数体中的加一。

`next()` 第一次执行闭包，把捕获的 `n` 更新到 1 并返回；第二次继续从 1 更新到 2。虽然外层调用已经结束，捕获的存储仍由闭包保留。另调用一次 `counter()` 会创建新的局部状态。

闭包按词法作用域捕获。多个闭包捕获同一可变变量时共享 Cell，不能解释为创建时复制一次整数。具名函数只能在文件顶层声明；需要嵌套行为时使用匿名函数表达式。

## 练习

在两次输出后追加 `chant(next());`。 先预测再执行 `check` 与 `run`，预期逐行输出：

```text title="exercise-output"
1
2
3
```

## 常见陷阱与核对

`next` 是函数值，`next()` 才执行调用；少写括号不是“读取最新计数”。共享捕获会观察后续修改，不能把返回闭包的环境当成创建时的独立数值快照。
