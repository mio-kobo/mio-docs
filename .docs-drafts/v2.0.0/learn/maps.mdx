## 学习目标与前置

用键值表保存命名数据，并处理查不到的结果。 前置：[上课：字符串、字节与 UTF-8](/docs/v2.0.0/learn/strings)。本章使用固定版本的 Go 引导 CLI / Mochi VM。

## 为什么需要

数组适合按位置访问，Map 适合按名称查找。这里以字符串为键、整数为值，类型写成 `Map<string, int64>`；构造表达式 `Map[string, int64]()` 使用方括号。

## 保存与运行

在安装页的 `项目` 目录保存为 `maps.mio`，使用该版本构建的 CLI 和同一份 `bunko/`：

```sh
mio check maps.mio
mio run maps.mio
```

`check` 成功报告 `check passed`。下面是完整程序与 `run` 的标准输出，末尾包含换行。

```mio title="maps.mio"
kaku entries = Map[string, int64]();
entries["answer"] = 42;
kaku alias = entries;
alias["answer"] = 43;
kaku answer = entries["answer"];
moshi (answer != mu) { chant(answer); }
chant(entries["missing"] == mu);
```

```text title="output"
43
hai
```

## 逐段理解

先写入 `answer=42`，再通过别名写成 43。Map 的赋值共享存储，原名称读回的也就是 43；它不会因为有键值类型参数就自动复制。

索引读取总是产生 `int64?`。有键时返回值，没有键时返回 `mu`。因此先把读取保存到局部 `answer`，再在非空分支输出；第二条输出说明 `missing` 不存在，而不是它的值恰好为零。

键可为支持的整数、`bool` 或 `string`，不能用数组或浮点数。不要把数组的 `len`、遍历或删除写法套用到 Map；本快照参考不承诺这些操作。

## 练习

把别名写入的值从 43 改为 99。 先预测再执行 `check` 与 `run`，预期逐行输出：

```text title="exercise-output"
99
hai
```

## 常见陷阱与核对

不存在的键返回 `mu`，不是 0。即使你确信键存在，类型仍是 `V?`，应先存入局部并检查。赋值给 Map 别名会共享修改；本快照没有可据数组写法推定的 Map 长度或遍历操作。
