## 原生 CLI <FeatureBadge status="new" since="2.1" /> <PlatformSupport showArch={true} systems={{ macos: { arm64: "full" }, linux: { x86_64: "full" }, windows: { x86_64: "full" } }} />

本页适用于 [Mio v2.1.0](https://github.com/mio-kobo/mio/releases/tag/v2.1.0) 正式发行包。运行 `mio version` 核对版本号；部分帮助文本仍带有历史上的 candidate 字样。三平台的发行归档均已验证基础 CLI 行为，见 [验证与来源](/docs/v2.1/tooling/verification)。

### 命令及用途

| 命令 | 正式 CLI 的行为 |
| --- | --- |
| `version`、`help` | 版本与帮助信息 |
| `check` | 检查源码并输出诊断 |
| `build` | 默认走原生构建；`--emit=mochi` 可生成 Mochi 字节码 |
| `run` | 从源码构建当前宿主的原生镜像，写入私有临时目录并启动子进程 |
| `exec` | 读取 Mochi 字节码，再编译/启动原生程序 |
| `disasm` | 查看字节码结构 |
| `test` | 交由 `selfhost/testrunner` |
| `lsp` | 交由 `selfhost/lsp/rpc` 的 stdio 服务器 |

注意：V2.0.0 正式 Go CLI 的 `mio run` 与 `mio exec` 使用 Mochi VM；V2.1 CLI则采用**原生编译与进程启动**流程，不能混为一谈。

### 已有命令选项

| 选项 | 使用方式 |
| --- | --- |
| `-o <path>` | 指定 build 输出文件；`run` 与 `exec` 自行管理原生临时路径 |
| `--emit=mochi` | 在 `build` 中选择 Mochi 输出 |
| `--bunko-root <directory>` | 显式指定 Bunko 路径 |
| `--target=darwin-arm64\|linux-amd64\|windows-amd64` | 选择原生目标；也接受 `--target <value>`，默认为当前宿主目标 |
| `--gc-stress` | 源码原生构建的 GC 压力测试选项 |
| `--observe`、`--emit-symbols <file>` | 仅用于 Darwin ARM64 源码原生 `build`，不能与 `--emit=mochi` 合用 |
| `--format=human\|short\|json` | 选择源码诊断形式 |
| `--color=auto\|always\|never` | 控制诊断与帮助文本的颜色输出 |
| `--theme=auto\|dark\|light` <FeatureBadge status="new" since="2.1.2" /> | 选择帮助与诊断的语义调色板（`auto` 依次读取 `MIO_THEME` 与 `COLORFGBG`） |
| `--lang=<locale>` <FeatureBadge status="new" since="2.1.2" /> | 指定 CLI 输出语言（支持 39 个 BCP 47 地区目录，也接受 `--lang <locale>`） |
| `--verbose` | 开启详细诊断 |
| `--` | 对 `run` / `exec` 分隔后续用户程序参数 |

`test` 与 `lsp` 使用独立的子命令解析逻辑。例如，无效的 Bunko 根目录返回 `E_BUNKO_ROOT` 和退出码 2；源码类型错误返回退出码 1。

### CLI 本地化与终端主题 <FeatureBadge status="new" since="2.1.2" />

自 `v2.1.2` 起，原生 CLI 与 Go 参考 CLI 共用一套内嵌的多语言目录（覆盖 39 个 BCP 47 地区标签），运行期完全离线，不访问网络也不依赖外部运行时。

- **帮助排版与终端宽度**：`mio help` 按 General、Compilation、Execution、Diagnostics、Testing、Development tools 六组列出全部子命令；`mio help <command>` 显示单条命令的用法与示例，并按环境变量 `COLUMNS`（20–1000，默认 80）自适应宽度。
- **语言解析优先级**：`--lang` → `MIO_LANG` → `LANGUAGE` / `LC_ALL` / `LC_MESSAGES` / `LANG` → 操作系统首选项（macOS 读取 `AppleLanguages`，Windows 读取注册表 `LocaleName` / `Get-Culture`，Linux 读取 `/etc/locale.conf`）→ 回退 `en-US`。Go 参考 CLI 共用环境变量优先级，但不启动操作系统探测进程。
- **标签规范化与回退链**：支持将 `zh_CN.UTF-8` 等 POSIX 标签规范化为 BCP 47，并兼容旧语言代码（`no`→`nb`、`iw`→`he`、`in`→`id`、`tl`→`fil`、`mo`→`ro`）；按「精确地区 → 区域别名（如 `zh-MO`→`zh-HK`）→ 文字默认（`zh-Hant`→`zh-TW`、`zh-Hans`→`zh-CN`）→ 主语言 → `en-US`」回退。
- **受支持的 39 个地区**：`ar-SA`（RTL）、`bn-BD`、`cs-CZ`、`da-DK`、`de-DE`、`el-GR`、`en-US`、`en-GB`、`es-ES`、`es-MX`、`fa-IR`（RTL）、`fi-FI`、`fil-PH`、`fr-FR`、`he-IL`（RTL）、`hi-IN`、`hu-HU`、`id-ID`、`it-IT`、`ja-JP`、`ko-KR`、`ms-MY`、`nb-NO`、`nl-NL`、`pl-PL`、`pt-BR`、`pt-PT`、`ro-RO`、`ru-RU`、`sv-SE`、`ta-IN`、`te-IN`、`th-TH`、`tr-TR`、`uk-UA`、`vi-VN`、`zh-CN`、`zh-TW`、`zh-HK`。
- **机器可读输出与边界**：`--format=json` 诊断与测试报告、LSP 协议帧、错误码（如 `E_OPTIONS`、`E0602`）及版本字符串保持字节稳定，不会被本地化或着色。编译器底层的类型/源码诊断细节、运行时 trap 与标准库外部文件系统/Bunko 错误仍保持英文技术原文（仅 CLI 标签与 `cause:` 本地化）；RTL 描述以纯 Unicode 输出，不插入不可见双向控制符。
- **颜色优先级**：`--color=always/never` → `NO_COLOR` / `TERM=dumb` / `CLICOLOR=0` → `CLICOLOR_FORCE` → `CI` → TTY 检测。未明确检测到亮/暗背景时，`--theme=auto` 使用高对比度 ANSI 16 色语义角色，不发送 OSC 11 等终端探测序列。

### 原生运行与测试 <PlatformSupport showArch={true} systems={{ macos: { arm64: "full" }, linux: { x86_64: "full" }, windows: { x86_64: "full" } }} />

```sh
mio version
mio check Hello.mio
mio build Hello.mio -o Hello-native
mio build Hello.mio -o Hello.mochi --emit=mochi
mio run Hello.mio -- one two
mio test ./tests --format=json
```

`mio build` 默认使用当前宿主目标。使用 `--target=linux-amd64` 或 `--target=windows-amd64` 可以输出其他目标的可执行文件，应在对应系统运行。Windows 可将输出名设为 `Hello.exe`。三平台正式归档均已通过 `run`、`exec` 和 `test` 烟测；编译出来的原生程序若因除零或数组越界退出，本机 macOS ARM64 测试中得到退出码 1，未收到错误文本。

### 开发边界

CLI 由编译前端、原生构建流程、字节码工具、测试运行器和语言服务器等组件组成。有关实现结构、完整自举与版本验证的技术细节，请阅读 [自托管工具链](/docs/v2.1/tooling/selfhost) 和 [验证与来源](/docs/v2.1/tooling/verification)。
