[Mio v2.1.0](https://github.com/mio-kobo/mio/releases/tag/v2.1.0) 提供 Core 和 Full 归档。三平台原生归档的校验、执行与 Bunko 路径解析见 [正式版 CI](https://github.com/mio-kobo/mio/actions/runs/42384976176)。

## 为什么拆分 Core 与 Full？

两种发行包使用**同一份、该平台原生编译的 Mio 可执行文件**。它们的区别在于是否附带独立的标准库和扩展工具，而不是语言语法、GC 或编译器实现有所不同。

| 内容 | Core | Full |
| --- | --- | --- |
| 原生 Mio 编译器及其必需运行组件 | 包含 | 包含，且编译器 SHA-256 与 Core 一致 |
| `bunko/kiso/` 标准库源码 | 不包含 | 包含 |
| 额外内容 | 许可、README、manifest 与 provenance | 同样包含这些记录，另附已验证示例；当前不附独立工具二进制 |
| 不导入 Bunko 的 Mio 源码 | 应可编译、运行 | 应可编译、运行 |
| 导入 `kiso/...` 的 Mio 源码 | 需要另行提供 Bunko | 使用随包附带的 Bunko |

**注意：** `mio test`、`mio lsp` 等如果实现为同一编译器可执行文件的子命令，Core 仍可能识别这些命令。“不带工具”指不附带额外的独立工具和标准库，不表示从编译器二进制中删去已有子命令。

## 目录布局

发行包采用编译器与标准库的相对目录布局：

```text
mio-2.1.0-linux-amd64-full/
├── bin/
│   └── mio
├── bunko/
│   └── kiso/
├── examples/
├── README.md
├── LICENSE
├── manifest.json
└── provenance.json
```

Core 保留编译器、必要的运行文件与发行许可信息，但不带 `bunko/`。上面的目录树对应正式归档；实际文件与摘要以归档内 `manifest.json` 为准。

Bunko 的导入路径始终使用 `kiso/...`，例如：

```mio title="Math.mio" no-run
yobu "kiso/math";

chant(math.gcd(84, 30));
```

`bunko/` 是文件系统中的库根目录，**不属于** `yobu` 导入路径的一部分。

## Bunko 路径解析

V2.1 CLI 通过共享的 `selfhost/bunkopath` 解析标准库位置，优先级从高到低为：

1. 用户显式传入的 `--bunko-root`（仅适用于接受此参数的命令）。
2. 环境变量 `MIO_BUNKO`。
3. 与实际可执行文件所在位置对应的 `../bunko` 目录。
4. 没有找到 Bunko：无标准库导入的 Core 程序仍应可用，导入 `kiso/...` 时则明确报错。

显式指定不存在或无效的 Bunko 路径时必须报错；不能静默回退到其他目录。自动解析应依据**可执行文件的实际位置**，而不是当前工作目录或不可靠的 `argv[0]` 字符串。

这一顺序已在 v2.1.0 实现，并经过迁移目录与错误路径测试；源码见 [`selfhost/bunkopath`](https://github.com/mio-kobo/mio/tree/74e461b2985886160a285c7104d2a41090d0f548/selfhost/bunkopath)。

## 如何安装与校验？

从 [v2.1.0 发布页](https://github.com/mio-kobo/mio/releases/tag/v2.1.0) 下载归档和 `SHA256SUMS`。解压前，使用 macOS 的 `shasum -a 256 <文件>`、Linux 的 `sha256sum <文件>` 或 PowerShell 的 `Get-FileHash <文件> -Algorithm SHA256`，与清单中对应文件的摘要比较。

解压后将包内 `bin` 目录加入 `PATH`，执行：

```sh
mio version
```

不必为预编译原生发行包安装 Go。若使用 Full，请保持 `bin/` 与 `bunko/` 的相对目录结构；也可以通过 `MIO_BUNKO` 明确指定 Bunko 根目录。

## 发行验证范围

[正式版 CI](https://github.com/mio-kobo/mio/actions/runs/42384976176) 在 macOS ARM64、Linux AMD64、Windows AMD64 原生环境分别检查归档摘要、内容、Core 与 Full 的编译器哈希、Hello 程序构建和运行、Full 自动查找 Bunko 以及无效路径诊断。三个目标均通过。验证范围和报告入口见 [验证与来源](/docs/v2.1/tooling/verification)。

Docker 离线开发环境见 [Docker 开发镜像](/docs/v2.1/tooling/docker)。
