### 已提交的 V2.1 工作

与 `v2.0.0` 比较，当前已提交源码主要增加或完善了：

- 纯 Mio 源码前端、原生构建管线、CLI、LSP、测试运行器及 Mach-O ad-hoc 签名；
- 具体泛型实例、跨包类型信息、Map 和数组布局等 Native 编译路径；
- Mochi v15 / v16 的类型与调用元数据；
- Young / Old 分代 GC、LOS、大对象与托管内存预算；
- Bunko 中的 JSON、正则表达式、SHA-256、OS 服务以及少量原有模块扩展。

上述内容表示**源码已进入分支**，并非宣称全部功能都具备最终版本的稳定性和验收结论。

### M19 的阶段证据 <FeatureBadge status="experimental" since="2.1" />

`benchmarks/native-gc/m19c-acceptance.json` 是 2026-10-26 的历史记录：M19c 独立功能为 `PASS`，当时的 M19 总门禁为 `BLOCKED`，M19b 历史整体验收为 `NOT_ACCEPTED`。这些字段只描述该次验收，不能直接作为当前总门禁结论。

当前分支已包含分代 GC、LOS、预算、并发 Old Mark、SATB 与 Concurrent Sweep 相关源码及 E6 测试。三平台候选 CI 不覆盖全部长期并发 GC 接纳；本轮没有取得可证明 M19 整体已接纳的新报告，仍按实验性能力介绍。

`Normal / Elevated / High / Critical` 是内部内存压力等级。`High / Balanced / Low` 三档 GC 模式仍属后续工作，不能作为已发布用户选项。

详见 [M19 分代 GC](/docs/v2.1/internals/gc) 和 [内存预算与压力](/docs/v2.1/internals/memory-policy)。

### 工具链的实际阶段 <FeatureBadge status="experimental" since="2.1" />

`selfhost/cli/main.mio` 明确将自身标注为 **GF3 development candidate**。其版本输出仍为 `mio v2.0.0-dev (pure Mio Native AOT; GF3 candidate)`，并没有使用正式的 `Mio 2.1.0` 字符串。

候选打包脚本会把上述版本模板替换为含源码提交的 `mio v2.1.0-pr.<commit> (candidate; commit ...; pure Mio Native AOT)`。当前已有三平台原生固定点与候选验证；命令和平台限制见 [Native CLI](/docs/v2.1/tooling/native-cli)，不能把候选接口等同于 V2.0 正式 CLI。

详情见 [原生 CLI 开发记录](/docs/v2.1/tooling/native-cli)。

### 已提交但仍需分项验证的开发

当前核对提交已包含 `kiso/net/tcp`、Native 实参检查修复、LSP 取消处理与并发 GC 集成源码。早期文档把这些工作描述为“尚未提交”，该状态已过时；各项能力的完整验收仍需匹配源码和测试报告，不能仅依据合入分支判断稳定性。

TCP 的当前公开接口为阻塞 IPv4，不能据此推断 UDP、DNS、IPv6、TLS 支持；并发 GC 内部入口也不等于普通 CLI 默认启用。

### 文档与 Playground

本站的 WebAssembly Playground 与 `Mio-2.1` 分支采用不同的版本基线。新版标准库模块不在当前 V2.0 浏览器包中；示例用 `no-run` 显示源码，避免让 V2.0 WASM 误报“找不到包”。

发布前应单独完成：目标平台实际构建、完整 CLI 和 Bunko 示例验证、M19 发布门禁、IDE 协议兼容检查、文档静态链接校验，以及部署页面的浏览器检查。**本文引用的测试结果来自历史记录，不等于已经对当前工作区重新运行编译、自举或集成测试。**
