> **版本说明：** 本页对应 Mio V2.1 中的 `kiso/aot/arm64` 模块。相比 V2.0，本版本补充了寄存器偏移访存、A64 基础原子操作（Load-Acquire / Store-Release 与 LL/SC 独占访存）、`NZCV` 条件标志读写以及多平台系统调用（`linux_abi` / `windows_abi`）适配支持。

## ARM64 指令编码

`kiso/aot/arm64` 为 Mio 的原生 AOT 后端提供纯 Mio 实现的 AArch64 指令编码器与汇编缓冲区（`Assembler`）。

该模块将寄存器编号、立即数和地址偏移量编码为 32 位小端序机器指令字（`uint32`），并在转换前以 `int64` 执行严格的范围与对齐校验，确保非法操作数不会静默截断为错误指令。

### 导入包

> **运行环境：** 当前网页 Playground 的 WASM 环境不包含 AOT 工具链模块。以下代码需在本地通过 Mio V2.1 CLI 与完整 Bunko 标准库运行。

通过 `yobu "kiso/aot/arm64";` 导入本包，并使用 `arm64.函数名(...)` 调用：

```mio title="Arm64Import.mio" no-run
yobu "kiso/aot/arm64";
```

### 单条指令编码与错误检查

所有指令编码函数均返回 `Instruction` 结构体。在读取 `word` 写入代码缓冲区之前，必须检查其 `error` 字段是否为 `mu`。

```mio title="EncodeSingle.mio" no-run
yobu "kiso/aot/arm64";

// 编码 MOVZ X0, #42
kaku inst = arm64.movz_x(0, 42, 0);
moshi (inst.error == mu) {
    chant(inst.word);
}

// 传入越界寄存器编号（有效范围为 0 ~ 31）
kaku invalid = arm64.movz_x(32, 0, 0);
moshi (invalid.error != mu) {
    chant("捕获到非法寄存器编码错误");
}
```

在上述示例中，`movz_x(0, 42, 0)` 生成合法的 32 位指令字，`error` 为 `mu`；而传入寄存器编号 `32` 时，编码器会返回 `EncodeError.InvalidRegister`，此时 `word` 为 `0`，调用方不应将其发射到指令流中。

### 使用 Assembler 管理标签与分支修补

编写包含前向或后向跳转的指令序列时，应使用 `Assembler` 缓冲指令，通过字符串标签（Label）自动计算相对指令字偏移并完成重定位修补。

```mio title="AssemblerDemo.mio" no-run
yobu "kiso/aot/arm64";

kaku code = arm64.assembler();

// 前向跳转至 done 标签
arm64.assembler_b_cond(code, 0, "done"); // B.EQ done
arm64.assembler_emit(code, arm64.movz_x(0, 1, 0));

// 声明目标标签并写入返回指令
arm64.assembler_label(code, "done");
arm64.assembler_emit(code, arm64.ret());

// 解析所有标签与分支修补
kaku result = arm64.assembler_assemble(code);
moshi (result.error == mu) {
    chant(len(result.words));
}
```

在上述示例中，`assembler_assemble` 会统一解析所有 `Fixup` 记录并返回最终的 `[]uint32` 指令字数组。如果存在未定义的标签、重复声明的标签或超出寻址范围的跳转，`result.error` 将返回对应的 `EncodeError`。

#### 汇编器的高级修补机制

- **远距离条件分支自动跳板**：`B.cond`、`CBZ` 和 `CBNZ` 在汇编器中会预先保留 2 个指令字（短距离跳转时第 2 个字填充为 `NOP`）。当目标距离超出 19 位有符号指令字范围（`-262144 ~ 262143`）时，`assembler_assemble` 会自动将其展开为“条件取反跳过 + 26 位无条件 `B` 跳转”的双指令跳板（`AL`/`NV` 恒真条件除外），且不修改 `NZCV` 标志位或通用寄存器。
- **多平台系统调用适配器**：默认情况下，`svc(128)` 会原样输出 Darwin 系统调用指令。如果在发射指令前通过 `assembler_label` 声明了 `"linux_abi"` 或 `"windows_abi"` 标签，汇编器会自动将 `SVC #128` 展开为 `stp x30, xzr, [sp, #-16]!`、`bl linux_syscall`（或 `windows_syscall`）与 `ldp x30, xzr, [sp], #16` 三条指令。

### 公开类型

#### `EncodeError`

编码与汇编阶段可能产生的错误枚举：

```mio title="Arm64Types.mio" no-run
koukai sentaku EncodeError {
    InvalidRegister;        // 寄存器编号超出 0 ~ 31，或独占存储状态寄存器与操作数冲突
    InvalidImmediate;       // 立即数、移位量或页偏移超出指令位宽允许范围
    InvalidCondition;       // 条件码超出 0 ~ 15 范围
    MisalignedOffset;       // 内存访存字节偏移未按访问宽度对齐
    BranchOutOfRange;       // 相对跳转距离超出 PC 相对寻址位宽限制
    DuplicateLabel(string); // 汇编器中重复声明了同名标签
    UndefinedLabel(string); // 分支引用的标签未在汇编器中定义
    InvalidPatch;           // 内部修补记录类型非法
}
```

### 使用限制与平台说明

- **工具链内部定位**：本模块仅覆盖 Mio 原生 AOT 编译器所需的 AArch64 基础指令子集（不依赖可选的 LSE 原子扩展），不负责生成 Mach-O/ELF 文件头、段布局或代码签名。
- **页对齐差异**：`adrp_offset` 严格遵循 AArch64 架构定义的 **4 KiB** 页大小计算页差，即使在 Darwin Mach-O 镜像采用 **16 KiB** 段对齐时也是如此。
- **验证边界**：该模块已在 macOS ARM64 上完成指令编码与独立交叉验证；`linux_abi` 与 `windows_abi` 系统调用适配器逻辑已在单元测试中验证指令展开，完整跨平台二进制产物验证请参考 [验证与来源](/docs/v2.1/tooling/verification)。

源码依据：[Mio V2.1 · `bunko/kiso/aot/arm64`](https://github.com/mio-kobo/mio/tree/main/bunko/kiso/aot/arm64)。
