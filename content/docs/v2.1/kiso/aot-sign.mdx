> **版本说明：** 本页对应 Mio V2.1 新增的 `kiso/aot/sign` 模块。该模块为未签名的 Darwin ARM64 Mach-O 镜像追加 `LC_CODE_SIGNATURE` 加载命令及基于 SHA-256 的 `CodeDirectory`（`v0x20400`），使原生编译产物无需外部 `codesign` 即可在 macOS ARM64 上通过内核代码签名校验。

## Mach-O ad-hoc 代码签名 <FeatureBadge status="new" since="2.1" /> <PlatformSupport showArch={true} systems={{ macos: { arm64: "full" }, linux: { x86_64: "unknown" }, windows: { x86_64: "unknown" } }} />

`kiso/aot/sign` 为 Mio 原生 AOT 编译流水线提供纯 Mio 实现的 Darwin ARM64 Mach-O 本地 ad-hoc 签名器。

在 Apple Silicon（macOS ARM64）平台上，系统内核要求所有可执行二进制文件具备有效的代码签名。该模块接收由 `kiso/aot/macho` 或其他原生链接器生成的未签名 ARM64 Mach-O 镜像字节数组，校验其头部与段布局合法性，计算每个 `4 KiB` 代码页的 SHA-256 摘要，并输出包含完整 `SuperBlob` 签名的可执行字节流。

### 导入包

> **运行环境：** 当前网页 Playground 的 WASM 环境不包含 AOT 工具链模块。以下代码需在本地通过 Mio V2.1 CLI 与完整 Bunko 标准库运行。

通过 `yobu "kiso/aot/sign";` 导入本包，并使用 `sign.函数名(...)` 调用：

```mio title="SignImport.mio" no-run
yobu "kiso/aot/sign";
```

### 对 Mach-O 镜像执行 ad-hoc 签名

生成原生可执行文件的最后一步是将 `macho.executable` 产出的未签名字节传入 `sign.adhoc`，并检查返回的 `error == ""`：

```mio title="SignMachO.mio" no-run
yobu "kiso/aot/arm64";
yobu "kiso/aot/macho";
yobu "kiso/aot/sign";

// 1. 编码最小退出指令序列
kaku words: []uint32 = [
    arm64.movz_x(0, 0, 0).word,
    arm64.movz_x(16, 1, 0).word,
    arm64.svc(128).word
];

// 2. 封装为未签名 Mach-O 镜像
kaku image = macho.executable(macho.ImageSpec {
    words: words,
    constants: [],
    globals: 0,
    patches: []
});

moshi (image.error == mu) {
    // 3. 追加本地 ad-hoc 签名
    kaku signed = sign.adhoc(image.bytes);
    moshi (signed.error == "") {
        chant(len(signed.bytes));
    } sore {
        chant(signed.error);
    }
}
```

在上述示例中，`sign.adhoc` 会将镜像的 Load Commands 数量加 `1`、更新 `__LINKEDIT` 段的虚拟内存与文件大小，并在镜像末尾追加 16 字节对齐的签名数据块。输出字节写入文件并赋予可执行权限后，即可通过系统 `codesign --verify --strict` 校验并直接运行。

### 签名结构与校验规则

`kiso/aot/sign` 严格按照 Apple Code Signing 二进制格式生成确定性的本地签名：

- **输入镜像前置校验**：输入字节数组长度必须为 `16` 字节对齐（范围 `768` 字节至 `64 MiB`），具备 64 位 ARM64 可执行文件头（魔数 `0xFEEDFACF`、`CPU_TYPE_ARM64`、`MH_EXECUTE`），包含 `1 ~ 32` 条 8 字节对齐的 Load Commands（总长度不超过 `720` 字节，确保新增 16 字节的 `LC_CODE_SIGNATURE` 后仍不越过 `0x300` 入口偏移），且尚未包含 `LC_CODE_SIGNATURE`（命令编号 `29`）。
- **`__LINKEDIT` 布局要求**：镜像末尾必须存在 `__TEXT` 与 `__LINKEDIT` 段。对于纯静态无重定位镜像（`adhoc`），`__LINKEDIT` 的初始文件大小必须为 `0`；对于包含动态链接器绑定数据的镜像（`adhoc_linked`），`__LINKEDIT` 必须位于文件末尾（`offset + size == len(image)`）并保留原有绑定负载。
- **签名数据组织**：签名块由 `SuperBlob`（20 字节，`0xFADE0CC0`）、`CodeDirectory`（`v0x20400`，固定标识符 `"mio\0"`，标志位 `0x00020002` 即 `CS_ADHOC | CS_LINKER_SIGNED`）以及按 **`4,096` 字节（`4 KiB`）** 页切分计算的 SHA-256 哈希槽数组组成，最终长度向上对齐至 `16` 字节边界。

### 公开类型与函数

#### `SignResult`

```mio title="SignTypes.mio" no-run
koukai kata SignResult {
    bytes: []uint8; // 追加签名并更新头部后的完整 Mach-O 文件字节（仅当 error == "" 时有效）
    error: string;  // 错误描述；为空字符串 "" 时表示签名成功
}
```

#### 公开函数（2 个）

| 函数           | 公开签名                                     | 功能与校验差异                                                                                                       |
| -------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `adhoc`        | `adhoc(image: []uint8) -> SignResult`        | 为无动态链接负载的纯静态 ARM64 Mach-O 镜像生成本地 ad-hoc 签名；要求输入镜像的 `__LINKEDIT` 段大小为 `0`。           |
| `adhoc_linked` | `adhoc_linked(image: []uint8) -> SignResult` | 为包含现有 dyld 绑定负载的动态 ARM64 Mach-O 镜像生成本地 ad-hoc 签名；保留 `__LINKEDIT` 既有数据并在其后追加签名块。 |

### 使用限制与平台说明

- **签名范围边界**：本模块仅生成本地内核校验所需的 ad-hoc 签名，不包含 Apple Developer ID 证书、CMS 签名块、Entitlements 权限配置或公证（Notarization）票据，也不负责解析重定位表。
- **平台适用性**：本模块针对 Darwin ARM64 Mach-O 格式设计，已在 macOS ARM64 上完成镜像生成与 `codesign --verify --strict` 严格验证；Linux 与 Windows 平台不适用 Mach-O 代码签名，详见 [验证与来源](/docs/v2.1/tooling/verification)。
