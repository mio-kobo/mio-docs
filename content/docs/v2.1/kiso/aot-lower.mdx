> **版本说明：** 本页对应 Mio V2.1 中的 `kiso/aot/lower` 模块。在保留 V2.0 基础编译入口的同时，V2.1 完整支持 Mochi v1~v16 字节码格式（含类型约束元数据与定型间接调用），新增分代回收（Generational GC）、大对象空间（LOS）、自适应内存预算与观测编译入口，并在 `LowerResult` 中公开了 `function_words` 与 `labels` 诊断字段。

## AOT Lowering 字节码降级

`kiso/aot/lower` 是 Mio 原生 AOT 编译流水线的核心后端。它接收由 `kiso/encoding/mochi` 解码后的 `mochi.File` 字节码模块，经过静态类型流分析与泛型特化后，降级生成可直接交付给 `kiso/aot/macho` 封装的 ARM64 机器指令字（`[]uint32`）、静态字符串常量区镜像、地址重定位补丁以及全局槽位需求。

所有公开编译入口均返回 `LowerResult`。调用方必须先检查 `result.error == mu`，严禁在编译出错时直接使用 `words` 或 `constants`。

### 导入包

> **运行环境：** 当前网页 Playground 的 WASM 环境不包含 AOT 工具链模块。以下代码需在本地通过 Mio V2.1 CLI 与完整 Bunko 标准库运行。

通过 `yobu "kiso/aot/lower";` 导入本包，并使用 `lower.函数名(...)` 调用：

```mio title="LowerImport.mio" no-run
yobu "kiso/aot/lower";
```

### 基础编译与错误检查

标准编译流程将 `mochi.File` 传入 `lower.compile`，验证 `error` 字段后即可获取生成的机器指令字与常量区数据。

```mio title="LowerBasic.mio" no-run
yobu "kiso/aot/lower";
yobu "kiso/encoding/mochi";

// 构造一个最小合法的 Mochi v14 空模块
kaku file = mochi.File {
    version: 14,
    constants: [],
    global_count: 0,
    instructions: [],
    functions: []
};

kaku result = lower.compile(file);
moshi (result.error == mu) {
    chant(len(result.words));
    chant(result.globals);
} sore {
    // 提取诊断错误码与定位详情
    kaku err = result.error;
    moshi (err != mu) {
        chant(lower.error_code(err));
        chant(lower.error_detail(err));
    }
}
```

在上述示例中，即使输入字节码为空，`compile` 也会自动发射程序入口序言（Prologue）、标准退出系统调用（`normal_exit`）以及基础运行时辅助例程；若字节码包含非法指令或类型冲突，`result.error` 将返回对应的 `LowerError` 枚举值。

### 核心架构与运行时约定

`kiso/aot/lower` 生成的原生代码严格遵循以下 ABI 与内存管理协议（Fail-Closed 安全边界）：

- **调用帧与寄存器约定**：主入口与每个函数各自拥有上限为 `4,080` 字节的操作数区域（基址 `x19`，实时字节偏移 `x20`）；函数局部变量区基址为 `x21`（最多支持 `256` 个局部变量与 `256` 个参数），闭包环境指针固定使用 `x25`，运行时堆元数据基址固定使用 `x23`，精确影子栈链表头固定使用 `x24`。递归调用深度上限为 `1024` 层。
- **精确 Shadow Frame 根追踪**：所有可能触发堆分配或跨函数调用的指令前均会压入精确影子帧（`{previous, count, roots...}`）。静态字符串常量使用最低位为 `1` 的 Tagged ID 表示，GC 标记阶段会自动跳过；可空基础标量（如 `int64?`）在装箱时分配独立的 Type-106 堆对象，确保与原始整数 `0` 严格区分。
- **有界托管堆与释放策略**：默认托管堆容量为 `128 MiB`（合法配置范围为 `64` 字节至 `1 GiB`，且必须为 `16` 字节对齐）。普通堆采用 39 级空闲链表（`0..30` 为 16 字节步进精确分箱，`31` 覆盖 `496..1023` 字节，`32..38` 为自 `1 KiB` 起的 2 的幂次分级）配合大对象空间（LOS，默认阈值 `128 KiB`）管理。

### 公开类型

#### `LowerError`

字节码验证、类型求解、栈帧布局与指令编码阶段可能报告的错误枚举：

```mio title="LowerTypes.mio" no-run
koukai sentaku LowerError {
    UnsupportedConstant;    // 常量池标签超出 1 ~ 10 支持范围
    UnsupportedOpcode(int64); // 遇到未实现或与模块版本号不兼容的操作码
    UnsupportedClosure;     // 非法的闭包捕获结构或函数 ID 不连续
    InvalidFunction;        // 函数索引越界、局部操作数出现在顶层或桥接签名不合法
    InvalidOperand(int64);  // 全局/局部槽位越界、堆容量参数非法或字节码截断
    FrameTooLarge;          // 操作数栈深度或局部/参数数量超出帧容量上限
    EncodeFailure;          // 底层 ARM64 指令编码器返回内部失败
    UnsafeType(int64);      // 静态类型求解失败、存在未解决的 unknown 布局或类型不匹配
    UnsupportedNative(int64); // 未知的 NativeFS 宿主签名或不支持的原生内建函数
    BranchOutOfRange(int64);  // 降级后的机器码跳转距离超出 ARM64 26-bit 寻址范围
}
```

#### `LowerResult`

降级编译的完整输出载体：

```mio title="LowerTypes.mio" no-run
koukai kata LowerResult {
    words: []uint32;                // 生成的 ARM64 32 位小端序机器指令字序列
    constants: []uint8;             // 静态 UTF-8 字符串表与字节数据镜像（供 __CONST 区使用）
    patches: []macho.AddressPatch;  // 需由 Mach-O 封装器重定位的跨段地址补丁列表
    globals: int64;                 // 需在 __DATA 段预留的 8 字节全局变量槽位总数
    error: LowerError?;             // 编译错误；仅当为 mu 时其余字段有效
    function_words: []int64;        // 各 Mochi 函数入口在 words 中的指令字索引（未发射为 -1）
    labels: []arm64.Label;          // 汇编器生成的全部符号标签表（可用于性能分析映射）
}
```

### 公开函数（15 个）

#### 1. 标准与内存预算编译入口（6 个）

| 函数                         | 公开签名                                                                                                           | 功能与参数规则                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| `compile`                    | `compile(file: mochi.File) -> LowerResult`                                                                         | 使用默认 `128 MiB` 有界托管堆执行标准 AOT 降级编译。                                 |
| `compile_gc_stress`          | `compile_gc_stress(file: mochi.File) -> LowerResult`                                                               | 在每次堆分配入口强制触发垃圾回收的验证编译模式，用于检验根追踪完整性。               |
| `compile_with_heap`          | `compile_with_heap(file: mochi.File, capacity: int64, gc_stress: bool) -> LowerResult`                             | 使用显式指定的托管堆容量（`64` 字节至 `1 GiB`，须 `16` 字节对齐）编译。              |
| `compile_with_observation`   | `compile_with_observation(file: mochi.File, capacity: int64, gc_stress: bool) -> LowerResult`                      | 生成内嵌内存采样与统计输出（`observation_dump`）的原生运行时代码。                   |
| `compile_with_adaptive_heap` | `compile_with_adaptive_heap(file: mochi.File, maximum: int64, gc_stress: bool, observation: bool) -> LowerResult`  | 启用运行时自动容量探测（`memory.autocap`）与动态内存压力策略，上限不超过 `maximum`。 |
| `compile_with_memory_budget` | `compile_with_memory_budget(file: mochi.File, hard_cap: int64, gc_stress: bool, observation: bool) -> LowerResult` | 根据总托管内存费用硬上限 `hard_cap`（不得低于 `114,688` 字节）自动推导并对齐堆容量。 |

#### 2. 诊断辅助函数（2 个）

| 函数           | 公开签名                                   | 功能与返回规则                                                                                                                                                                                                              |
| -------------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `error_code`   | `error_code(value: LowerError) -> int64`   | 返回标准错误分类编号（`1` ~ `10`；其中 `InvalidOperand(detail)` 返回 `5000 + detail`）。                                                                                                                                    |
| `error_detail` | `error_detail(value: LowerError) -> int64` | 提取附带的定位信息：对操作码或类型错误，按 `(functionID + 1) * 1_000_000 + byteOffset * 100 + opcode` 打包编码（顶层 `main` 的 `functionID` 为 `-1`，无高位函数前缀）；对 `BranchOutOfRange` 返回发生越界的机器指令字索引。 |

### 使用限制与平台说明

- **字节码版本要求**：支持 `mochi.File` 版本 `1 ~ 16`（其中操作码 `66` 类型约束要求 `version >= 15`，操作码 `67` 定型间接调用要求 `version >= 16`），单模块全局变量槽位上限为 `2,048` 个。
- **输出行为差异**：遵循原生运行时 ABI（RA-1），只有显式调用 `chant` 才会向标准输出写入内容；顶层表达式求值后被丢弃的值不会像 `mio run` 交互执行那样自动回显。
- **发布门禁边界**：`compile_with_adaptive_heap` 与 `compile_with_memory_budget` 属于源码层公开函数，并非独立发布的 CLI 参数；并发老年代回收的整体接纳状态与跨平台支持范围请参考 [从 V2.0 到 V2.1](/docs/v2.1/migration) 与 [验证与来源](/docs/v2.1/tooling/verification)。
