> **版本说明：** 本页对应 Mio V2.1 中的 `kiso/encoding/mochi` 模块。相比 V2.0（`VERSION = 14`），V2.1 将解码器版本上限常量更新为 `VERSION = 16`，新增对 v15 类型约束指令（`OP_TYPE_CONSTRAINT = 66`）与 v16 定型间接调用指令（`OP_CALL_TYPED = 67`）的解码、边界校验及规范化重编码支持。

## Mochi 字节码编解码器

`kiso/encoding/mochi` 提供纯 Mio 实现的 Mochi 字节码（`.mochi`）解码器、静态结构验证器、摘要统计工具以及确定性规范化重编码器（`canonical_bytes`）。

该模块严格校验魔数（`MOCHI`）、格式版本（`1 ~ 16`）、资源容量上限、UTF-8 编码、常量池标签、函数槽位与闭包捕获范围、全部已定义操作码及其版本门槛，以及所有跳转目标的指令边界。

### 导入包

> **网页运行说明：** 内存解码、摘要与规范化函数（`decode`、`canonical_bytes`、`summarize`、`error_code`）均可在网页 Playground 与原生 CLI 中运行；文件分块读取入口 `decode_file` 依赖文件系统模块 `kiso/fs`，需在本地 CLI 环境运行。

通过 `yobu "kiso/encoding/mochi";` 导入本包，并使用 `mochi.函数名(...)` 调用：

```mio title="MochiImport.mio"
yobu "kiso/encoding/mochi";
```

### 解码、校验与规范化重编码

使用 `mochi.decode` 解码内存中的字节数组后，必须先检查 `result.error == mu`，确认解码成功后再访问 `result.value`。成功解码得到的 `mochi.File` 可通过 `mochi.summarize` 查看结构统计，或通过 `mochi.canonical_bytes` 序列化为规范字节流。

```mio title="MochiDecode.mio"
yobu "kiso/encoding/binary";
yobu "kiso/encoding/mochi";

// 构造一个包含 v16 定型间接调用操作码（67）的最小字节码文件
kaku w = binary.writer(256);
binary.writer_write_bytes(w, [77, 79, 67, 72, 73]); // 魔数 "MOCHI"
binary.writer_write_u16_be(w, uint16(mochi.VERSION)); // 版本 16
binary.writer_write_u32_be(w, uint32(0));            // 常量池数量: 0
binary.writer_write_u32_be(w, uint32(0));            // 全局槽位数量: 0
binary.writer_write_length_prefixed(w, [21, 67, 0, 0, 1, 3]); // 顶层指令
binary.writer_write_u32_be(w, uint32(0));            // 函数表数量: 0

kaku raw = binary.writer_bytes(w);
kaku decoded = mochi.decode(raw);

moshi (decoded.error == mu) {
    kaku file = decoded.value;
    moshi (file != mu) {
        kaku info = mochi.summarize(file);
        chant(info.version);           // 16
        chant(info.instruction_bytes); // 6

        // 确定性规范化重编码并与原始字节比对长度
        kaku canonical = mochi.canonical_bytes(file);
        chant(len(canonical) == len(raw)); // hai
    }
} sore {
    kaku err = decoded.error;
    moshi (err != mu) {
        chant(mochi.error_code(err));
    }
}
```

在上述示例中，由于操作码 `67` 要求 `version >= 16`，若将版本号改为 `15`，`mochi.decode` 会返回 `InvalidInstruction`（错误码 `8`）并拒绝该文件。

### 从文件分块解码

`mochi.decode_file` 以 `32 KiB` 分块读取磁盘上的 `.mochi` 文件，在读取过程中实时强制执行 `MAX_FILE_SIZE`（`64 MiB`）上限保护，防止恶意超大文件触发无界内存分配。

```mio title="MochiFile.mio" no-run
yobu "kiso/encoding/mochi";

kaku res = mochi.decode_file("build/app.mochi");
moshi (res.error == mu) {
    kaku file = res.value;
    moshi (file != mu) {
        chant(mochi.summarize(file).functions);
    }
} sore {
    kaku err = res.error;
    moshi (err != mu) {
        // 文件不存在或读取失败返回 IoFailure (错误码 12)
        chant(mochi.error_code(err));
    }
}
```

### 公开常量（8 个）

| 常量                    | 值         | 说明                                            |
| ----------------------- | ---------- | ----------------------------------------------- |
| `VERSION`               | `16`       | 当前解码器支持的最高 Mochi 字节码格式版本号     |
| `MAX_FILE_SIZE`         | `67108864` | 单文件最大允许字节数（`64 MiB`）                |
| `MAX_CONSTANTS`         | `65536`    | 单模块常量池最大条目数                          |
| `MAX_GLOBALS`           | `65536`    | 单模块全局变量槽位最大数量                      |
| `MAX_STRING_BYTES`      | `16777216` | 单个字符串常量的最大 UTF-8 字节长度（`16 MiB`） |
| `MAX_INSTRUCTION_BYTES` | `16777216` | 顶层或单个函数体的最大指令字节长度（`16 MiB`）  |
| `MAX_FUNCTIONS`         | `65536`    | 单模块函数表最大函数数量                        |
| `MAX_FUNCTION_SLOTS`    | `65536`    | 单个函数的参数、局部变量及捕获槽位最大数量      |

#### V2.1 新增格式特性（v15 ~ v16）

| 格式版本 | 新增操作码     | 语义与校验规则                                                                                     |
| -------- | -------------- | -------------------------------------------------------------------------------------------------- |
| `v15`    | `66`（2 字节） | 记录栈顶值的声明类型描述符约束（`1 ~ 17`，不带可空标志位），不执行运行时类型转换。                 |
| `v16`    | `67`（4 字节） | 定型间接调用，操作数包含参数个数与返回值标志位（`0` 表示无返回值，`1` 表示有返回值，其他值拒绝）。 |

### 公开类型

#### 错误类型与错误码映射

```mio title="MochiErrors.mio" no-run
koukai sentaku DecodeErrorKind {
    Truncated;          // 1: 输入在预期字段或指令操作数结束前提前截断
    InvalidMagic;       // 2: 缺少 5 字节 "MOCHI" 文件头魔数
    UnsupportedVersion; // 3: 格式版本号小于 1 或大于 VERSION (16)
    LimitExceeded;      // 4: 文件总大小、表项数量或指令长度超出公开上限常量
    InvalidConstant;    // 5: 常量标签非法（非 1 ~ 10）或标签低于当前格式版本要求
    InvalidUtf8;        // 6: 字符串常量或函数名称包含非法 UTF-8 字节序列
    InvalidFunction;    // 7: 函数 ID 不连续、槽位计数矛盾、返回标志非法或顶层出现 return 指令
    InvalidInstruction; // 8: 未知操作码、操作码超出当前版本允许范围或子操作数非法
    InvalidIndex;       // 9: 常量、全局、局部、函数或捕获上值索引越界
    InvalidJump;        // 10: 分支跳转目标越界或未落在合法指令起始边界上
    TrailingData;       // 11: 解析完所有段后文件末尾仍有多余未消费字节
    IoFailure;          // 12: decode_file 打开、分块读取或关闭文件失败
}

koukai kata DecodeError {
    kind: DecodeErrorKind; // 错误分类枚举
    offset: int64;         // 发生错误时的字节偏移量
    detail: int64;         // 附加诊断详情（如非法操作码编号、越界索引或实际长度）
}
```

```mio title="MochiTypes.mio" no-run

// 闭包捕获来源描述

// 单个函数元数据与字节码体
koukai kata Function {
    id: int64;

    parameter_count: int64;
    local_count: int64;

// 解码后的完整 Mochi 模块

    version: int64;
    constants: []Constant;

// 模块结构摘要信息
```

### 公开函数（5 个）

| 函数              | 公开签名                                    | 功能与返回规则                                                                         |
| ----------------- | ------------------------------------------- | -------------------------------------------------------------------------------------- |
| `decode`          | `decode(data: []uint8) -> DecodeResult`     | 从内存字节数组完整解码并验证 Mochi 字节码；不会修改输入的 `data` 数组。                |
| `decode_file`     | `decode_file(path: string) -> DecodeResult` | 分块读取指定路径的 `.mochi` 文件并执行完整解码验证，读取阶段即强制校验 `64 MiB` 上限。 |
| `canonical_bytes` | `canonical_bytes(value: File) -> []uint8`   | 将已解码的 `File` 结构确定性地重新序列化为标准大端序字节流。                           |
| `summarize`       | `summarize(value: File) -> Summary`         | 统计并返回模块版本号、常量/函数/全局槽位数量、总指令字节数及规范化编码大小。           |
| `error_code`      | `error_code(error: DecodeError) -> int64`   | 将 `DecodeError` 映射为稳定的整型错误分类编号（`1 ~ 12`）。                            |

### 使用限制与平台说明

- **跨工具链版本兼容性**：`VERSION = 16` 反映 V2.1 解码器的支持上限。V2.0 的旧版参考解码器最高仅支持 `v14`，且历史布局编码接口默认仍输出 `v14` 格式；在跨版本分发 `.mochi` 文件时需确认目标运行时支持对应的操作码版本。
- **输入不可变性与校验优先**：`decode` 不会修改传入的 `[]uint8` 缓冲区，所有标量常量按原始 `U64` 位模式保留（完整保留 `NaN` 载荷、`-0.0` 与 `MinInt64`）；`canonical_bytes` 面向合法的 `File` 结构，传入未经验证的伪造节点可能导致输出越界截断。
