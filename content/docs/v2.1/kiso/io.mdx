> **版本说明：** 本页对应 Mio V2.1 中的 `kiso/io` 模块。全部 7 个公开函数与函数闭包式流抽象（`Reader`、`Writer`）均基于纯 Mio 源码与闭包捕获实现，可在 Mochi VM、Web Playground 与原生 AOT 后端运行。

## 输入输出

输入输出标准库（`kiso/io`）为 Mio 提供同步字节流抽象（`Reader` 与 `Writer`）以及基于这些抽象的通用读取、写入、完整读写（`read_full` / `write_all`）、流复制（`copy_stream`）和内存字节流适配器（`reader_from_bytes` / `writer_to_buffer`）。

与依赖类继承或内置 Trait 的语言不同，Mio 的 `Reader` 与 `Writer` 是包含函数类型字段的结构体。任何拥有匹配函数签名的闭包都可以直接作为流实例传入标准库函数（例如 `kiso/fs` 的 `fs.reader` 与 `fs.writer`）。

### 单次读写与部分进度语义

`io.read` 与 `io.write` 接收字节切片的 `[offset, offset + length)` 区间参数，执行前置边界校验后调用底层流回调。单次读写允许**部分成功**（`0 < count < length`），并且允许在返回最后一批字节的同时报告 `eof == hai`。

```mio title="IoPartial.mio"
yobu "kiso/array";
yobu "kiso/io";

kaku source: []uint8 = [65, 66, 67, 68];
kaku r = io.reader_from_bytes(source);
kaku buf = array.make[uint8](4, uint8(0));

// 从偏移 1 开始读取 2 个字节到 buf[1..3]
kaku first = io.read(r, buf, 1, 2);
moshi (first.error == mu) {
    chant(first.count); // 2
    chant(first.eof);   // iie
    chant(buf[1]);      // 65 ('A')
    chant(buf[2]);      // 66 ('B')
}

// 读取剩余最后 2 个字节，本次同时返回 count = 2 与 eof = hai
kaku second = io.read(r, buf, 0, 2);
moshi (second.error == mu) {
    chant(second.count); // 2
    chant(second.eof);   // hai
}
```

### 完整读写与错误类型处理

`io.read_full` 会循环调用底层 `read` 直到填满请求的 `length` 字节，若中途遇到流结束则返回 `IoError.UnexpectedEOF`；`io.write_all` 则循环写入直到全部 `length` 字节写完或发生错误。若底层流在未到达 EOF 时连续返回 `count == 0` 且无错误，两者均会返回 `IoError.NoProgress` 防止死循环。

```mio title="IoFull.mio"
yobu "kiso/array";
yobu "kiso/bytes";
yobu "kiso/io";

kaku dst = array.make[uint8](4, uint8(0));
kaku short = io.read_full(io.reader_from_bytes([10, 20]), dst, 0, 4);

// 即使中途提前 EOF，count 仍保留已成功读取的 2 字节
chant(short.count); // 2

kaku err = short.error;
moshi (err != mu) {
    awase (err) {
        baai UnexpectedEOF { chant("stream ended early"); }
        baai NoProgress { chant("stalled"); }
        baai InvalidArgument { chant("bad range"); }
        baai Closed { chant("closed"); }
        baai Other(msg) { chant(msg); }
    }
}
```

### 流复制与内存适配器

`io.copy_stream` 内部维护一块固定的 `32 KiB`（`32,768` 字节）缓冲区，持续从 `Reader` 读取并完整写入 `Writer`，直到遇到 `eof` 或错误。`reader_from_bytes` 创建拥有独立游标但共享源数组的内存读取器；`writer_to_buffer` 则向共享的 `bytes.ByteBuffer` 追加字节。

```mio title="IoCopy.mio"
yobu "kiso/bytes";
yobu "kiso/io";
yobu "kiso/string";

kaku data = string.to_bytes("Stream copy in Mio");
kaku r = io.reader_from_bytes(data);
kaku buf = bytes.new_buffer();

kaku copied = io.copy_stream(r, io.writer_to_buffer(buf));
moshi (copied.error == mu) {
    chant(copied.count); // 18
    kaku text = string.from_utf8(bytes.buffer_bytes(buf));
    moshi (text != mu) {
        chant(text);     // Stream copy in Mio
    }
}
```

### 公开类型

#### 错误枚举与结果载体

```mio title="IoTypes.mio" no-run
koukai sentaku IoError {
    Closed;          // 底层资源已关闭
    InvalidArgument; // 读写偏移/长度越界，或自定义回调返回了非法的 count（< 0 或 > length）
    NoProgress;      // 底层流在未报告 EOF 或错误的情况下返回 count == 0
    UnexpectedEOF;   // read_full 在读满请求字节数之前到达流末尾
    Other(string);   // 底层宿主或自定义流报告的其他错误文本
}

koukai kata ReadResult {
    count: int64;    // 本次或累计成功读取的字节数（即使伴随 error 也保留已完成进度）
    eof: bool;       // 是否已到达流末尾
    error: IoError?; // 错误详情；为 mu 时表示成功
}

koukai kata WriteResult {
    count: int64;    // 本次或累计成功写入的字节数
    error: IoError?; // 错误详情；为 mu 时表示成功
}

koukai kata CopyResult {
    count: int64;    // 累计成功复制的字节数
    error: IoError?; // 错误详情；为 mu 时表示成功
}
```

#### 流接口结构体

```mio title="IoInterfaces.mio" no-run
// 同步字节读取器（函数字段闭包，无继承要求）
koukai kata Reader {
    read: ([]uint8, int64, int64) -> ReadResult;
}

// 同步字节写入器（函数字段闭包，无继承要求）
koukai kata Writer {
    write: ([]uint8, int64, int64) -> WriteResult;
}
```

### 公开函数（7 个）

| 函数                | 公开签名                                                                                      | 功能与返回规则                                                                                                                                                             |
| ------------------- | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `read`              | `read(reader: Reader, destination: []uint8, offset: int64, length: int64) -> ReadResult`      | 校验 `destination[offset .. offset+length)` 合法性后调用 `reader.read`，允许部分读取。                                                                                     |
| `write`             | `write(writer: Writer, source: []uint8, offset: int64, length: int64) -> WriteResult`         | 校验 `source[offset .. offset+length)` 合法性后调用 `writer.write`，允许部分写入。                                                                                         |
| `read_full`         | `read_full(reader: Reader, destination: []uint8, offset: int64, length: int64) -> ReadResult` | 循环读取直到填满 `length` 字节；若提前到达末尾返回 `UnexpectedEOF`，零进展返回 `NoProgress`；若 `length == 0` 则不调用底层回调并直接返回 `count: 0, eof: iie, error: mu`。 |
| `write_all`         | `write_all(writer: Writer, source: []uint8, offset: int64, length: int64) -> WriteResult`     | 循环写入直到完整写出 `length` 字节；若发生零进展返回 `NoProgress`。                                                                                                        |
| `copy_stream`       | `copy_stream(reader: Reader, writer: Writer) -> CopyResult`                                   | 使用内部 `32 KiB` 缓冲区从 `reader` 当前游标持续复制字节到 `writer` 直至 `eof` 或发生错误。                                                                                |
| `reader_from_bytes` | `reader_from_bytes(source: []uint8) -> Reader`                                                | 创建基于 `source` 的内存 `Reader`；每个实例拥有独立读取游标，但与 `source` 共享底层存储（读取期间修改 `source` 元素会被观察到）。                                          |
| `writer_to_buffer`  | `writer_to_buffer(buffer: bytes.ByteBuffer) -> Writer`                                        | 创建向 `buffer` 末尾追加字节的内存 `Writer`（共享 `ByteBuffer` 存储）。                                                                                                    |

### 使用限制与平台说明

- **错误与进度共存**：当 `read_full`、`write_all` 或 `copy_stream` 中途失败时，返回的 `error != mu`，但 `count` 仍准确记录错误发生前已成功传输的字节数。
- **自定义流契约**：用户自定义 `Reader` 或 `Writer` 回调必须遵守计数边界 `0 <= count <= length`；若回调返回负数或超出请求长度的 `count`，`read_full`、`write_all` 与 `copy_stream` 会立即中止并报告 `IoError.InvalidArgument`。
- **模块边界**：本模块仅提供同步字节流抽象与内存流适配器；文件流适配器请使用 `kiso/fs`（`fs.reader` / `fs.writer`），TCP 网络流请使用 `kiso/net/tcp`。
