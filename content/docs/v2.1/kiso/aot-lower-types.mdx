## AOT 类型与控制流分析

`kiso/aot/lower/types` 为 Mio 原生 AOT 降级器（`kiso/aot/lower`）提供静态类型流求解与控制流可达性分析。

该模块读取 `mochi.File` 字节码模块，通过两阶段求解（先建立基本块指令边界与精确操作数栈深度，再构造并查集类型等价类与数据流固定点）推导出每个全局槽位、局部槽位、捕获单元以及每条指令入口栈槽的物理表示类别、可空性及精确 GC 根属性。

### 导入包

> **运行环境：** 当前网页 Playground 的 WASM 环境不包含 AOT 工具链模块。以下代码需在本地通过 Mio V2.1 CLI 与完整 Bunko 标准库运行。

通过 `yobu "kiso/aot/lower/types";` 导入本包，并使用 `types.函数名(...)` 调用：

```mio title="LowerTypesImport.mio" no-run
yobu "kiso/aot/lower/types";
```

### 执行类型分析与查询节点状态

调用 `types.analyze_types` 传入 `mochi.File` 后，应先检查 `result.error_detail == 0`，再查询各槽位及指令入口栈槽的分析结果：

```mio title="AnalyzeTypesDemo.mio" no-run
yobu "kiso/aot/lower/types";
yobu "kiso/encoding/binary";
yobu "kiso/encoding/mochi";

// 构造包含常量压栈与丢弃的最小模块（OpConst 0; OpPop）
kaku file = mochi.File {
    version: 14,
    constants: [
        mochi.Constant {
            tag: uint8(1),
            bits: binary.U64 { high: uint32(0), low: uint32(42) },
            data: []
        }
    ],
    global_count: 0,
    instructions: [1, 0, 0, 3],
    functions: []
};

kaku analysis = types.analyze_types(file);
moshi (analysis.error_detail == 0) {
    // 查询第 1 条指令（字节偏移 3 处的 OpPop）入口栈顶节点
    kaku stack = analysis.blocks[0].entry[3];
    kaku top = stack[0];

    chant(types.type_kind(analysis, top) == types.type_integer);
    chant(types.type_nullable(analysis, top));
    chant(types.type_is_heap_reference(analysis, top));
}
```

在上述示例中，`analysis.blocks[0]` 对应顶层主代码块（函数对应的 `TypeBlock` 位于 `blocks[function_id + 1]`）。字节偏移 `3` 处的栈顶元素被求解为非空 `type_integer`，因此 `type_is_heap_reference` 返回 `iie`，降级器无需将其登记为 GC 根。

### 表示类别与根判定规则

本模块维护的 13 个闭合类别常量描述的是**运行时物理表示形态**，而非源码层语法类型名称：

- **精确 GC 根判定（`type_is_heap_reference`）**：
    - 引用类别（`type_string_id`、`type_array_ref`、`type_struct_ref`、`type_enum_ref`、`type_function_ref`、`type_map_ref`）始终返回 `hai`（其中静态字符串常量以最低位为 `1` 的 Tagged ID 形式发布，GC 标记阶段会自动跳过）。
    - 基础标量类别（`type_integer`、`type_float32`、`type_float64`、`type_float_any`、`type_bool`）仅在标记为可空（`type_nullable == hai`，即需要分配 Type-106 堆装箱对象）时返回 `hai`；非空原始标量位模式绝不会被发布为堆根。
    - `type_unknown` 与 `type_nil` 始终返回 `iie`。
- **严谨的等价类合并（Strict Union）**：合并两条控制流分支时，`type_nil` 仅会为另一侧的具体类型补充 `nullable` 标记，而不会把两种不兼容的具体表示（如 `int64` 与 `string`）静默折叠为模糊指针。
- **路径敏感的非空窄化**：前向必经分析（Must-Analysis）会在 `OpIsNil` 条件分支的非空边上为未捕获的局部变量建立非空事实；若变量被闭包捕获为共享 `Cell`，在经历函数调用或写单元操作后该非空证明会自动失效。

### 公开常量（13 个）

| 常量                | 值   | 物理表示说明                                                             |
| ------------------- | ---- | ------------------------------------------------------------------------ |
| `type_unknown`      | `0`  | 尚未求解的约束变量或不可达位置                                           |
| `type_integer`      | `1`  | 64 位寄存器槽承载的有符号/无符号整数（具体位宽见 `integer_descriptor`）  |
| `type_float32`      | `2`  | IEEE 754 32 位单精度浮点数                                               |
| `type_float64`      | `3`  | IEEE 754 64 位双精度浮点数                                               |
| `type_bool`         | `4`  | 布尔值（`0` 或 `1`）                                                     |
| `type_string_id`    | `5`  | 字符串槽（Tagged 常量表 ID 或动态托管字符串描述符）                      |
| `type_array_ref`    | `6`  | 托管数组描述符引用                                                       |
| `type_struct_ref`   | `7`  | 托管结构体实例引用                                                       |
| `type_enum_ref`     | `8`  | 托管枚举实例引用                                                         |
| `type_function_ref` | `9`  | 托管闭包 / 函数值对象引用                                                |
| `type_nil`          | `10` | 纯 `mu` 空值                                                             |
| `type_float_any`    | `11` | 浮点宽度的多态表示（用于同时接受 `float32` 与 `float64` 的内置浮点谓词） |
| `type_map_ref`      | `12` | 托管 Map 映射描述符引用                                                  |

### 公开类型

```mio title="LowerTypesStructs.mio" no-run
// 并查集存储与类型约束图状态
koukai kata TypeArena {
    parent: []int64;
    revision: []int64;
    kind: []int64;
    nullable: []bool;
    struct_arity: []int64;
    struct_exact: []bool;
    fields: [][]int64;
    array_width: []int64;
    array_descriptor: []int64;
    integer_descriptor: []int64;
    map_written: []bool;
    targets: [][]int64;
    variants: [][][]int64;
    trace: []bool;
    context: []int64;
    nullable_origins: [][]int64;
}

// 单个代码块（顶层 main 或函数体）的逐字节入口栈快照与可达性
koukai kata TypeBlock {
    data: []uint8;
    function_id: int64; // 顶层 main 为 -1，其余为函数索引
    entry: [][]int64;   // entry[offset] 保存该字节偏移处的栈底到栈顶节点编号
    reachable: []bool;  // reachable[offset] 标记该字节偏移是否从入口可达
}

// 完整类型分析结果
koukai kata TypeAnalysis {
    arena: TypeArena;
    globals: []int64;     // 各全局变量槽位对应的类型节点编号
    locals: [][]int64;    // locals[function_id][slot] 对应的类型节点编号
    returns: []int64;     // 各函数返回值的类型节点编号（无返回值时为 -1）
    upvalues: [][]int64;  // 各函数捕获上值（Upvalue）的类型节点编号
    cells: [][]bool;      // cells[function_id][slot] 标记局部槽位是否被闭包捕获为共享 Cell
    blocks: []TypeBlock;  // blocks[0] 为顶层代码，blocks[id + 1] 为对应函数代码
    error_detail: int64;  // 0 表示求解成功；非 0 为打包的定位错误码
}
```

| ------------------------ | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `analyze_types`          | `analyze_types(file: mochi.File) -> TypeAnalysis`                     | 对 `mochi.File` 执行完整类型流求解与可达性分析（关闭溯源追踪）。                                                                          |
| `analyze_types_traced`   | `analyze_types_traced(file: mochi.File, trace: bool) -> TypeAnalysis` | 执行类型分析；当 `trace` 为 `hai` 时在 `arena.nullable_origins` 中记录可空性引入的指令来源。                                              |

### 使用限制与平台说明

- **节点编号归属**：传入 `type_kind`、`type_nullable`、`type_is_heap_reference` 等查询函数的 `node` 必须来自同一次 `TypeAnalysis` 实例；传入越界索引或跨分析实例混用会导致数组越界运行时错误。
- **专用内部表示**：本模块面向编译期静态类型求解与代码生成，不提供运行期动态反射能力，也不应将分析节点编号与运行时堆对象地址混淆。
