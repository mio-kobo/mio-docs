> **版本说明：** 本页对应 Mio V2.1 中的 `kiso/encoding/binary` 模块。全部 61 个公开函数与流式读写器均基于纯 Mio 源码与紧凑 `[]uint8` 存储实现，可在 Mochi VM、Web Playground 与原生 AOT 后端运行。

## 二进制编解码

二进制编解码标准库（`kiso/encoding/binary`）用于对 `[]uint8` 字节序列执行定宽有符号/无符号整数的小端（Little Endian）与大端（Big Endian）读写、LEB128 可变长度整数编解码，并提供带游标状态的 `BinaryReader` 与支持硬容量上限和偏移回填的 `BinaryWriter`。

本模块的所有偏移量与长度均以**字节**为单位。由于 Mio 当前未公开内置 `uint64` 基础数值类型，无符号 64 位位模式通过显式的 `U64 { high: uint32; low: uint32; }` 结构体表示，避免最高位被误解释为负数。

### 定宽大小端读写

定宽读取函数（如 `read_u16_le`、`read_i64_be`）接收字节数组与起始偏移量，返回包含 `value` 与可空 `error` 的结构体。定宽写入函数（如 `write_u32_le`、`write_i64_be`）直接在目标数组的现有位置修改字节，**不会自动扩容**，返回 `BinaryError?`。

```mio title="BinaryFixed.mio"
yobu "kiso/array";
yobu "kiso/encoding/binary";

kaku buf = array.make[uint8](12, uint8(0));

// 写入小端 uint16 与大端 int64
kaku err1 = binary.write_u16_le(buf, 0, uint16(4660));
kaku err2 = binary.write_i64_be(buf, 4, -42);

moshi (err1 == mu && err2 == mu) {
    kaku u16_res = binary.read_u16_le(buf, 0);
    kaku i64_res = binary.read_i64_be(buf, 4);
    moshi (u16_res.error == mu && i64_res.error == mu) {
        chant(u16_res.value); // 4660
        chant(i64_res.value); // -42
    }
}

// 越界访问安全返回 InsufficientData 错误，不会触发运行时崩溃
kaku oob = binary.read_u32_le(buf, 10);
chant(oob.error != mu); // hai
```

### 可变长度整数（LEB128）

`write_var_u32` 与 `read_var_u32` 使用无符号 LEB128 编码（最多 `5` 字节）；`write_var_i64` 与 `read_var_i64` 使用 DWARF 风格的有符号 LEB128 编码（最多 `10` 字节）。两种变长编码均**不是 ZigZag 编码**。

解码器会严格校验编码规范性，拒绝截断数据、数值溢出以及冗余前导零的非规范（Overlong）编码，并在结果中返回实际消费的字节数 `count`。

```mio title="BinaryVarint.mio"
yobu "kiso/encoding/binary";

kaku enc_u = binary.write_var_u32(uint32(300));
kaku dec_u = binary.read_var_u32(enc_u.data, 0);
moshi (dec_u.error == mu) {
    chant(dec_u.value); // 300
    chant(dec_u.count); // 2（占用 2 字节）
}

kaku enc_i = binary.write_var_i64(-123456);
kaku dec_i = binary.read_var_i64(enc_i.data, 0);
moshi (dec_i.error == mu) {
    chant(dec_i.value); // -123456
    chant(dec_i.count); // 3
}

// 非规范超长编码会被拒绝
chant(binary.read_var_u32([128, 0], 0).error != mu); // hai
```

### 流式读写器：BinaryReader 与 BinaryWriter

`BinaryWriter` 构造时需指定硬容量上限 `max_length`（字节数），支持顺序追加、长度前缀原子写入以及通过 `writer_reserve` 预留占位后调用 `writer_patch_*` 回填头部字段，最后通过 `writer_bytes` 导出独立的 `[]uint8` 副本。

`BinaryReader` 持有输入字节数组的只读视图与内部游标，每次成功读取都会自动推进游标；读取失败时游标保持在原位置不变。

```mio title="BinaryStream.mio"
yobu "kiso/encoding/binary";

// 创建上限为 64 字节的写入器
kaku w = binary.writer(64);
binary.writer_write_u8(w, uint8(1));

// 预留 4 字节用于后续回填负载长度
kaku slot = binary.writer_reserve(w, 4);
binary.writer_write_u64_be(w, binary.U64 { high: uint32(0), low: uint32(999) });

// 回填预留槽位
moshi (slot.error == mu) {
    binary.writer_patch_u32_be(w, slot.value, uint32(8));
}

// 导出独立字节流并使用 Reader 顺序解析
kaku r = binary.reader(binary.writer_bytes(w));
chant(binary.reader_read_u8(r).value);      // 1
chant(binary.reader_read_u32_be(r).value);  // 8
chant(binary.reader_read_u64_be(r).value.low); // 999
chant(binary.reader_eof(r));                // hai
```

### 公开类型

#### 错误与无符号 64 位表示

```mio title="BinaryTypes.mio" no-run
koukai sentaku BinaryError {
    InvalidOffset;    // 偏移量或跳过计数为负数
    InsufficientData; // 剩余字节不足以完成读取、写入或寻址
    Overflow;         // 超出 BinaryWriter 的 max_length 上限或 Varint 数值位宽溢出
    MalformedVarint;  // LEB128 编码不完整、超长或包含非规范前导零字节
}

// 无符号 64 位整数位模式（高低 32 位组合）
koukai kata U64 {
    high: uint32;
    low: uint32;
}
```

### 使用限制与平台说明

- **错误返回机制**：所有越界、容量溢出或格式错误均通过结果结构体中的 `BinaryError?` 返回，不会触发不可捕获的运行时异常；调用方在使用 `value` 或 `data` 前必须先检查 `error == mu`。
- **共享存储与隔离**：`BinaryReader` 与 `BinaryWriter` 内部持有对底层字节数组的共享引用；若需安全传递或修改输出缓冲区，请使用 `writer_bytes` 与 `reader_read_bytes` 返回的独立副本。

源码依据：[Mio V2.1 · `bunko/kiso/encoding/binary`](https://github.com/mio-kobo/mio/tree/Mio-2.1.2/bunko/kiso/encoding/binary)。
