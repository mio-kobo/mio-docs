## JSON 编解码 <FeatureBadge status="new" since="2.1" />

JSON 编解码标准库（`kiso/encoding/json`）提供符合 RFC 8259 规范的 UTF-8 JSON 解析与渲染功能。

该模块不将 JSON 对象直接转换为动态 `Map`，而是采用**扁平节点索引树（`Document`）**设计：解析后的每个 JSON 值存入 `Document.values` 数组，数组和对象通过整数索引（`children`）引用子节点，并将数字保存为原始 JSON 文本。这一设计避免了将 64 位大整数（如雪花 ID）提前转换为 `float64` 而导致的精度丢失。

### 解析 JSON 与读取字段

`json.parse` 接收 UTF-8 字节数组 `[]uint8`，返回 `Document`。使用前必须检查 `doc.error == ""`；若解析失败，`doc.error` 包含错误说明，`doc.offset` 记录出错时的字节位置，`doc.root` 为 `-1`。

```mio title="ReadJson.mio"
yobu "kiso/encoding/json";
yobu "kiso/string";

kaku payload = string.to_bytes("{\"id\":9223372036854775807,\"name\":\"Mio\",\"tags\":[\"v2\",\"aot\"]}");
kaku doc = json.parse(payload);

moshi (doc.error == "") {
    // 1. 读取大整数并保留完整 int64 精度
    kaku id_node = json.member(doc, doc.root, "id");
    kaku id = json.integer(doc, id_node);
    moshi (id != mu) {
        chant(id); // 9223372036854775807
    }

    // 2. 读取字符串字段（已自动解码转义序列）
    kaku name_node = json.member(doc, doc.root, "name");
    chant(json.text(doc, name_node)); // Mio

    // 3. 遍历 JSON 数组子节点
    kaku tags_node = json.member(doc, doc.root, "tags");
    moshi (tags_node >= 0) {
        kaku tags = doc.values[tags_node];
        kaku i = 0;
        aida (i < len(tags.children)) {
            chant(json.text(doc, tags.children[i]));
            i = i + 1;
        }
    }
}
```

在上述示例中，`json.member` 在对象节点中查找指定键名并返回对应子节点的整数索引，若键不存在或目标节点非对象则返回 `-1`（注意返回值为 `-1` 而非 `mu`）。当 JSON 对象包含重复键名时，`member` 从后向前查找并返回**最后一个同名成员**。

### 转义引号与渲染节点

`json.quote` 将普通字符串编码为带双引号的合法 JSON 字符串字面量（自动转义 `"`、`\`、控制字符 `\b`/`\f`/`\n`/`\r`/`\t` 以及其余 `< 0x20` 控制字节为 `\u00XX`）；`json.render` 则将指定节点及其子树渲染为无多余空白的紧凑 JSON 文本。

```mio title="RenderJson.mio"
yobu "kiso/encoding/json";
yobu "kiso/string";

kaku doc = json.parse(string.to_bytes("{ \"ok\": true, \"items\": [1, null, 7] }"));
moshi (doc.error == "") {
    // 输出紧凑 JSON：{"ok":true,"items":[1,null,7]}
    chant(json.render(doc, doc.root));
}

// 单独转义包含换行与引号的字符串
chant(json.quote("Hello\n\"Mio\"")); // "Hello\n\"Mio\""
```

### 公开类型

#### `Value` 与 `Document`

```mio title="JsonTypes.mio" no-run
// 单个 JSON 值的扁平节点表示
koukai kata Value {
    kind: int64;       // 节点类型编号（0 ~ 5）
    text: string;      // 原始文本或解码后的字符串内容
    children: []int64; // 子节点在 Document.values 中的索引列表（array 与 object 使用）
    keys: []string;    // 成员键名列表（仅 object 使用，与 children 一一对应）
}

// 解析后的 JSON 文档容器
koukai kata Document {
    values: []Value;   // 文档内全部扁平节点池
    root: int64;       // 根节点索引（失败时为 -1）
    error: string;     // 错误描述（空字符串 "" 表示解析成功）
    offset: int64;     // 解析结束或发生错误时的字节偏移量
}
```

#### `Value.kind` 类型编码对照

| `kind` 值 | JSON 类型 | `text` 字段内容                             | `children` / `keys` 内容                       |
| --------- | --------- | ------------------------------------------- | ---------------------------------------------- |
| `0`       | `null`    | `"null"`                                    | 均为空数组                                     |
| `1`       | `bool`    | `"true"` 或 `"false"`                       | 均为空数组                                     |
| `2`       | `number`  | 原始数字文本（如 `"-1.25e+3"`）             | 均为空数组                                     |
| `3`       | `string`  | 已解码转义与 `\uXXXX` 代理对后的 UTF-8 文本 | 均为空数组                                     |
| `4`       | `array`   | `""`                                        | `children` 按顺序保存元素节点索引；`keys` 为空 |
| `5`       | `object`  | `""`                                        | `keys` 与 `children` 按出现顺序一一对应        |

### 公开函数（6 个）

| 函数      | 公开签名                                                          | 功能与返回规则                                                                                                                    |
| --------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `parse`   | `parse(data: []uint8) -> Document`                                | 校验 UTF-8 并解析完整 JSON 文档；若输入非法、超出限制或末尾存在非空白多余数据，返回 `error != ""` 的 `Document`。                 |
| `member`  | `member(document: Document, object: int64, key: string) -> int64` | 在索引为 `object` 的对象节点中从后向前查找 `key`，返回匹配子节点的索引；未找到或节点类型非对象返回 `-1`。                         |
| `text`    | `text(document: Document, node: int64) -> string`                 | 返回索引为 `node` 的节点的 `text` 字段（字符串节点返回解码后文本，数字/布尔/null 返回原始文本，容器节点或越界索引返回 `""`）。    |
| `integer` | `integer(document: Document, node: int64) -> int64?`              | 仅当 `node` 为数字节点（`kind == 2`）且文本可无损解析为有符号 `int64` 时返回对应整数；小数、指数、越界或非数字节点一律返回 `mu`。 |
| `quote`   | `quote(text: string) -> string`                                   | 为 `text` 添加首尾双引号并转义必要字符，生成合法 JSON 字符串字面量。                                                              |
| `render`  | `render(document: Document, node: int64) -> string`               | 将 `node` 及其子节点递归序列化为紧凑 JSON 文本；若 `node` 索引越界则返回 `"null"`。                                               |

### 完整示例

下面的示例演示了从解析嵌套 JSON、安全提取整数字段与浮点原始文本、修改后重新渲染的完整流程：

```mio title="JsonWorkflow.mio"
yobu "kiso/convert";
yobu "kiso/encoding/json";
yobu "kiso/string";

kaku raw = "{\"service\":\"mio\",\"port\":8080,\"ratio\":-1.25e+3,\"dup\":1,\"dup\":2}";
kaku doc = json.parse(string.to_bytes(raw));

moshi (doc.error == "") {
    // 提取整数端口
    kaku port = json.integer(doc, json.member(doc, doc.root, "port"));
    moshi (port != mu) {
        chant(port); // 8080
    }

    // 科学计数法数字通过 text() 读取原始文本后再按需转为 float64
    kaku ratio_text = json.text(doc, json.member(doc, doc.root, "ratio"));
    kaku ratio = convert.parse_float64(ratio_text);
    moshi (ratio != mu) {
        chant(ratio); // -1250
    }

    // 重复键名返回最后一个匹配项
    chant(json.text(doc, json.member(doc, doc.root, "dup"))); // 2
}
```

### 使用限制与平台说明

- **资源与安全上限**：`json.parse` 在解析前会校验输入长度与 UTF-8 合法性，单次输入最大支持 **`67,108,864` 字节（64 MiB）**，嵌套结构深度上限为 **`256` 层**，单文档最多容纳 **`1,000,000` 个节点**，超出任意限制均安全返回错误。
- **严格 RFC 8259 语法**：解析器拒绝前导零数字（如 `01`）、尾随逗号（如 `[1,]`）、未完整指数（如 `1e+`）以及字符串中未转义的控制字符（`< 0x20`）。`\uXXXX` 支持 UTF-16 代理对（Surrogate Pair）合并解码，孤立代理项会被替换为 Unicode 替换字符 `U+FFFD`。
- **渲染与序列化边界**：`json.render` 面向由 `json.parse` 生成的合法无环节点图，不保证手工构造的循环引用节点图安全；当前模块未提供将任意 Mio `Map` 或自定义结构体直接自动序列化为 JSON 的反射接口。
