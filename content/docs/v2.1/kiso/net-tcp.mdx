## TCP 网络 <FeatureBadge status="new" since="2.1" /> <PlatformSupport showArch={true} systems={{ macos: { arm64: "full" }, linux: { x86_64: "full" }, windows: { x86_64: "full" } }} />

`kiso/net/tcp` 是 Mio v2.1.0 Bunko 标准库中的阻塞 IPv4 TCP 模块。用 `yobu "kiso/net/tcp";` 导入。使用 v2.1.0 原生 CLI 与同版本 Bunko（例如 [Full 发行包](/docs/v2.1/tooling/distribution)）；套接字操作依赖原生运行时。WebAssembly Playground 未嵌入该模块，也不提供 TCP 套接字，以下示例需在本机终端运行。

客户端用 `connect` 得到一个 `Connection`。服务端先用 `listen` 创建 `Listener`，再用 `accept` 为每个入站连接取得独立的 `Connection`。监听器只负责接入，字节读写都在连接上进行。阻塞调用会等待操作完成或失败，例如没有入站连接时，`accept` 会等待；没有数据时，非零长度的 `read` 会等待数据、EOF 或错误。

### 公开类型

| 类型 | 字段或用途 |
| --- | --- |
| `TcpError` | TCP 错误枚举，见下文的[错误处理](#错误处理)。 |
| `IPv4Address` | `octets: []uint8`（四个地址字节）；`port: int64`（有效范围 0–65535）。通常用 `ipv4` 构造。 |
| `Connection` | `handle: resource`，用于读写已建立的 TCP 连接。使用 `close` 释放。 |
| `Listener` | `handle: resource`，用于接收连接。使用 `close_listener` 释放。 |
| `ConnectionResult` | `connection: Connection?`、`error: TcpError?`。连接或接入成功时有连接，失败时连接为 `mu`。 |
| `ListenerResult` | `listener: Listener?`、`error: TcpError?`。监听成功时有监听器，失败时监听器为 `mu`。 |
| `ReadResult` | `count: int64` 为实际读取的字节数，`eof: bool` 表示读到流末尾，`error: TcpError?` 表示读取错误。 |
| `WriteResult` | `count: int64` 为实际写入的字节数（`write_all` 返回累计值），`error: TcpError?` 表示写入错误。 |
| `UnitResult` | `error: TcpError?`，关闭操作无其他返回值。 |

`error == mu` 表示操作没有报告错误。连接和监听器是运行时资源；复制结构体不会创建独立套接字，关闭后不要再使用持有同一资源的值。

### 公开函数（12 个）

读写的 `offset` 是从 0 开始的字节下标，`length` 是请求的字节数，两者都必须非负且指定区间不能越过数组末尾；否则返回 `InvalidArgument`。

| 公开签名 | 参数、返回值和使用要点 |
| --- | --- |
| `ipv4(a: uint8, b: uint8, c: uint8, d: uint8, port: int64) -> IPv4Address` | 按点分十进制地址的顺序传入四个字节和端口。只构造地址，不访问网络，也不验证端口；端口由 `connect` 或监听函数检查。 |
| `connect(address: IPv4Address) -> ConnectionResult` | 阻塞连接指定 IPv4 地址和端口。地址字节数不是 4 或端口越界时返回 `InvalidArgument`；目标拒绝连接时可返回 `ConnectionRefused`。成功后由调用方关闭连接。 |
| `listen(address: IPv4Address) -> ListenerResult` | 绑定本地地址和端口，以默认 backlog 128 开始监听。无效地址返回 `InvalidArgument`，端口冲突可返回 `AddressInUse`。回环实验绑定 `127.0.0.1`。 |
| `listen_with_backlog(address: IPv4Address, backlog: int64) -> ListenerResult` | 与 `listen` 相同，但可传入待接入队列的 backlog 参数（0–65535，由系统处理）。超出范围返回 `InvalidArgument`，绑定和监听也可能返回系统错误。端口 0 允许系统选端口；本模块没有查询所选端口的公开函数。 |
| `accept(listener: Listener) -> ConnectionResult` | 等待并接入一个连接。监听器已关闭时返回 `Closed`；系统接入失败时返回对应错误。新连接须单独关闭，监听器仍可接入下一条连接。 |
| `read(connection: Connection, destination: []uint8, offset: int64, length: int64) -> ReadResult` | 从连接读取到目标数组指定区间；只使用 `count` 个新读入的字节。无效区间、失效连接或读取失败均可报告错误。成功的零长度读取返回 0，且不表示 EOF。 |
| `write(connection: Connection, source: []uint8, offset: int64, length: int64) -> WriteResult` | 从来源数组的指定区间写入连接。返回实际写入的字节数，可能小于请求量；无效区间、失效连接或发送失败均可报告错误。继续写时按 `count` 推进偏移量。 |
| `write_all(connection: Connection, source: []uint8, offset: int64, length: int64) -> WriteResult` | 重复写入来源区间，直到写完或失败。无效区间返回 `InvalidArgument`；后续写入失败时保留累计 `count`；有剩余数据却写入 0 字节且无底层错误时返回 `Other("write made no progress")`。有效的零长度请求直接成功，不调用套接字。 |
| `close(connection: Connection) -> UnitResult` | 关闭一个连接并返回可空错误。关闭后不得继续读写；重复关闭会报告失效资源错误。 |
| `close_listener(listener: Listener) -> UnitResult` | 停止监听并返回可空错误。已接入的连接需要各自关闭；重复关闭可返回 `Closed`。 |
| `reader(connection: Connection) -> io.Reader` | 把连接包装为同步字节流读取器。构造时不读取，也不返回错误；读时复用 `tcp.read` 并将错误转换成 `io.IoError`。 |
| `writer(connection: Connection) -> io.Writer` | 把连接包装为同步字节流写入器。构造时不写入，也不返回错误；写时复用 `tcp.write` 并转换错误，单次写仍可能只写一部分。 |

### TCP 客户端：发送并读取回显

将下例保存为 `tcp-client.mio`。客户端连接 `127.0.0.1:18080`，发送代表 ASCII 文本 `Mio` 的三个字节。只有写完才等待同样长度的回显；读取成功后打印三个字节的十进制值。无论收发是否成功，已建立的连接都会关闭。

```mio title="tcp-client.mio" no-run
yobu "kiso/net/tcp";
yobu "kiso/io";

waza exchange(connection: tcp.Connection) -> unit {
    kaku data: []uint8 = [uint8(77), uint8(105), uint8(111)];
    kaku sent = io.write_all(tcp.writer(connection), data, 0, len(data));
    moshi (sent.error != mu || sent.count != len(data)) {
        chant("TCP write failed");
        kaesu;
    }
    kaku echo: []uint8 = [uint8(0), uint8(0), uint8(0)];
    kaku received = io.read_full(tcp.reader(connection), echo, 0, len(echo));
    moshi (received.error != mu || received.count != len(echo)) {
        chant("TCP read failed");
        kaesu;
    }
    chant(echo[0]);
    chant(echo[1]);
    chant(echo[2]);
}

waza main() -> unit {
    kaku address = tcp.ipv4(uint8(127), uint8(0), uint8(0), uint8(1), 18080);
    kaku connected = tcp.connect(address);
    kaku connection = connected.connection;
    moshi (connection == mu) {
        chant("TCP connect failed");
        kaesu;
    }
    exchange(connection);
    moshi (tcp.close(connection).error != mu) {
        chant("TCP close failed");
    }
}

main();
```

### TCP 服务端：实现回显

将下例保存为 `tcp-server.mio`。服务端在回环地址启动监听，接入一个客户端后等满三个字节，再把原字节写回。它先关闭客户端连接，最后关闭监听器。即使接入失败，也会关闭已创建的监听器。

```mio title="tcp-server.mio" no-run
yobu "kiso/net/tcp";
yobu "kiso/io";

waza echo_client(connection: tcp.Connection) -> unit {
    kaku data: []uint8 = [uint8(0), uint8(0), uint8(0)];
    kaku received = io.read_full(tcp.reader(connection), data, 0, len(data));
    moshi (received.error != mu || received.count != len(data)) {
        chant("TCP read failed");
        kaesu;
    }
    kaku sent = tcp.write_all(connection, data, 0, len(data));
    moshi (sent.error != mu || sent.count != len(data)) {
        chant("TCP write failed");
    }
}

waza main() -> unit {
    kaku address = tcp.ipv4(uint8(127), uint8(0), uint8(0), uint8(1), 18080);
    kaku started = tcp.listen(address);
    kaku listener = started.listener;
    moshi (listener == mu) {
        chant("TCP listen failed");
        kaesu;
    }

    chant("Mio TCP server waiting on 127.0.0.1");
    kaku accepted = tcp.accept(listener);
    kaku connection = accepted.connection;
    moshi (connection != mu) {
        echo_client(connection);
        moshi (tcp.close(connection).error != mu) {
            chant("TCP close failed");
        }
    } sore {
        chant("TCP accept failed");
    }
    moshi (tcp.close_listener(listener).error != mu) {
        chant("TCP close listener failed");
    }
}

main();
```

### 在两个终端运行完整 Echo 示例

在 Mio v2.1.0 源码根目录中使用正式版的 [服务端](https://github.com/mio-kobo/mio/blob/v2.1.0/examples/tcp_echo_server.mio) 和 [客户端](https://github.com/mio-kobo/mio/blob/v2.1.0/examples/tcp_echo_client.mio)。两端默认使用 `127.0.0.1:18080`，无需外部网络服务。先在终端 A 启动服务端：

```sh
mio run examples/tcp_echo_server.mio
```

看到 `Mio TCP server waiting on 127.0.0.1` 后，在终端 B 启动客户端：

```sh
mio run examples/tcp_echo_client.mio
```

客户端应报告连接成功、写入 3 字节、读回 3 字节，并依次输出 `77`、`105`、`111`。服务端写回 3 字节后退出；再次运行客户端前需重启服务端。若端口已被占用，给两端命令追加相同的 `-- <端口>`（1–65535）。运行上方教程版本时，把命令中的文件路径替换为保存的文件名，使用默认端口即可。

### 错误处理

先用 `moshi (failure != mu)` 判断有无错误，再用 `awase (failure)` 匹配枚举变体。使用可空的连接或监听器前也要确认它不为 `mu`。

| `TcpError` 变体 | 含义和处理 |
| --- | --- |
| `InvalidArgument` | 检查地址字节数、端口、backlog 或缓冲区范围；修改参数后再调用。 |
| `Closed` | 资源已关闭或句柄已失效；停止使用该资源，必要时重新建立连接或监听。 |
| `TimedOut` | 宿主报告超时。本模块没有公开的超时设置接口。 |
| `ConnectionRefused` | 对端拒绝建立连接。回环示例中先确认服务端正在监听，且两端端口相同。 |
| `ConnectionReset` | 连接被重置，与正常 EOF 不同。结束本次会话并释放连接；是否重连或重发由应用协议决定。 |
| `AddressInUse` | 本地地址或端口冲突。停止占用该地址的旧服务，或为客户端和服务端一起更换端口。 |
| `PermissionDenied` | 宿主拒绝操作；检查系统权限和策略。 |
| `WouldBlock` | 宿主报告操作会阻塞；该变体不代表模块提供非阻塞模式。 |
| `Other(string)` | 未归入上述分类的错误，字符串提供诊断信息。 |

短读或短写本身不是错误。循环读写时按 `count` 推进偏移量，处理剩余区间；如果出错，仍须考虑此前已处理的字节，避免从头盲目重发。对非零长度的读取，`error == mu` 且 `eof == hai` 表示对端已正常结束发送。EOF 不是空消息，也不是连接重置；需要固定长度时，数据未读满便遇到 EOF 属于协议数据不完整。

### 与 kiso/io 集成

`tcp.reader` 和 `tcp.writer` 把同一个连接包装成 [`io.Reader` 和 `io.Writer`](/docs/v2.1/kiso/io)。上面的客户端用 `io.write_all(tcp.writer(connection), data, 0, len(data))` 处理短写，用 `io.read_full(tcp.reader(connection), echo, 0, len(echo))` 读满固定长度；若提前到达 EOF，后者返回 `IoError.UnexpectedEOF` 和已读字节数。

适配器保留读写计数与读取的 EOF 标志。`InvalidArgument` 和 `Closed` 映射为同名的 `IoError` 变体，其余 TCP 错误转换为 `IoError.Other(string)`。若要按 `ConnectionReset` 等 TCP 变体分支，可直接用 `tcp.read` 或 `tcp.write`。适配器不会接管连接，仍需调用 `tcp.close`。

### 当前限制

- 只提供阻塞 IPv4 TCP。没有 DNS 解析、IPv6、UDP、TLS 或公开的超时配置接口。
- TCP 传输的是字节流，不保留消息边界。一次写入可能对应多次读取，多次写入也可能合在一次读取中。应用协议应自行约定长度、分隔符或其他边界规则。
- 读写都可能只完成一部分。检查 `count`、`error` 和读取的 `eof`；在成功和失败路径上都显式关闭已取得的连接与监听器。
