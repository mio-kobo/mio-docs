> **版本说明：** 本页对应 Mio V2.1 新增的 `kiso/net/tcp` 模块。该模块在纯 Mio 层封装连接管理、错误映射、短写重试与 `kiso/io` 流适配器，底层通过 `mio/sys/socket` 原语对接 Darwin ARM64 / Linux x86_64 系统调用与 Windows x86_64 Winsock，已在三平台正式版上通过完整回环通信与句柄复用测试。

## TCP 网络 <FeatureBadge status="new" since="2.1" /> <PlatformSupport showArch={true} systems={{ macos: { arm64: "full" }, linux: { x86_64: "full" }, windows: { x86_64: "full" } }} />

`kiso/net/tcp` 为 Mio 提供阻塞式（Blocking）IPv4 TCP 套接字通信能力，涵盖客户端发起连接（`connect`）、服务端绑定与监听（`listen` / `listen_with_backlog`）、接入入站连接（`accept`）、字节流读写（`read` / `write` / `write_all`）以及与 `kiso/io` 兼容的流适配器（`reader` / `writer`）。

所有套接字均为阻塞模式：当没有入站连接时 `accept` 会挂起等待；当接收缓冲区为空时非零长度的 `read` 会等待数据到达、对端优雅关闭（`eof == hai`）或发生连接错误。

### 构建 IPv4 地址与客户端连接

使用 `tcp.ipv4(a, b, c, d, port)` 构造点分十进制 IPv4 地址结构，随后传入 `tcp.connect`。调用方必须检查 `result.error == mu` 且 `result.connection != mu` 后再执行读写，并在结束时调用 `tcp.close` 释放句柄。

```mio title="TcpClient.mio" no-run
yobu "kiso/io";
yobu "kiso/net/tcp";
yobu "kiso/string";

waza exchange(conn: tcp.Connection) -> unit {
    kaku payload = string.to_bytes("Mio");
    kaku sent = tcp.write_all(conn, payload, 0, len(payload));
    moshi (sent.error != mu || sent.count != len(payload)) {
        chant("TCP write failed");
        kaesu;
    }

    kaku reply: []uint8 = [uint8(0), uint8(0), uint8(0)];
    kaku received = io.read_full(tcp.reader(conn), reply, 0, len(reply));
    moshi (received.error != mu || received.count != len(reply)) {
        chant("TCP read failed");
        kaesu;
    }

    chant(reply[0]); // 77 ('M')
    chant(reply[1]); // 105 ('i')
    chant(reply[2]); // 111 ('o')
}

kaku addr = tcp.ipv4(uint8(127), uint8(0), uint8(0), uint8(1), 18080);
kaku res = tcp.connect(addr);
kaku conn = res.connection;
moshi (conn != mu) {
    exchange(conn);
    tcp.close(conn);
} sore {
    chant("TCP connect failed");
}
```

### 服务端监听与接入回显

服务端通过 `tcp.listen`（默认待接入队列 backlog 为 `128`）或 `tcp.listen_with_backlog` 绑定本地端口并启动监听，随后循环或单次调用 `tcp.accept` 获取独立的客户端 `Connection`。监听器仅负责接收新连接，数据收发均在 `accept` 返回的 `Connection` 上完成。

```mio title="TcpServer.mio" no-run
yobu "kiso/io";
yobu "kiso/net/tcp";

waza handle_client(conn: tcp.Connection) -> unit {
    kaku buf: []uint8 = [uint8(0), uint8(0), uint8(0)];
    kaku req = io.read_full(tcp.reader(conn), buf, 0, len(buf));
    moshi (req.error == mu && req.count == len(buf)) {
        tcp.write_all(conn, buf, 0, len(buf));
    }
}

kaku addr = tcp.ipv4(uint8(127), uint8(0), uint8(0), uint8(1), 18080);
kaku started = tcp.listen(addr);
kaku listener = started.listener;

moshi (listener != mu) {
    chant("Mio TCP server waiting on 127.0.0.1:18080");
    kaku accepted = tcp.accept(listener);
    kaku client = accepted.connection;
    moshi (client != mu) {
        handle_client(client);
        tcp.close(client);
    }
    tcp.close_listener(listener);
} sore {
    chant("TCP listen failed");
}
```

### 公开类型

#### 错误枚举：`TcpError`

```mio title="TcpErrors.mio" no-run
koukai sentaku TcpError {
    InvalidArgument;   // 地址非 4 字节、端口越界（非 0~65535）、backlog 非法或缓冲区区间越界
    Closed;            // 连接或监听器已关闭，或引用了已失效的代际句柄令牌
    TimedOut;          // 底层套接字操作超时
    ConnectionRefused; // 目标地址与端口拒绝连接（无人监听或防火墙拒绝）
    ConnectionReset;   // 对端异常重置连接（RST）
    AddressInUse;      // 本地地址与端口已被其他套接字占用
    PermissionDenied;  // 操作系统拒绝绑定特权端口或网络权限不足
    WouldBlock;        // 底层套接字报告操作会阻塞
    Other(string);     // 未归入上述分类的其他底层网络错误信息
}
```

#### 地址、句柄与结果载体

```mio title="TcpTypes.mio" no-run
// IPv4 地址与端口（octets 必须包含 4 个字节，port 范围 0 ~ 65535）
koukai kata IPv4Address {
    octets: []uint8;
    port: int64;
}

// 受宿主代际检查保护的已建立 TCP 连接句柄（赋值复制会共享底层句柄状态）
koukai kata Connection {
    handle: resource;
}

// 受宿主代际检查保护的 TCP 监听套接字句柄
koukai kata Listener {
    handle: resource;
}

koukai kata ConnectionResult {
    connection: Connection?;
    error: TcpError?;
}

koukai kata ListenerResult {
    listener: Listener?;
    error: TcpError?;
}

koukai kata ReadResult {
    count: int64;     // 实际读入的字节数
    eof: bool;        // 对端是否已优雅关闭发送流（FIN）
    error: TcpError?; // 错误详情；为 mu 时表示成功
}

koukai kata WriteResult {
    count: int64;     // 实际写入（或 write_all 累计写入）的字节数
    error: TcpError?; // 错误详情；为 mu 时表示成功
}

koukai kata UnitResult {
    error: TcpError?;
}
```

### 公开函数（12 个）

#### 1. 地址构造、连接与监听（5 个）

| 函数                  | 公开签名                                                                      | 功能与返回规则                                                                                   |
| --------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `ipv4`                | `ipv4(a: uint8, b: uint8, c: uint8, d: uint8, port: int64) -> IPv4Address`    | 构造点分十进制 `a.b.c.d:port` 地址结构（纯内存构造，延迟至 `connect`/`listen` 时校验端口范围）。 |
| `connect`             | `connect(address: IPv4Address) -> ConnectionResult`                           | 阻塞发起 IPv4 TCP 连接；若地址非法返回 `InvalidArgument`，无人监听返回 `ConnectionRefused`。     |
| `listen`              | `listen(address: IPv4Address) -> ListenerResult`                              | 绑定本地 IPv4 地址与端口并以默认队列长度 `128` 启动监听（端口传入 `0` 由系统分配临时端口）。     |
| `listen_with_backlog` | `listen_with_backlog(address: IPv4Address, backlog: int64) -> ListenerResult` | 同 `listen`，允许显式指定待接入队列 `backlog`（合法范围 `0 ~ 65535`）。                          |
| `accept`              | `accept(listener: Listener) -> ConnectionResult`                              | 阻塞等待并接入一条入站连接，返回独立的客户端 `Connection`；若监听器已关闭则返回 `Closed`。       |

#### 2. 字节流读写、关闭与 `kiso/io` 适配（7 个）

| 函数             | 公开签名                                                                                          | 功能与返回规则                                                                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `read`           | `read(connection: Connection, destination: []uint8, offset: int64, length: int64) -> ReadResult`  | 从连接读取最多 `length` 字节到 `destination[offset .. offset+length)`，允许部分读取；对端关闭时返回 `eof: hai`；零长度读取直接成功且 `eof: iie`。 |
| `write`          | `write(connection: Connection, source: []uint8, offset: int64, length: int64) -> WriteResult`     | 将 `source[offset .. offset+length)` 写入连接，可能仅写入部分字节（`count <= length`）。                                                          |
| `write_all`      | `write_all(connection: Connection, source: []uint8, offset: int64, length: int64) -> WriteResult` | 循环调用 `write` 直至完整写出 `length` 字节；若中途出错保留累计 `count`，若出现无错误零写入则返回 `Other("write made no progress")`。             |
| `close`          | `close(connection: Connection) -> UnitResult`                                                     | 关闭已建立的 TCP 连接并释放句柄；重复关闭返回 `Closed`。                                                                                          |
| `close_listener` | `close_listener(listener: Listener) -> UnitResult`                                                | 关闭 TCP 监听器；已通过 `accept` 接入的连接不受影响，需各自单独关闭。                                                                             |
| `reader`         | `reader(connection: Connection) -> io.Reader`                                                     | 将 `connection` 包装为 `kiso/io.Reader`（自动将 `TcpError` 映射为 `io.IoError`，不接管关闭责任）。                                                |
| `writer`         | `writer(connection: Connection) -> io.Writer`                                                     | 将 `connection` 包装为 `kiso/io.Writer`（自动将 `TcpError` 映射为 `io.IoError`，不接管关闭责任）。                                                |

### 使用限制与平台说明

- **字节流边界与短读写**：TCP 是面向字节流（Byte-Stream）的传输协议，不保留发送端单次 `write` 的消息边界。读取固定长度报文请使用 `io.read_full(tcp.reader(conn), ...)`；区分连接正常结束（`eof == hai`）与异常中断（`ConnectionReset`）。
- **功能范围边界**：当前模块仅支持阻塞式 IPv4 字面量连接，不包含异步非阻塞事件循环、DNS 域名解析、IPv6、UDP、TLS 加密或公开的套接字超时参数配置接口（也未提供查询端口 `0` 实际分配端口号的公开函数）。
- **资源复用安全**：底层运行时对所有套接字资源采用代际检查句柄表（上限 `32` 个并发资源槽位），即使操作系统内核快速复用了已关闭的原始文件描述符，使用旧句柄令牌操作仍会安全返回 `TcpError.Closed`。
