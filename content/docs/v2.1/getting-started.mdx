## 开始使用 Mio

Mio 是一门使用日语罗马字关键字的静态强类型编程语言。你可以先在文档站的 Playground 中运行简单程序，再根据需要安装本地命令行工具（CLI）。

V2.1 延续了 V2.0 的语言基础，主要变化在编译器、Runtime 和 Bunko。**目前 V2.1 仍处于开发阶段，尚未提供可据本页确认的正式 V2.1.0 发行包。**

目前有三种常见的使用方式：

| 使用方式 | 适合对象 | 是否需要安装 Go |
| --- | --- | --- |
| 网页 Playground | 第一次体验 Mio、学习基础语法 | 不需要 |
| V2.0 正式发行包 | 学习已有功能、使用稳定版本的本地 CLI | 不需要 |
| V2.1 开发源码 | 体验新功能、参与工具链开发 | 构建方式不同，见下文“从源码构建 Mio” |

**V2.1 正在测试 macOS ARM64、Linux AMD64 和 Windows AMD64 原生版本。** Linux 和 Windows 目前仍属实验性平台；Intel Mac 与 Linux ARM64 暂不在这一批发行计划中。网页 Playground、V2.0 发行包和 V2.1 开发源码的功能范围可能不同。已实现但尚未正式发布的 Core / Full 候选包与 Docker 离线环境见 [发行包说明](/docs/v2.1/tooling/distribution)及 [Docker 开发](/docs/v2.1/tooling/docker)。

## 在浏览器中运行第一个程序

如果你正在 Mio 文档站阅读本页，可以直接运行下面的代码：

```mio title="Hello.mio"
chant("Hello, Mio!");
```

对于支持交互的代码块，点击 **运行** 即可执行程序，也可以点击 **检查** 只进行语法和类型检查。**编辑** 用于修改当前示例，**重置** 可以恢复原始代码。

在上述示例中，`chant()` 用于输出内容，语句以分号 `;` 结尾。简单的 Mio 程序可以直接编写顶层语句，不需要额外定义 `main` 函数。

每个 Playground 示例都是独立编译的程序。如果示例需要使用标准库，必须在同一个代码块内写出相应的 `yobu` 导入语句。例如：

```mio title="Math.mio"
yobu "kiso/math";

kaku value: float64 = 144.0;
chant(math.sqrt(value));
```

当前网页运行环境支持 `kiso/math`、`kiso/array`、`kiso/string`、`kiso/bytes` 和 `kiso/utf8`。其他未嵌入的包（例如 `kiso/fs`、`kiso/io` 和 `kiso/testing`）需要使用本地 Mio CLI。V2.1 新增的 JSON、正则表达式和 SHA-256 模块也不在当前 Playground 的内嵌范围内。

Playground 用于教学和快速试验，并不等同于完整的本地工具链。需要使用文件系统、测试、Mochi 字节码文件或 Native AOT 时，请继续按照下面的步骤安装 Mio。

## 使用 V2.0 正式发行包

如果你想先在本地学习 Mio 的基本语法，可以继续使用 **v2.0.0** 正式发行包。它已于 2026 年 10 月 21 日发布，包含 `mio`、`mochi-aot`、`mochi-aot-audit`、`native-aot` 和 Bunko 标准库。

**这一节安装的是 V2.0，不是 V2.1。** 两个版本的基础语言语法没有发生大规模变化；要查看 V2.1 CLI 与新增模块，请继续阅读后面的“从源码构建 Mio”。

发行包已经包含运行所需的程序，因此普通用户无须安装 Go。从源码重新构建工具链时才需要 Go。

### 下载并校验

前往 [Mio v2.0.0 Release](https://github.com/mio-kobo/mio/releases/tag/v2.0.0)，下载以下两个文件：

- `mio-2.0.0-darwin-arm64.tar.gz`
- `SHA256SUMS`

你也可以在终端中执行以下命令，下载并校验发行包：

```sh
mkdir -p "$HOME/.local/share/mio-2.0.0"
cd "$HOME/.local/share/mio-2.0.0"

curl -fLO https://github.com/mio-kobo/mio/releases/download/v2.0.0/mio-2.0.0-darwin-arm64.tar.gz
curl -fLO https://github.com/mio-kobo/mio/releases/download/v2.0.0/SHA256SUMS

shasum -a 256 -c SHA256SUMS
```

校验成功时应显示归档文件的 `OK` 状态。此版本归档大小为 `3,645,944` 字节，SHA-256 为 `15a7a65c048e4bac4dc1e792c2106df979d7e68ca28b36e213343c8d1e3dde2e`。

如果校验失败，应停止安装，重新检查下载文件与来源，不要直接运行未验证的程序。

### 解压与配置环境变量

在刚才的下载目录中执行：

```sh
cd "$HOME/.local/share/mio-2.0.0"
tar -xzf mio-2.0.0-darwin-arm64.tar.gz

export MIO_HOME="$PWD/mio-2.0.0-darwin-arm64"
export PATH="$MIO_HOME:$PATH"
export MIO_BUNKO="$MIO_HOME/bunko"

mio version
```

执行 `mio version` 时，应看到 `Mio 2.0.0`。

解压后的目录包含主要工具以及 Bunko 标准库：

```text
mio-2.0.0-darwin-arm64/
├── mio
├── mochi-aot
├── mochi-aot-audit
├── native-aot
├── native-aot.mochi
├── bunko/
├── examples/
└── docs/
```

其中，`MIO_BUNKO` 用于指定包含 `kiso/` 的物理标准库根目录。Mio 程序的导入路径不需要添加物理目录名称 `bunko/`。

如果使用 zsh，可以将以下内容添加到 `~/.zshrc`，使后续新终端自动获得相同配置：

```sh
export MIO_HOME="$HOME/.local/share/mio-2.0.0/mio-2.0.0-darwin-arm64"
export PATH="$MIO_HOME:$PATH"
export MIO_BUNKO="$MIO_HOME/bunko"
```

如果实际解压位置不同，请对应修改 `MIO_HOME`。使用 bash 时，可以根据自己的环境改为写入 `~/.bashrc`。

### 检查可执行文件与系统签名

可以进一步检查安装文件：

```sh
file "$MIO_HOME/mio"
codesign --verify --strict "$MIO_HOME/mio"
```

`file` 应将其识别为 ARM64 的 Mach-O 可执行文件。`codesign --verify --strict` 成功时不需要显示任何内容。

需要注意，v2.0.0 发行包使用 **ad-hoc 签名**，没有 Apple Developer ID 签名，也未经过 Apple notarization。签名结构验证通过不等同于 Apple 公证。如果 macOS 的 Gatekeeper 阻止首次运行，请核对下载来源并按照系统的“隐私与安全性”提示处理。

## 在本地运行 Mio 程序

创建一个名为 `hello.mio` 的 UTF-8 文本文件：

```mio title="hello.mio"
chant("Hello, Mio!");
```

如果按照前一节安装了 V2.0 正式发行包，进入该文件所在的目录，在终端中执行：

```sh
mio check hello.mio
mio run hello.mio
```

`mio check` 会加载源码和依赖、折叠编译期常量并完成名称与类型检查，但不会执行程序。检查通过时会显示 `check passed`。

这里的 `mio run` 会通过 Mochi VM 执行程序。V2.1 CLI 的 `run` 行为有所不同，见下文。

### 编译与执行 Mochi 字节码

除了直接运行源码，也可以先将程序编译为 `.mochi` 文件，再交给 VM 执行：

```sh
mio build -o hello.mochi hello.mio
mio exec hello.mochi
mio disasm hello.mochi
```

在 **V2.0 正式 CLI** 中，`mio build` 生成的是 **Mochi 字节码**，不是操作系统原生可执行文件。

`mio exec` 用于执行已经编译好的 `.mochi` 文件，而 `mio disasm` 用于查看字节码常量、指令及函数等结构。

如果想将受支持的 Mochi 程序转换为真正的 ARM64 Mach-O 原生程序，可以阅读 [Native AOT](/docs/v2.0/internals/native-aot)。原生编译使用独立的 `mochi-aot` 或 `native-aot`，而不是直接使用 `mio build`。

### V2.1 的原生编译

V2.1 CLI 默认将源码编译为原生可执行文件。如果需要保存 Mochi 字节码，可以显式指定 `--emit=mochi`。这与 V2.0 CLI 默认生成字节码的行为不同。

如果你已经获得了与当前开发源码匹配的 V2.1 CLI，可以使用下面的命令：

```sh
mio check hello.mio
mio build -o hello hello.mio
./hello

mio build --emit=mochi -o hello.mochi hello.mio
```

与 V2.0 正式 CLI 相比，V2.1 CLI 的主要行为变化如下：

| 命令 | V2.0 正式 CLI | V2.1 开发版 CLI |
| --- | --- | --- |
| `build` | 默认生成 `.mochi` 字节码 | 默认生成原生可执行文件，默认名称为 `a.out` |
| `run` | 通过 Mochi VM 执行 | 构建临时原生程序后执行 |
| `exec` | 执行 Mochi 字节码 | 将受支持的 Mochi 输入编译为原生程序后执行 |
| `build --emit=mochi` | 不是该 CLI 的新增选择方式 | 显式生成 Mochi 中间文件 |

上面的原生构建命令**不能直接交给 V2.0 发行包中的 `mio` 执行**。仅克隆 V2.1 源码也不会自动生成开发版 CLI；构建方法见 [工具链说明](/docs/v2.1/tooling/selfhost)。

V2.1 编译器支持较新的 Mochi 格式，而 V2.0 工具可能无法读取新版本字节码。macOS 的 ad-hoc 签名也不等于 Apple Developer ID 签名或 Apple 公证。具体兼容性见 [Mochi 格式](/docs/v2.1/internals/mochi)。

## 使用 Bunko 标准库

Bunko 是 Mio 的标准库，它通过 `yobu` 关键字按需导入。基础标准库使用 `kiso/` 作为公开导入路径。

例如，使用数学标准库计算平方根和最大公约数：

```mio title="Math.mio"
yobu "kiso/math";

kaku value: float64 = 144.0;
chant(math.sqrt(value));
chant(math.gcd(84, 30));
```

`yobu "kiso/math";` 用于导入数学包，默认限定名为导入路径最后一段 `math`，因此可以通过 `math.sqrt()` 和 `math.gcd()` 调用公开函数。

同样，动态数组的追加操作需要导入 `kiso/array`：

```mio title="Array.mio"
yobu "kiso/array";

kaku numbers = [10, 20];
array.push(numbers, 30);

chant(len(numbers));
chant(numbers[2]);
```

这些代码块都包含各自需要的导入语句，因此既可以在支持对应标准库的网页 Playground 中独立运行，也可以保存为 `.mio` 文件后通过 CLI 执行。

更多模块的用法见 [Bunko 标准库](/docs/v2.1/kiso)。文件系统和输入输出等模块未全部嵌入网页环境，建议使用本地 CLI 运行相关示例。

### V2.1 新增的 Bunko 模块

除了上面这些 V2.0 已经存在的模块，V2.1 开发源码还增加了：

| 导入路径 | 用途 | 使用范围 |
| --- | --- | --- |
| `kiso/encoding/json` | 解析、查询与生成 JSON | 保留数字原始文本，转换前应检查类型与结果 |
| `kiso/regexp` | 正则表达式编译与布尔匹配 | 支持部分 Unicode 特性，不提供完整捕获结果与替换 API |
| `kiso/crypto/sha256` | SHA-256 摘要计算 | 返回字节数组，正常摘要长度为 32 |
| `kiso/os` | 程序参数、环境、进程与部分系统服务 | 支持范围随目标平台而异，Windows 进程启动与 stdin polling 尚未实现 |

例如，使用 JSON 模块读取对象中的 `name` 字段：

```mio title="Json.mio" no-run
yobu "kiso/encoding/json";
yobu "kiso/string";

kaku document = json.parse(string.to_bytes("{\"name\":\"Mio\"}"));
moshi (document.error == "") {
    kaku name = json.member(document, document.root, "name");
    chant(json.text(document, name));
}
```

`json.parse()` 返回解析结果。读取字段之前应先检查 `error`，不要假设输入一定是合法 JSON。

正则模块可以判断字符串是否符合指定模式：

```mio title="Regexp.mio" no-run
yobu "kiso/regexp";

kaku pattern = regexp.compile("^Mio[0-9]+$");
moshi (pattern.error == "") {
    chant(regexp.matches(pattern, "Mio21"));
}
```

计算 SHA-256 摘要时，先将字符串转换为字节数组：

```mio title="SHA256.mio" no-run
yobu "kiso/crypto/sha256";
yobu "kiso/string";

kaku digest = sha256.sum(string.to_bytes("abc"));
chant(len(digest));
```

这些新增示例依据 V2.1 源码中已经核实的 API 整理，本次没有执行。需要使用包含相应模块及依赖的开发环境；现有网页 Playground 尚未提供这些新增包。

## 函数与基本程序结构

Mio 使用 `waza` 定义函数，使用 `kaesu` 返回结果：

```mio title="Function.mio"
waza add(a: int64, b: int64) -> int64 {
    kaesu a + b;
}

kaku result = add(20, 22);
chant(result);
```

函数参数需要明确的类型标注，返回值类型使用 `->` 指定。对于不返回普通值的函数，可以使用 `unit` 返回类型。

基础语法的完整说明可以从 [学习 Mio](/docs/v2.1/learn) 开始阅读；V2.1 没有新增一套需要重新学习的基础语法。

## 编写和运行测试

Mio 通过 `mio test` 运行测试文件。测试源码以 `_test.mio` 结尾，测试函数以 `test_` 开头，且应无参数、非泛型，并返回 `unit`。

创建 `example_test.mio`：

```mio title="example_test.mio" mode=test no-run
yobu "kiso/testing";

waza test_add() -> unit {
    testing.expect(1 + 1 == 2, "addition should work");
}
```

在包含该文件的目录中执行：

```sh
mio test .
```

`kiso/testing` 的断言能力只在 `mio test` 环境中注册，不能把测试文件当作普通 `mio run` 程序直接运行。`expect()` 在断言不成立时记录失败，测试结果由 CLI 汇总报告。

V2.1 的测试运行器延续相同的测试源码约定，并改为在隔离的原生进程中运行测试。使用时应确认当前 CLI 版本。

完整的测试命令、筛选和报告参数见 [开发工具](/docs/v2.1/tooling/cli)，断言 API 见 [kiso/testing](/docs/v2.1/kiso/testing)。

## 从源码构建 Mio

如果希望参与 V2.1 工具链开发，可以克隆 `Mio-2.1` 分支，再检出本页所依据的固定提交。这样后续分支更新不会影响当前阅读的源码内容。

```sh
git clone --branch Mio-2.1 https://github.com/mio-kobo/mio.git mio-source
cd mio-source
git checkout --detach 59002db2c9dc0c6dd11ff0f4341de42f79677df2

go build -o mio-ref ./cmd/mio
./mio-ref version
```

需要在本地准备与该仓库兼容的 Go 环境。上面的 `go build` 命令构建的是**参考 CLI**，并非 V2.1 原生发行候选。当前开发分支的版本文件也不能代替正式发行版本的确认。

V2.1 原生 CLI 的源码位于 `selfhost/cli/`，其构建流程需要匹配的引导程序及验证步骤。具体过程由 [自举与工具链文档](/docs/v2.1/tooling/selfhost)说明；本页不提供未经验证的下载地址。

在源码仓库内，`bunko/` 就是标准库物理根。如果要在其他目录运行自己编译的 CLI，请根据实际源码仓库位置设置 `MIO_BUNKO`，例如在源码仓库根目录执行：

```sh
export MIO_BUNKO="$PWD/bunko"
```

较早的开发版 CLI 可能内嵌 Bunko。V2.1 的 Core / Full 候选包已将标准库作为独立目录提供，并允许通过 `--bunko-root` 或 `MIO_BUNKO` 指定位置。详情见 [发行包说明](/docs/v2.1/tooling/distribution)。

本页固定提交已包含 TCP Socket、Native 实参检查与并发 GC 相关源码；源码存在不等于版本整体通过验收。在实验性平台上构建成功，也不等于该平台已获得 V2.1 正式支持。

## V2.1 开发状态

V2.1 正在完善原生编译、内存管理和标准库，部分功能仍处于实验阶段。在正式发行前，请以 [开发状态](/docs/v2.1/development) 与 [支持平台](/docs/v2.1/tooling/distribution) 为准。

想了解 GC、网络模块等功能的具体实现和验收结果，可继续阅读 [运行时与 GC](/docs/v2.1/internals/gc) 及相关开发文档。

## 常见问题

| 情况 | 检查方法 |
| --- | --- |
| 终端提示 `mio: command not found` | 如果使用 V2.0 发行包，检查 `PATH`；V2.1 开发源码不会自动生成可用的 `mio` |
| 导入 `kiso/math` 失败 | 确认 `MIO_BUNKO` 指向包含 `kiso/` 的 `bunko/` 根目录 |
| 网页提示 `undefined identifier "math"` | 确认当前代码块中包含 `yobu "kiso/math";` |
| 网页代码不显示运行按钮 | 检查是否为测试示例、代码片段，或导入了浏览器未嵌入的模块 |
| `mio check` 通过但没有程序输出 | `check` 不会执行程序；请使用 `mio run` 或 Playground 的“运行” |
| `mio build` 输出格式与预期不同 | 确认使用的是 V2.0 还是 V2.1 CLI；两者默认输出不同 |
| 直接打开 `.mochi` 无法执行 | 字节码不能当作原生程序；还需注意新 Mochi v16 与旧 Go decoder 的版本差异 |
| 网页无法导入 V2.1 新 Bunko 模块 | Playground 未嵌入这些模块，需使用能解析其依赖的本地开发环境 |
| 找不到 `kiso/net/tcp` | 确认 CLI 与 Bunko 来自匹配的 V2.1 开发提交；V2.0 不含此模块 |
| 运行测试失败 | 检查 `_test.mio` 文件名、`test_` 函数签名，并使用 `mio test` |
| macOS 拒绝打开可执行文件 | 检查架构、发布来源、哈希以及系统的 Gatekeeper 提示 |

更详细的错误类型与排查方法见 [故障排查](/docs/v2.1/tooling/troubleshooting)。
