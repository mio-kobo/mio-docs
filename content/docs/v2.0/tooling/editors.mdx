编辑器插件是独立于 Mio 核心仓库的项目，版本号不跟随 Mio 语言版本。本页依据各插件仓库的实际源码清单核对安装与配置；**没有在 IDE 中完成 v2.0.0 的端到端认证**，因此不把“源码声明的功能”写成“已在所有 IDE 版本中验证通过”。

| 插件 | 源码版本 | IDE 要求 |
| --- | --- | --- |
| VS Code `mio-language-support` | `0.3.0` | VS Code `^1.85.0` |
| JetBrains `Mio - Programming Language Tools` | `0.6.1` | IntelliJ IDEA / GoLand 2025.3，`sinceBuild 253` |

两个插件都需要一个可用的 Mio CLI。官方 v2.0.0 发行包只提供 macOS Apple Silicon ARM64 构建：

```sh
export MIO_HOME="$HOME/.local/share/mio-2.0.0/mio-2.0.0-darwin-arm64"
export PATH="$MIO_HOME:$PATH"
export MIO_BUNKO="$MIO_HOME/bunko"
mio version
```

预期输出 `Mio 2.0.0`。安装步骤见 [Getting Started](/docs/v2.0/getting-started)。

## VS Code

### 安装

插件身份为 `exmikupro.mio-language-support`，可从 Visual Studio Marketplace 安装：

- Marketplace：[Visual Studio Marketplace](https://marketplace.visualstudio.com/items?itemName=exmikupro.mio-language-support)
- 命令行安装 VSIX：

```sh
code --install-extension mio-language-support-0.3.0.vsix
```

从源码构建：

```sh
git clone https://github.com/mio-kobo/mio-vscode.git
cd mio-vscode
npm ci
npm run compile
npx vsce package
code --install-extension mio-language-support-0.3.0.vsix
```

安装后重新加载 VS Code，打开任意 `.mio` 文件。

### 配置 CLI 与 Bunko

插件优先使用 `mio.executablePath`，为空时在 `PATH` 中查找 `mio` 或 `mio.exe`。它不会扫描工作区寻找同名二进制。

```json
{
  "mio.executablePath": "/Users/you/.local/share/mio-2.0.0/mio-2.0.0-darwin-arm64/mio",
  "mio.languageServer.enabled": true,
  "mio.diagnostics.enabled": true,
  "mio.outputDirectory": ""
}
```

Bunko 路径没有单独的 `mio.bunkoPath` 设置。插件沿用 CLI 的查找规则：

1. 启动 VS Code 的环境变量 `MIO_BUNKO`；
2. 从源文件向上查找最近的 `bunko/` 目录。

如果 Bunko 不在项目内，请在启动 VS Code 的 shell 环境中设置：

```sh
export MIO_BUNKO="$MIO_HOME/bunko"
code .
```

### 设置

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `mio.executablePath` | 空 | CLI 绝对路径；空表示查找 `PATH`。支持 `~` 展开 |
| `mio.languageServer.enabled` | `true` | 使用 `mio lsp` 启动语言服务器 |
| `mio.diagnostics.enabled` | `true` | 诊断总开关 |
| `mio.diagnostics.onSave` | `true` | LSP 不可用时，保存后运行 `mio check` |
| `mio.outputDirectory` | 空 | `mio build` 的输出目录；空表示写在源文件旁 |

### 命令

| 命令 ID | 命令面板标题 |
| --- | --- |
| `mio.checkCurrentFile` | Mio: Check Current File |
| `mio.runCurrentFile` | Mio: Run Current File |
| `mio.buildCurrentFile` | Mio: Build Current File |
| `mio.showCompilerVersion` | Mio: Show Compiler Version |
| `mio.openOutput` | Mio: Open Output |

`Run Current File` 与 `Build Current File` 会先保存脏缓冲区。语言服务器运行时，诊断由 `mio lsp` 提供，手动 `Check Current File` 不会再启动一套重复的 CLI 诊断。

### 语言服务

VS Code 客户端通过 `mio lsp` 启动 MioCore LSP，支持：

- 实时诊断（包括未保存缓冲区）；
- Hover、Definition、References、Document Symbol、Completion、Signature Help；
- UTF-16 位置转换、增量编辑、版本校验和 `$/cancelRequest`。

语言服务器不可用或崩溃时，插件回退到 `mio check --format=json`，并清空另一套诊断，避免 Problems 面板同时显示两个来源。语法高亮和代码片段不依赖 CLI。

当前 LSP 诊断只发布第一条错误；Rename、Semantic Tokens、Formatting、Code Action、Workspace Symbols 没有实现。Rename 等能力不应写进工作流。

## JetBrains

### 安装

插件 ID 为 `com.exmikupro.mio`，显示名为 **Mio - Programming Language Tools**：

- Marketplace：[JetBrains Marketplace](https://plugins.jetbrains.com/plugin/35197-mio-language-support)
- 本地 ZIP：执行 `./gradlew buildPlugin` 后，在 **Settings → Plugins → Install Plugin from Disk...** 选择 `build/distributions/mio-language-support-*.zip`，重启 IDE。

源码版本 `0.6.1` 目标 IntelliJ IDEA 2025.3 / GoLand 2025.3（平台分支 253），使用 Java 21、Kotlin 2.2.20、IntelliJ Platform Gradle Plugin 2.19.0。它只依赖通用 IntelliJ Platform 模块，不依赖 GoLand 私有 API 或 Go 插件。

### 配置 Mio SDK

进入 **Settings → Languages & Frameworks → Mio SDK**：

- 查看已安装 SDK；
- 添加本地 CLI；
- 从 GitHub Releases 安装（按平台选择资产并验证 SHA-256）；
- 为 SDK 配置 Bunko 根目录；
- 为当前项目选择 SDK。

CLI 解析优先级：

1. Run Configuration 中显式配置的 CLI；
2. 项目选择的 Mio SDK；
3. 兼容路径；
4. `PATH`。

Bunko 路径通过 `MIO_BUNKO` 传给检查和运行，并作为补全与自动导入的索引根。未配置 Bunko 时，SDK 会显示为部分可用。

### 功能与边界

JetBrains 插件使用自己的轻量 PSI、解析器和 CLI 集成，**不是 MioCore LSP 客户端**。它提供：

- `.mio` 文件识别、语法高亮、括号匹配和注释；
- 参数、局部变量、函数、常量、类型、同目录包声明补全；
- Bunko `koukai` 成员补全、`yobu` 路径补全、自动导入与安全导入；
- 跳转、Find Usages、Quick Documentation；
- 后台调用 `mio check --format=json` 的诊断；
- Mio Run Configuration，可运行单个文件或包目录。

当前不支持持久化 StubIndex、安全重命名、完整表达式类型推断、LSP 和 Debugger。字段跳转依赖显式类型或可直接识别的结构体字面量；解析不唯一时不会猜测。

Run Configuration 保留程序参数字段，但当前 Mio CLI 不接受 `run <target>` 之后的程序参数；插件会在运行前明确报错，而不是静默丢弃。

### 源码构建

在插件仓库执行：

```sh
./gradlew test
./gradlew buildPlugin
./gradlew verifyPlugin
```

首次运行需要联网下载 Gradle、IntelliJ Platform 和测试依赖。ZIP 位于 `build/distributions/`。这些命令是插件仓库的构建入口；本页没有把它们标记为本轮已在所有 IDE 版本上验证。

## 常见问题

- **插件找不到 CLI**：设置 `mio.executablePath` 或把安装目录加入启动 IDE 的环境 `PATH`。GUI 启动的 VS Code / JetBrains 可能读不到你终端里的 `PATH`。
- **诊断提示找不到 `kiso/...`**：设置 `MIO_BUNKO` 指向发行包的 `bunko` 目录，并重启 IDE。
- **LSP 无法启动**：用 `mio lsp --stdio` 手动测试；确认 CLI 版本为 `2.0.0`，且 stdout 没有被其他程序污染。
- **运行配置参数被拒绝**：当前 CLI 不支持程序参数，移除参数或等待 CLI 支持。
- **v2.0.0 CLI 在 Intel Mac 上无法运行**：官方 v2.0.0 只提供 macOS ARM64 构建；插件本身不改变这一平台边界。

更多安装、Bunko 和原生工具问题见 [故障排查](/docs/v2.0/tooling/troubleshooting)。
