MioCore 是核心 CLI 内置的 stdio JSON-RPC 语言服务器。使用 `mio lsp` 或 `mio lsp --stdio` 启动；`--stdio` 是当前唯一支持的传输参数。

```sh
mio lsp --stdio
```

stdout **只用于**带 `Content-Length` 的 JSON-RPC 帧；日志和错误写 stderr。不能把 `mio lsp` 当作逐行 JSON 命令，也不要在 stdout 打印版本号、shell 提示或调试信息。

## 协议与能力

| 范围 | v2.0.0 状态 |
| --- | --- |
| 生命周期 | `initialize` / `initialized` / `shutdown` / `exit` |
| 文档同步 | open/close、增量 change、save；位置编码 `utf-16` |
| 诊断 | 名称解析、语法、类型检查；未保存文本参与分析 |
| Hover | 类型、签名与可提取的源码文档注释 |
| Definition / References | 语义符号身份与引用索引 |
| DocumentSymbol | AST 声明、字段、变体、参数 |
| Completion | 作用域、模块/成员、字段与变体候选，`.` 触发 |
| SignatureHelp | `(` 与 `,` 触发的调用参数信息 |
| 取消 | `$/cancelRequest` 与分析取消路径 |

`initialize` 返回的 `serverInfo` 为：

```json
{ "name": "MioCore", "version": "2.0.0" }
```

当前**没有**声明或实现 Rename、Semantic Tokens、Formatting、Code Action、Workspace Symbols 或 Debugger。编辑器自己的语法着色不是 LSP 语义着色。

## 分析范围与限制

- 使用真实 Lexer、Parser、Resolver、TypeChecker，不是正则或猜测。
- 结合导入图与已打开的文档；不等于对整个工作区的全部 `.mio` 建立持久索引。
- 当前诊断管线主要返回第一条错误；容错解析结果不能当作完整静态检查通过。
- Mio 源码位置、宿主 UTF-8 字节偏移和 LSP UTF-16 位置不同；实现中有 Unicode 与 CRLF 转换测试。
- 未保存缓冲区通过内存 overlay 参与分析，不会在磁盘创建临时文件。
- 同一文件同时只应有一个诊断来源；客户端应避免 LSP 与 CLI 诊断重复显示。

## 编辑器接入

外部编辑器应配置：

- 命令：Mio CLI 的绝对路径，或 `PATH` 中的 `mio`；
- 参数：`["lsp", "--stdio"]`；
- 环境：`MIO_BUNKO` 指向与 CLI 匹配的 Bunko 根。

VS Code 的具体设置、LSP 回退和 JetBrains 的独立 CLI 集成见 [编辑器](/docs/v2.0/tooling/editors)。

## 实测验证

本次文档验证使用官方 v2.0.0 发行包启动了真实 `mio lsp --stdio`，完成：

1. `initialize`，确认 `serverInfo = {"name":"MioCore","version":"2.0.0"}`；
2. 读取 capabilities，确认包含 completion、definition、documentSymbol、hover、references、signatureHelp、textDocumentSync 与 `positionEncoding`；
3. `shutdown` 后发送 `exit`，进程退出码 `0`。

这是一次协议级握手验证，不是 VS Code 或 JetBrains 的端到端 IDE 验收。
