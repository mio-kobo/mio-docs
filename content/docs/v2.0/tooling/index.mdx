## 开发工具

开发工具（Tooling）是用于编写、检查、编译、运行和维护 Mio 程序的一组工具。

Mio V2.0.0 提供命令行工具 `mio`、Mochi 字节码虚拟机、MioCore 语言服务器（LSP），并可与 VS Code 和 JetBrains 编辑器插件配合使用。

在 Mio 中，源码使用 `.mio` 扩展名。我们可以直接运行源码，也可以先将源码编译成 `.mochi` 字节码，再交给 Mochi VM 执行。

### 命令行工具

`mio` 是 Mio 的主要命令行入口。它提供静态检查、运行、字节码编译、字节码执行、反汇编、测试和语言服务器等命令。

常见操作如下：

| 命令 | 作用 |
| --- | --- |
| `mio version` | 查看 Mio 版本 |
| `mio check` | 解析并检查源代码，不执行程序 |
| `mio run` | 编译并通过 Mochi VM 运行程序 |
| `mio build` | 将 Mio 源代码编译成 `.mochi` 字节码 |
| `mio exec` | 执行已有 `.mochi` 字节码文件 |
| `mio disasm` | 查看 Mochi 字节码指令 |
| `mio test` | 发现和执行测试函数 |
| `mio lsp` | 启动 MioCore 语言服务器 |

例如，创建一个名为 `Hello.mio` 的文件：

```mio title="Hello.mio"
chant("Hello, Mio!");
```

随后在终端中执行：

```sh
mio check Hello.mio
mio run Hello.mio
```

上述代码可以直接在网页 Playground 中运行。终端命令则需要在已安装 Mio CLI 的本地环境中执行。

### 从源码到运行结果

Mio 的主要运行流程如下：

```text
Mio 源文件（.mio）
       │
       ├── mio check ──→ 语法、名称与类型检查
       │
       ├── mio run ────→ 编译为 Mochi ──→ Mochi VM 执行
       │
       └── mio build ──→ Mochi 字节码（.mochi）
                                  │
                                  ├── mio exec ──→ Mochi VM 执行
                                  └── mio disasm → 查看字节码
```

`mio build` 生成的是 Mochi 字节码，不是操作系统可以直接执行的机器码文件。

Mio V2.0.0 的正式发行包还提供 `mochi-aot` 和 `native-aot` 两个独立的原生编译工具，用于在已支持的平台上将 Mochi 转换为 ARM64 Mach-O 程序。原生编译与普通 `mio build` 是不同的操作。

### Bunko 标准库

Bunko 是 Mio 的标准库。其物理目录为 `bunko/`，但在源代码中应使用 `kiso/` 导入路径。

例如：

```mio title="Math.mio"
yobu "kiso/math";

kaku value: float64 = 144.0;
chant(math.sqrt(value));
```

每个网页 Playground 示例都是独立编译的程序，因此使用标准库的代码块应当自行包含需要的 `yobu` 语句。

本地 CLI 可以通过 `MIO_BUNKO` 环境变量指定标准库根目录。

### 编辑器和语言服务

MioCore 是 Mio CLI 内置的语言服务器，通过 `mio lsp --stdio` 与编辑器通信。它支持语法与类型诊断、悬停信息、定义跳转、引用查询、补全和函数签名提示。

VS Code 插件能够调用 MioCore LSP；JetBrains 插件则使用自己的编辑器解析与 CLI 集成机制。这两个插件是独立项目，其版本号不等于 Mio 语言版本。
