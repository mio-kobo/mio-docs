## 测试

测试标准库（Testing）用于在 Mio 测试函数中报告断言失败。它只在 `mio test` 环境提供所需的宿主测试接口，不能将其当作普通 `mio run` 程序中的通用输出或异常处理库。

测试源码以 `_test.mio` 结尾，测试函数名以 `test_` 开头、不能带参数、不能为泛型，并且返回 `unit`。

本页以 Mio `v2.0.0` 已实现的公开接口为准，不包含未实现的函数或语言语法。

### 导入包

> **运行环境：** 测试示例仅供 Mio CLI 的 `mio test` 使用。网页 Playground 不提供测试宿主接口，请将代码保存为 `answer_test.mio` 后执行 `mio test`。

通过 `yobu "kiso/testing";` 导入本包，随后使用 `testing.函数名(...)` 调用。

```mio title="Stdlib.mio"
yobu "kiso/testing";
```

### 编写测试函数

将测试逻辑放在顶层的 `test_` 函数里，再通过 `testing.expect` 检查条件。条件为 `iie` 时记录错误消息，但并不以异常方式立即停止整个函数。

```mio title="answer_test.mio" mode=test no-run
yobu "kiso/testing";

waza test_answer() -> unit {
    testing.expect(6 * 7 == 42, "answer should be 42");
}
```

### 主动标记失败

`testing.fail(message)` 无条件记录一次失败，适合处理测试逻辑中不应该到达的分支。

```mio title="answer_test.mio" mode=test no-run
yobu "kiso/testing";

waza test_unexpected() -> unit {
    moshi (iie) { testing.fail("unexpected state"); }
}
```

### 运行测试

使用 `mio test` 执行测试，而不是直接调用 `mio run`。测试文件中的普通顶层代码和待测源文件的加载行为应遵守 `mio test` 的测试发现规则。

### 公开函数（2 个）

以下签名保留已实现的函数名称、参数类型和返回类型。`unit` 表示无普通返回值；`T?` 与 `Error?` 需要根据 API 语义处理 `mu`。

| 函数 | 公开签名 | 功能与返回规则 |
| --- | --- | --- |
| `expect` | `expect(condition: bool, message: string) -> unit` | 在条件为 `iie` 时记录失败及消息。 |
| `fail` | `fail(message: string) -> unit` | 无条件记录一条测试失败。 |

### 完整示例

```mio title="answer_test.mio" mode=test no-run
yobu "kiso/testing";

waza test_answer() -> unit {
    testing.expect(6 * 7 == 42, "answer");
}
```

### 使用限制

完整示例应保存为 `answer_test.mio`，并在测试模式中执行。不要把 `_test.mio` 文件当作普通运行入口，也不要假设 `expect` 会停止当前函数的后续语句。
