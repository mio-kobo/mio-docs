## 文件系统

文件系统标准库（File System）提供同步文件打开、读写、关闭、目录创建、文件状态与目录列表等操作。

它借助宿主提供的文件系统能力执行操作。`File` 内部包含受信任的 `resource` 句柄，不是可以由 Mio 普通代码随意构造的操作系统指针。

本页以 Mio `v2.0.0` 已实现的公开接口为准，不包含未实现的函数或语言语法。

### 导入包

> **运行环境：** 当前网页 Playground 的 WASM 不包含此包。以下代码示例使用 Mio V2.0.0 CLI 与完整 Bunko 标准库，网页中仅展示代码，不提供无法运行的「运行」按钮。

通过 `yobu "kiso/fs";` 导入本包，随后使用 `fs.函数名(...)` 调用。

```mio title="Stdlib.mio"
yobu "kiso/fs";
yobu "kiso/string";
```

### 读取和写入整个文件

`read_all` 和 `write_all` 适合一次性处理一个文件。两者均通过结果类型返回 `error`；其中 `read_all` 返回字节数组，而不是自动解码后的文本。

```mio title="Fs.mio" no-run
yobu "kiso/fs";
yobu "kiso/string";

kaku written = fs.write_all("sample.txt", string.to_bytes("Mio"));
chant(written.error == mu);
kaku loaded = fs.read_all("sample.txt");
chant(loaded.error == mu);
```

### 显式打开与关闭

`open_read`、`open_write`、`open_append` 分别用于只读、创建或截断写入、追加写入。成功打开后可以调用 `read`、`write`；使用完毕应调用 `close`。

```mio title="Fs.mio" no-run
yobu "kiso/fs";
yobu "kiso/string";

kaku result = fs.open_read("sample.txt");
kaku file = result.file;
moshi (file != mu) {
    kaku closed = fs.close(file);
    chant(closed.error == mu);
}
```

### 文件和目录状态

`stat` 提供是否存在、是否为文件、是否为目录及错误详情。`exists`、`is_file`、`is_dir` 是便捷布尔函数，但会丢弃详细错误。`read_dir` 返回目录项数组。

```mio title="Fs.mio" no-run
yobu "kiso/fs";
yobu "kiso/string";

kaku info = fs.stat("sample.txt");
moshi (info.error == mu) { chant(info.exists); }
```

### 连接到 io

`fs.reader`、`fs.writer` 将文件句柄包装为 `kiso/io` 兼容的 Reader 或 Writer。适配器不会接管文件的关闭责任。

```mio title="Fs.mio" no-run
yobu "kiso/fs";
yobu "kiso/string";

kaku opened = fs.open_read("sample.txt");
kaku file = opened.file;
moshi (file != mu) {
    kaku reader = fs.reader(file);
    fs.close(file);
}
```

### 公开类型

- `File { handle: resource; }`：受宿主管理的文件句柄。
- `FileResult { file: File?; error: FsError?; }`：文件打开结果。
- `ReadAllResult { data: []uint8; error: FsError?; }`：完整读取结果。
- `UnitResult { error: FsError?; }`：无普通值的操作结果。
- `StatResult { exists: bool; is_file: bool; is_dir: bool; error: FsError?; }`：路径状态。
- `DirEntry { name: string; is_file: bool; is_dir: bool; }`：目录项。
- `DirResult { entries: []DirEntry; error: FsError?; }`：目录列举结果。
- `FsError`：文件系统操作错误的枚举。

### 公开函数（16 个）

以下签名保留已实现的函数名称、参数类型和返回类型。`unit` 表示无普通返回值；`T?` 与 `Error?` 需要根据 API 语义处理 `mu`。

| 函数 | 公开签名 | 功能与返回规则 |
| --- | --- | --- |
| `open_read` | `open_read(path: string) -> FileResult` | 以只读方式打开文件，失败时 `file = mu`。 |
| `open_write` | `open_write(path: string) -> FileResult` | 创建或截断文件，以写入方式打开。 |
| `open_append` | `open_append(path: string) -> FileResult` | 创建或以追加模式打开文件。 |
| `read` | `read(file: File, destination: []uint8, offset: int64, length: int64) -> io.ReadResult` | 从打开的文件读取字节，支持部分读取。 |
| `write` | `write(file: File, source: []uint8, offset: int64, length: int64) -> io.WriteResult` | 将字节写入文件，支持部分写入。 |
| `close` | `close(file: File) -> UnitResult` | 关闭文件句柄，重复关闭会返回错误。 |
| `reader` | `reader(file: File) -> io.Reader` | 将打开的文件包装为 io.Reader。 |
| `writer` | `writer(file: File) -> io.Writer` | 将打开的文件包装为 io.Writer。 |
| `read_all` | `read_all(path: string) -> ReadAllResult` | 打开、分块读取并关闭文件；错误时可能包含已读前缀。 |
| `write_all` | `write_all(path: string, data: []uint8) -> UnitResult` | 创建或截断文件，完整写入字节并关闭。 |
| `stat` | `stat(path: string) -> StatResult` | 返回文件是否存在、文件或目录的状态和错误。 |
| `exists` | `exists(path: string) -> bool` | 判断是否存在；不保留详细错误。 |
| `is_file` | `is_file(path: string) -> bool` | 判断是否为文件；不保留详细错误。 |
| `is_dir` | `is_dir(path: string) -> bool` | 判断是否为目录；不保留详细错误。 |
| `create_dir` | `create_dir(path: string) -> UnitResult` | 创建单级目录；不自动递归创建父目录。 |
| `read_dir` | `read_dir(path: string) -> DirResult` | 列举目录项并返回错误。 |

### 完整示例

```mio title="Fs.mio" no-run
yobu "kiso/fs";
yobu "kiso/string";

kaku written = fs.write_all("sample.txt", string.to_bytes("Mio"));
chant(written.error == mu);
kaku loaded = fs.read_all("sample.txt");
chant(loaded.error == mu);
chant(len(loaded.data));
chant(fs.is_file("sample.txt"));
kaku opened = fs.open_read("sample.txt");
kaku file = opened.file;
moshi (file != mu) {
    kaku first = fs.close(file);
    chant(first.error == mu);
}
```

### 使用限制

使用 `kiso/fs` 需要当前运行环境提供文件系统宿主接口；浏览器中的 Mio Playground 不等同于具有本机文件访问能力。文件的访问权限、路径解析与实际写入结果由宿主系统决定。复制 `File` 值会共享句柄状态，关闭后其他副本同样不能再用。
