## AOT 降低编译

AOT Lowering 模块将经过验证的 Mochi 字节码描述转换为用于生成 ARM64 可执行文件的指令字、常量区与地址修补记录。

这是工具链开发接口，普通 Mio 程序不应将它视为通用的 JIT 编译 API。

本模块属于 **AOT 编译工具链接口**，其公开声明不等于稳定的应用层 API；以下内容对应 `v2.0.0` 发布标签。

### 导入包

> **运行环境：** 当前网页 Playground 的 WASM 不包含此包。以下代码示例使用 Mio V2.0.0 CLI 与完整 Bunko 标准库，网页中仅展示代码，不提供无法运行的「运行」按钮。

通过 `yobu "kiso/aot/lower";` 导入本包，随后使用 `lower.函数名(...)` 调用。

```mio title="Stdlib.mio"
yobu "kiso/aot/lower";
```

### 编译结果

`compile` 接收已经解码的 `mochi.File`，返回 `LowerResult`。成功结果包含 `words`、`constants`、`patches` 和 `globals`；失败时 `error` 非空。

### GC 压力和堆大小

`compile_gc_stress` 采用 GC 压力配置；`compile_with_heap` 允许指定容量和 `gc_stress`。这是 v2.0.0 确认存在的公开函数，旧文档可能没有包含。

### 错误分类

`error_code` 和 `error_detail` 可从 `LowerError` 获取便于工具分析的数字类别与详细信息。这些数值不等同于操作系统的 errno。

```mio title="Lower.mio" no-run
yobu "kiso/aot/lower";

kaku error = lower.LowerError.UnsupportedConstant();
chant(lower.error_code(error));
```

### 公开类型

- `LowerError`：不支持的操作码、无效操作数、表示限制等降低编译错误枚举。
- `LowerResult { words: []uint32; constants: []uint8; patches: []macho.AddressPatch; globals: int64; error: LowerError?; }`：机器指令、常量区和修补记录。

### 公开函数（5 个）

以下签名保留已实现的函数名称、参数类型和返回类型。`unit` 表示无普通返回值；`T?` 与 `Error?` 需要根据 API 语义处理 `mu`。

| 函数 | 公开签名 | 功能与返回规则 |
| --- | --- | --- |
| `error_code` | `error_code(value: LowerError) -> int64` | 返回工具链定义的降低编译错误代码。 |
| `error_detail` | `error_detail(value: LowerError) -> int64` | 返回错误对应的细节编号。 |
| `compile` | `compile(file: mochi.File) -> LowerResult` | 使用默认设置降低已验证的 Mochi 文件。 |
| `compile_gc_stress` | `compile_gc_stress(file: mochi.File) -> LowerResult` | 在 GC 压力模式下降低文件。 |
| `compile_with_heap` | `compile_with_heap(file: mochi.File, capacity: int64, gc_stress: bool) -> LowerResult` | 指定堆容量与 GC 压力模式执行降低编译。 |

### 完整示例

```mio title="Lower.mio" no-run
yobu "kiso/aot/lower";

kaku error = lower.LowerError.UnsupportedConstant();
chant(lower.error_code(error));
chant(lower.error_detail(error));
```

### 使用限制

应先通过 `kiso/encoding/mochi` 对输入进行解码与验证，调用降低编译后检查 `LowerResult.error`。不是所有 Mochi 指令或数据表示都适合当前 AOT 路径，失败时不能把部分生成的数据视为可执行代码。
