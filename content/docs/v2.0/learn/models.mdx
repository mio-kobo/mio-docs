## 学习目标与前置

把相关字段组合成数据，并显式表示多种结果。 前置：[上课：Map 与缺失键](/docs/v2.0/learn/maps)。本章使用固定版本的 Go 引导 CLI / Mochi VM。

## 为什么需要

当多个值总是一起出现时，只用平行数组会让对应关系容易错位。结构体把命名字段装到一个类型里；枚举则表达一次结果只能属于其中一种情况。

## 保存与运行

在安装页的 `mio-tutorial` 目录保存为 `models.mio`，使用该版本构建的 CLI 和同一份 `bunko/`：

```sh
./mio check models.mio
./mio run models.mio
```

`check` 成功报告 `check passed`。下面是完整程序与 `run` 的标准输出，末尾包含换行。

```mio title="models.mio"
kata Pair<T> { first: T; second: T; }
sentaku Result<T, E> { Ok(T); Err(E); }
waza get(result: Result<int64, string>) -> int64 {
    awase (result) {
        baai Ok(value) { kaesu value; }
        baai Err(message) { chant(message); kaesu 0; }
    }
}
kaku pair = Pair[int64] { second: 22, first: 20 };
chant(pair.first + pair.second);
kaku result: Result<int64, string> = Result.Ok(7);
chant(get(result));
```

```text title="output"
42
7
```

## 逐段理解

`Pair<T>` 把两个同类型值作为 `first`、`second` 字段保存。构造时显式选择 `int64`，字段按名字指定，因此写入顺序不必与声明相同。这里先读回两字段求和，输出 42。

`Result<T, E>` 是本程序自行声明的示例类型，不是内置或承诺存在的 Kiso API。它的 `Ok` 携带一个值，`Err` 携带错误信息。目标标注 `Result<int64, string>` 给构造器提供完整类型上下文。

`get` 对枚举进行 `awase`，每个 `baai` 绑定对应载荷。必须覆盖所有变体；此例 `Ok` 直接返回整数，`Err` 输出信息后返回示例约定的 0。这个约定只属于本程序；生产代码应根据调用方需要设计错误处理，而不是把 0 普遍视为错误。

用户类型名以 ASCII 大写字母开头，结构体字段不能重新赋值。字段内若含共享数组或 Map，仍能通过集合修改存储，因此字段不可赋值不代表深不可变。泛型的具体推断规则留到后续课程。

## 练习

把 `Result.Ok(7)` 改为 `Result.Err("missing")`。 先预测再执行 `check` 与 `run`，预期逐行输出：

```text title="exercise-output"
42
missing
0
```

## 常见陷阱与核对

字段名不能缺失、重复或凭空增加；字段声明不允许事后重新赋值。`awase` 分支必须覆盖所有枚举变体，每个分支绑定的载荷数量须正确。示例的 Result 是用户类型，不要按内置错误处理机制使用它。
