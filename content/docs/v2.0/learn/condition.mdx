## 条件控制

条件控制（Conditional Control）用于根据不同的条件决定程序的执行流程。

在 Mio 中，我们可以通过条件控制让程序根据变量的值或表达式的结果，执行不同的代码。

Mio 使用 `moshi` 关键字进行条件判断，使用 `sore` 关键字表示条件不成立时执行的其他分支。

例如：

```mio title="Condition.mio"
kaku age = 18;

moshi (age >= 18) {
    chant("已成年");
} sore {
    chant("未成年");
}
```


在上述示例中，`moshi` 用于判断 `age >= 18` 是否成立。

当条件为 `hai` 时，执行 `moshi` 对应的代码块；当条件为 `iie` 时，则执行 `sore` 对应的代码块。

通过这种方式，我们可以让程序根据不同的情况执行不同的操作。

### 基本条件判断

Mio 中最简单的条件控制是 `moshi` 语句。

其基本语法如下：

```text
moshi (条件表达式) {
    // 条件成立时执行的代码
}
```

其中，`条件表达式` 必须返回 `bool` 类型的结果。

当条件为 `hai` 时，程序执行大括号中的代码；如果条件为 `iie`，则跳过该代码块。

例如：

```mio title="Condition.mio"
kaku score = 85;

moshi (score >= 60) {
    chant("考试及格");
}

chant("程序结束");
```


在上述示例中，`score >= 60` 的判断结果为 `hai`，因此程序会输出 `"考试及格"`。

如果将 `score` 修改为 `50`，条件不成立，程序会跳过 `moshi` 代码块，只输出 `"程序结束"`。

需要注意，`moshi` 的条件表达式必须使用括号 `()` 包围，执行的代码则需要使用大括号 `{}` 包围。

### 条件分支

当程序需要根据条件成立与否分别执行不同的代码时，可以使用 `moshi` 和 `sore` 组合。

基本语法如下：

```text
moshi (条件表达式) {
    // 条件成立时执行
} sore {
    // 条件不成立时执行
}
```

例如：

```mio title="Condition.mio"
kaku temperature = 28;

moshi (temperature >= 30) {
    chant("天气炎热");
} sore {
    chant("温度正常");
}
```


在上述示例中，程序首先判断 `temperature >= 30` 是否成立。

由于 `temperature` 的值为 `28`，条件不成立，因此程序会执行 `sore` 代码块。

需要注意，`sore` 是可选的。如果不需要在条件不成立时执行其他代码，可以省略 `sore`。

此外，`moshi` 和 `sore` 两个分支不会同时执行，程序只会选择符合条件的分支。

### 多条件判断

在实际开发中，有时需要根据多个不同的条件执行不同的操作。

Mio V2.0 可以通过嵌套 `moshi` 语句实现多分支判断。

例如：

```mio title="Condition.mio"
kaku score = 75;

moshi (score >= 90) {
    chant("优秀");
} sore {
    moshi (score >= 60) {
        chant("及格");
    } sore {
        chant("不及格");
    }
}
```


在上述示例中，程序首先判断 `score >= 90` 是否成立。

如果条件成立，则输出 `"优秀"`；否则进入 `sore` 分支，继续判断 `score >= 60`。

由于 `score` 为 `75`，因此程序最终输出 `"及格"`。

需要注意，Mio V2.0 目前不支持直接使用 `sore moshi` 作为连续分支语法。

如果需要实现多个条件分支，应当在 `sore` 的代码块中嵌套新的 `moshi` 语句。

### 逻辑条件

Mio 支持使用逻辑运算符组合多个条件，使程序能够执行更加复杂的判断。

常用的逻辑运算符包括：

| 运算符 | 名称 | 说明 |
| --- | --- | --- |
| `&&` | 逻辑与 | 两个条件都成立时返回 `hai` |
| `\|\|` | 逻辑或 | 任意一个条件成立时返回 `hai` |
| `!` | 逻辑非 | 将布尔值取反 |

例如：

```mio title="Condition.mio"
kaku age = 20;
kaku has_ticket = hai;

moshi (age >= 18 && has_ticket) {
    chant("允许进入");
} sore {
    chant("禁止进入");
}
```

在上述示例中，`&&` 表示逻辑与，要求 `age >= 18` 和 `has_ticket` 两个条件同时成立。

由于两个条件都为 `hai`，因此程序执行第一个分支。

如果只要求两个条件中有一个成立，可以使用 `||`：

```mio title="Condition.mio"
kaku is_admin = iie;
kaku is_owner = hai;

moshi (is_admin || is_owner) {
    chant("允许操作");
}
```


其中，只要 `is_admin` 或 `is_owner` 中有一个为 `hai`，整个条件就成立。

我们也可以通过 `!` 运算符对布尔值取反：

```mio title="Condition.mio"
kaku enabled = iie;

moshi (!enabled) {
    chant("功能未启用");
}
```

需要注意，Mio 的 `&&` 和 `||` 支持短路求值。

对于 `&&`，如果左侧条件已经为 `iie`，则不会继续计算右侧表达式；对于 `||`，如果左侧条件已经为 `hai`，也不会继续计算右侧表达式。

### 嵌套条件判断

Mio 允许在一个条件代码块内部继续使用 `moshi`，这种方式称为嵌套条件判断（Nested Conditional）。

例如：

```mio title="Condition.mio"
kaku age = 20;
kaku has_ticket = hai;

moshi (age >= 18) {
    chant("年龄符合要求");

    moshi (has_ticket) {
        chant("允许进入");
    } sore {
        chant("请先购买门票");
    }
} sore {
    chant("年龄不符合要求");
}
```

在上述示例中，程序首先判断年龄是否符合要求。

只有当 `age >= 18` 成立时，才会进入内部代码块，继续判断是否持有门票。

嵌套条件适合需要依次检查多个前置条件的场景。

不过，如果多个条件可以通过逻辑运算符直接组合，通常可以使用 `&&` 或 `||` 简化代码，避免出现过多的嵌套层级。

### 条件表达式的类型

Mio 是静态强类型语言，因此 `moshi` 的条件表达式必须是 `bool` 类型。

例如：

```mio title="Condition.mio"
kaku number = 10;

moshi (number > 0) {
    chant("正数");
}
```

这是合法的，因为 `number > 0` 是比较表达式，结果为 `bool`。

但是，下面的写法无法通过类型检查：

```text
kaku number = 10;

moshi (number) {
    chant("正数");
}
```

因为 `number` 是 `int64` 类型，而不是 `bool` 类型。

与某些编程语言不同，Mio 不会自动将非零整数转换为 `hai`，也不会将零转换为 `iie`。

如果需要判断一个整数是否为零，应使用明确的比较表达式：

```mio title="Condition.mio"
kaku number = 10;

moshi (number != 0) {
    chant("number 不等于零");
}
```

通过明确的比较条件，可以让程序的判断逻辑更加清晰。

### 可空类型的条件判断

Mio 还支持通过条件控制判断一个可空变量是否包含有效值。

可空类型使用 `?` 标记，空值使用 `mu` 表示。

例如：

```mio title="Condition.mio"
kaku score: int64? = 85;

moshi (score != mu) {
    chant(score + 5);
} sore {
    chant("分数尚未设置");
}
```

在上述示例中，`score` 被声明为 `int64?` 类型，因此可以保存一个整数，也可以保存 `mu`。

程序通过 `score != mu` 判断变量是否具有有效值。

当条件成立时，Mio 可以在对应的代码分支中将该变量收窄为非空的 `int64` 类型，从而安全地执行 `score + 5`。

同样，当 `score == mu` 时，也可以在 `sore` 分支中处理已经确认非空的值。

需要注意，这种类型收窄依赖明确的空值判断及变量状态。如果变量在判断之后被重新赋值，原先的非空判断结果可能不再有效。

### 条件代码块的作用域

在 Mio 中，每个使用大括号 `{}` 包围的条件代码块都会创建独立的词法作用域。

代码块内部声明的局部变量不会直接暴露到外部。

例如：

```mio title="Condition.mio"
kaku number = 10;

moshi (hai) {
    kaku number = 20;

    chant(number);
}

chant(number);
```

在上述示例中，条件代码块内部重新声明了一个名为 `number` 的变量。

内部变量会遮蔽外部的同名变量，但不会改变外部变量原来的值。

如果希望在条件分支中修改外部变量，应直接使用赋值语句，而不是重新声明一个同名变量。

例如：

```mio title="Condition.mio"
kaku number = 10;

moshi (number < 20) {
    number = 30;
}

chant(number);
```

这里的 `number = 30;` 修改的是已经声明的外部变量，因此离开代码块后仍然可以访问修改后的值。

### 条件控制的注意事项

在 Mio V2.0 中，使用条件控制时需要注意以下规则：

- `moshi` 后必须使用括号包围条件表达式。
- 条件表达式必须返回 `bool` 类型。
- 条件成立和条件不成立时分别执行对应分支，不会同时执行。
- `sore` 可以省略，但使用时必须跟随一个代码块。
- 多条件判断可以通过逻辑运算符或嵌套 `moshi` 实现。
- 每个条件代码块都有独立的词法作用域。
- 条件语句的代码块结束后不需要额外添加分号。

另外，`moshi` 是条件控制语句，而不是可以直接返回值的条件表达式，因此不能把整个 `moshi` 语句当作普通数值赋给变量。
