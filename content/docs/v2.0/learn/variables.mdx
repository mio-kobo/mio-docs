## 学习目标与前置

完成后，你能声明和更新变量、区分推断与显式标注，并为整数与浮点混合计算选择转换。前置知识是安装页的文件保存、`check` 与 `run`。

如果每次计算都直接写数值，修改输入时就要在多处查找。变量给数据一个名字；静态类型则让编译器在运行前发现把单价当成计数等不合法操作。

## 保存与运行

在安装页的 `mio-tutorial` 源码根目录，把下面程序保存为 `variables.mio`；保持 `bunko/` 可用。在同一目录执行：

```sh
./mio check variables.mio
./mio run variables.mio
```

`check` 成功报告 `check passed`；后面的 output 仅列 `run` 的标准输出，每行末尾包含换行。

## 完整程序

```mio title="variables.mio"
kaku count = 3;
count = count + 1;
kaku price: float64 = 2.5;
kaku total = float64(count) * price;
chant(count);
chant(total);
```

```text title="output"
4
10
```


## 从输入推导到输出

前两行处理数量：初始化给 `count` 类型 `int64`，重新赋值读取旧值 3，加一后写回 4。等号左侧是已有变量，右侧是计算，第二行不再写 `kaku`。

中间两行计算总价：`price` 明确为 `float64`；`float64(count)` 创建浮点值，原来的 `count` 仍是整数。乘法两端现在同为 `float64`，推断出的 `total` 也是浮点。

最后两行只负责观察结果。输出 `10` 是格式化后的文本，类型由声明与表达式决定，不能从是否出现小数点反推。

## 类型规则

整数字面量在没有目标类型时默认 `int64`，浮点默认 `float64`。有目标类型的字面量可以按上下文检查，例如单价的显式标注；已声明的不同数值类型变量相运算则需要转换。显式转换不是任意安全：转窄整数可能越界，整数转浮点也可能损失精度。此课只使用可精确表示的小值。

本例的 `count` 不断更新，适合变量。若一个值在编译时确定且不应改写，可以在后续参考中查 `teisu` 常量。

## 练习

把第一行改为 `kaku count = 5;`，保留后面的加一。运行前先计算预期结果。

预期依次输出 `6` 和 `15`。如果仍输出旧结果，检查保存的文件与命令中的路径是否一致。

## 常见错误

- 写成 `count = 2.5;`：原变量类型是 `int64`，不能通过赋值变成 `float64`。
- 写成 `count * price`：两侧类型不同，必须显式转换。
- 使用 `let` 或 `var`：Mio 的变量声明关键字是 `kaku`。

精确规则见 [语言参考](/docs/v2.0/reference/types)。下一课：[条件与循环](/docs/v2.0/learn/control-flow)。
