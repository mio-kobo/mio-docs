## 函数

函数（Function）用于将一段可以重复使用的代码组织在一起，使程序能够通过函数名称执行特定的操作。

当程序规模逐渐增大时，我们可以将不同功能拆分为独立的函数，从而减少重复代码，提高程序的可读性和可维护性。

在 Mio 中，使用 `waza` 关键字声明函数，使用函数名称和括号 `()` 调用函数。

例如：

```mio
waza greet() -> unit {
    chant("Hello, Mio!");
}

greet();
```

在上述示例中，`greet` 是我们定义的函数。

程序通过 `greet();` 调用该函数，执行函数体中的代码，并输出对应的内容。

Mio 支持函数参数、返回值、递归调用、匿名函数、闭包以及泛型函数等功能。

## 函数声明

Mio 使用 `waza` 关键字声明函数。

基本语法如下：

```text
waza 函数名(参数名: 参数类型) -> 返回类型 {
    函数体
}
```

一个函数通常由以下部分组成：

- `waza`：函数声明关键字。
- 函数名：用于标识和调用函数。
- `()`：函数参数列表，可以包含零个或多个参数。
- `->`：用于指定函数的返回类型。
- `{}`：函数体，包含调用函数时需要执行的代码。

例如，我们可以定义一个计算两个整数之和的函数：

```mio
waza add(a: int64, b: int64) -> int64 {
    kaesu a + b;
}

kaku result = add(10, 20);

chant(result);
```

在上述示例中，`add` 函数接收两个 `int64` 类型的参数，并返回它们相加的结果。

其中，`kaesu` 用于返回函数的计算结果。

调用 `add(10, 20)` 时，参数 `a` 和 `b` 分别接收 `10` 和 `20`，最终返回 `30`。

需要注意，Mio 的函数必须显式声明返回类型，即使函数不需要返回值，也必须使用 `-> unit`。

此外，函数声明末尾不需要添加分号。

## 函数参数

函数可以通过参数（Parameter）接收外部传入的数据。

在 Mio 中，每个函数参数都必须显式声明类型。

多个参数之间使用逗号 `,` 分隔。

例如：

```mio
waza introduce(name: string, age: int64) -> unit {
    chant(name);
    chant(age);
}

introduce("Mio", 18);
```

在上述示例中，`introduce` 函数包含两个参数：

- `name`：`string` 类型，用于接收姓名。
- `age`：`int64` 类型，用于接收年龄。

调用函数时，传入的实参（Argument）会按照参数声明的顺序与对应的形参匹配。

### 无参数函数

如果函数不需要接收任何数据，可以使用空参数列表 `()`。

例如：

```mio
waza answer() -> int64 {
    kaesu 42;
}

chant(answer());
```

即使函数没有参数，调用时仍然需要添加括号。

### 参数类型检查

Mio 是静态强类型语言，因此函数调用时会检查参数的数量与类型。

例如：

```mio
waza add(a: int64, b: int64) -> int64 {
    kaesu a + b;
}

chant(add(10, 20));
```

这是合法的，因为传入的两个参数都符合函数声明的类型要求。

但是，下面的调用无法通过类型检查：

```text
add(10);
add(10, 20, 30);
add(10, "Mio");
```

其中：

- `add(10)`：传入的参数数量不足。
- `add(10, 20, 30)`：传入的参数数量过多。
- `add(10, "Mio")`：第二个参数的类型不符合要求。

因此，调用函数时必须确保参数数量正确，并且参数类型能够与函数声明匹配。

## 函数返回值

函数可以通过 `kaesu` 关键字返回计算结果。

`kaesu` 对应的英文概念是 Return。

基本语法如下：

```text
kaesu 表达式;
```

执行 `kaesu` 后，当前函数会立即结束，并将表达式的结果返回给调用者。

例如：

```mio
waza square(value: int64) -> int64 {
    kaesu value * value;
}

chant(square(5));
chant(square(10));
```

在上述示例中，`square` 函数接收一个整数，并返回这个整数的平方。

函数的返回值可以直接作为其他表达式的一部分使用。

例如：

```mio
waza square(value: int64) -> int64 {
    kaesu value * value;
}

kaku result = square(3) + square(4);

chant(result);
```

其中，`square(3)` 返回 `9`，`square(4)` 返回 `16`，最终计算得到 `25`。

### 条件返回

函数可以根据不同条件返回不同的结果。

例如：

```mio
waza is_adult(age: int64) -> bool {
    moshi (age >= 18) {
        kaesu hai;
    } sore {
        kaesu iie;
    }
}

chant(is_adult(20));
chant(is_adult(15));
```

在上述示例中，`is_adult` 函数通过条件判断决定返回 `hai` 还是 `iie`。

由于函数声明的返回类型是 `bool`，因此所有返回值都必须符合该类型。

对于返回类型不是 `unit` 的函数，Mio 要求函数在所有静态可见的执行路径上返回正确类型的值。

如果某条执行路径可能在没有返回值的情况下结束，编译器会报告错误。

## 无返回值函数

有些函数只需要执行操作，不需要向调用者返回数据。

例如，输出文本、修改数组内容或执行某些状态更新操作。

这类函数可以使用 `unit` 作为返回类型。

例如：

```mio
waza show_message(message: string) -> unit {
    chant(message);
}

show_message("Hello!");
show_message("Welcome to Mio!");
```

在上述示例中，`show_message` 函数只负责输出传入的字符串。

由于函数的返回类型是 `unit`，因此不需要使用 `kaesu` 返回具体的值。

当函数执行到函数体末尾时，会自动结束。

### 提前结束函数

如果希望提前结束一个 `unit` 函数，可以使用：

```mio
kaesu;
```

例如：

```mio
waza greet(name: string) -> unit {
    moshi (name == "") {
        kaesu;
    }

    chant(name);
}

greet("");
greet("Mio");
```

在上述示例中，当 `name` 是空字符串时，函数会直接结束。

因此，第一次调用不会输出任何内容。

第二次调用传入 `"Mio"`，函数继续执行并输出对应的字符串。

需要注意，`unit` 函数不能通过 `kaesu` 返回具体数值，也不能将其调用结果保存为普通变量。

## 函数的作用域

在 Mio 中，函数参数和函数体内部声明的局部变量具有独立的词法作用域。

函数内部声明的局部变量，不能直接从函数外部访问。

例如：

```mio
waza calculate() -> int64 {
    kaku a = 10;
    kaku b = 20;

    kaesu a + b;
}

chant(calculate());
```

在上述示例中，`a` 和 `b` 都是 `calculate` 函数内部的局部变量。

当函数执行结束后，外部代码无法直接通过这些变量名称访问函数内部的数据。

### 参数与局部变量

函数参数也属于函数自身的局部作用域。

例如：

```mio
kaku value = 100;

waza display(value: int64) -> unit {
    chant(value);
}

display(10);

chant(value);
```

在上述示例中，函数参数 `value` 与外部变量 `value` 是两个不同的变量。

函数内部的参数会遮蔽同名的外部变量。

因此，调用 `display(10)` 不会改变外部变量保存的 `100`。

### 全局变量

Mio 的函数也可以访问当前包中可见的全局变量。

例如：

```mio
kaku counter = 0;

waza increment() -> unit {
    counter = counter + 1;
}

increment();
increment();
increment();

chant(counter);
```

在上述示例中，`counter` 是全局变量。

`increment` 函数每次执行时，都会将其增加 `1`。

因此，连续调用三次后，`counter` 的值变为 `3`。

虽然 Mio 允许函数修改全局变量，但在实际开发中，建议尽量通过函数参数和返回值传递数据，减少不必要的全局状态依赖。

## 函数参数与引用类型

Mio 的不同类型具有不同的值语义。

对于 `int64`、`bool` 等基础值类型，函数参数保存传入的值。

而数组和 Map 采用共享引用语义，将它们传入函数时不会自动复制整个集合。

例如：

```mio
waza replace(values: []int64) -> unit {
    values[0] = 99;
}

kaku numbers = [10, 20, 30];

replace(numbers);

chant(numbers[0]);
```

在上述示例中，`replace` 函数接收一个 `[]int64` 类型的数组。

由于数组采用共享引用语义，函数内部通过 `values[0] = 99;` 修改元素后，外部的 `numbers` 也能观察到这个变化。

需要注意，这并不代表 Mio 支持指针语法。

Mio 当前可以通过数组、Map 等类型共享可变数据，但尚未提供通用的取地址和解引用操作。

## 递归函数

递归（Recursion）是指函数在执行过程中再次调用自身。

递归适合处理能够分解为规模更小、结构相似的问题。

例如，我们可以通过递归实现阶乘计算。

数学中的阶乘定义为：

\[
n! = n \times (n-1) \times \cdots \times 1
\]

例如：

```mio
waza factorial(n: int64) -> int64 {
    moshi (n <= 1) {
        kaesu 1;
    } sore {
        kaesu n * factorial(n - 1);
    }
}

chant(factorial(5));
```

在上述示例中，`factorial` 函数会不断调用自身。

计算过程相当于：

```text
factorial(5)
= 5 * factorial(4)
= 5 * 4 * factorial(3)
= 5 * 4 * 3 * factorial(2)
= 5 * 4 * 3 * 2 * factorial(1)
= 120
```

当 `n <= 1` 时，函数直接返回 `1`，不再继续递归。

这个条件称为递归终止条件。

需要注意，递归函数必须设计合理的终止条件，否则可能持续调用自身，最终超过运行时允许的函数调用深度。

Mio 的 Mochi VM 对同时存在的函数调用层数设有限制，超过限制会产生运行时错误。

### 函数的声明顺序

Mio 支持在函数声明之前调用函数。

例如：

```mio
chant(square(6));

waza square(value: int64) -> int64 {
    kaesu value * value;
}
```

这是因为 Mio 会在检查函数体之前收集函数声明及其签名。

因此，函数不必按照调用顺序依次声明。

这一机制也允许不同函数之间进行相互递归调用。

## 匿名函数

除了通过名称声明函数，Mio 还支持匿名函数（Anonymous Function）。

匿名函数没有独立的声明名称，可以直接作为表达式创建，并保存到变量中。

基本语法如下：

```text
waza (参数名: 参数类型) -> 返回类型 {
    函数体
}
```

例如：

```mio
kaku double = waza (value: int64) -> int64 {
    kaesu value * 2;
};

chant(double(10));
chant(double(20));
```

在上述示例中，我们创建了一个匿名函数，并将其保存到变量 `double` 中。

之后可以像调用普通函数一样，通过 `double()` 执行该函数。

需要注意，匿名函数属于表达式。

当匿名函数作为变量的初始值时，整个变量声明语句仍然需要以分号结束。

## 函数类型

Mio 支持将函数作为一种值使用。

函数类型使用以下形式表示：

```text
(参数类型) -> 返回类型
```

例如：

```text
(int64) -> int64
```

表示接收一个 `int64` 参数，并返回一个 `int64` 结果的函数。

如果函数有多个参数，可以通过逗号分隔：

```text
(int64, int64) -> int64
```

如果函数没有参数，则使用空括号：

```text
() -> int64
```

### 将函数作为参数

由于函数可以作为值使用，因此也可以将一个函数传递给另一个函数。

这种接收其他函数作为参数，或者返回函数的函数，通常称为高阶函数（Higher-order Function）。

例如：

```mio
waza apply(
    value: int64,
    transform: (int64) -> int64
) -> int64 {
    kaesu transform(value);
}

waza double(value: int64) -> int64 {
    kaesu value * 2;
}

chant(apply(21, double));
```

在上述示例中，`apply` 函数接收两个参数：

- `value`：需要处理的整数。
- `transform`：接收一个整数并返回整数的函数。

调用 `apply(21, double)` 时，`double` 函数作为参数传递给 `apply`。

随后，`apply` 内部通过 `transform(value)` 调用传入的函数，最终得到 `42`。

通过这种方式，可以将通用的数据处理逻辑与具体操作分离，提高函数的复用能力。

## 闭包

闭包（Closure）是一种能够访问其定义位置外部变量的函数值。

Mio 支持词法闭包，可以通过匿名函数捕获外层作用域中的变量。

例如：

```mio
kaku offset = 5;

kaku add_offset = waza (value: int64) -> int64 {
    kaesu value + offset;
};

chant(add_offset(10));
```

在上述示例中，匿名函数使用了外部定义的变量 `offset`。

虽然 `offset` 并不是函数参数，但闭包仍然能够访问它。

### 使用闭包保存状态

闭包还可以捕获外层函数中的局部变量，使这些变量在外层函数返回之后仍然可以被访问。

例如：

```mio
waza make_counter() -> () -> int64 {
    kaku count = 0;

    kaesu waza () -> int64 {
        count = count + 1;
        kaesu count;
    };
}

kaku counter = make_counter();

chant(counter());
chant(counter());
chant(counter());
```

在上述示例中，`make_counter` 函数返回一个不接收参数、返回 `int64` 的匿名函数。

因此，它的返回类型是：

```text
() -> int64
```

返回的闭包捕获了外层函数中的 `count` 变量。

即使 `make_counter()` 已经执行结束，闭包仍然能够访问并修改这个变量。

每次调用 `counter()`，都会将捕获的 `count` 增加 `1`。

需要注意，Mio 的闭包可以共享被捕获的可变变量，因此多个闭包也可能观察到同一个变量发生的变化。

## 泛型函数

Mio 支持泛型函数（Generic Function），允许函数通过类型参数处理不同类型的数据。

泛型函数使用尖括号 `< >` 声明类型参数。

例如：

```mio
waza identity<T>(value: T) -> T {
    kaesu value;
}

chant(identity(42));
chant(identity[string]("Mio"));
```

在上述示例中，`T` 是函数的类型参数。

`identity` 函数接收一个 `T` 类型的值，并返回相同类型的结果。

因此，同一个函数既可以处理整数，也可以处理字符串。

### 类型参数推断

调用泛型函数时，Mio 通常可以根据实参推断类型参数。

例如：

```mio
waza identity<T>(value: T) -> T {
    kaesu value;
}

kaku number = identity(100);
kaku message = identity("Hello");
```

这里不需要显式写出 `T` 的具体类型。

Mio 可以根据调用时传入的数据，分别推断为 `int64` 和 `string`。

如果希望显式指定类型参数，可以使用方括号：

```mio
identity[int64](100);
identity[string]("Hello");
```

需要注意，Mio 使用尖括号声明泛型类型参数，但在函数调用时使用方括号指定具体类型。

### 泛型类型约束

Mio 还支持通过类型约束限制泛型参数可以接收的类型。

例如：

```mio
waza smaller<T: Number>(a: T, b: T) -> T {
    moshi (a < b) {
        kaesu a;
    }

    kaesu b;
}

chant(smaller(10, 20));
```

在上述示例中，`T: Number` 表示类型参数 `T` 必须满足数值类型约束。

Mio V2.0 提供以下数值泛型约束：

| 约束 | 允许的类型范围 |
|---|---|
| `Number` | 整数类型与浮点类型 |
| `Integer` | 整数类型 |
| `Signed` | 有符号整数类型与浮点类型 |
| `Float` | `float32` 与 `float64` |

通过这些约束，可以在保持类型安全的前提下，为不同数值类型复用同一套函数逻辑。

## 公开函数

默认情况下，Mio 包中的函数只能在当前包内部使用。

如果希望某个函数能够被其他包调用，可以在函数声明前添加 `koukai` 关键字。

例如：

```mio
koukai waza add(a: int64, b: int64) -> int64 {
    kaesu a + b;
}
```

在上述示例中，`add` 是一个公开函数。

当其他包通过 `yobu` 导入包含该函数的包后，可以通过包限定名访问这个函数。

没有使用 `koukai` 修饰的函数仍然可以在同一个包的其他源文件中调用，但不能直接从包外访问。

有关包的组织与导入规则，可以参考「包与模块」章节。

## 函数的注意事项

在 Mio V2.0 中，使用函数时需要注意以下规则：

- 使用 `waza` 关键字声明函数。
- 具名函数只能在文件顶层声明，不能直接在其他函数内部声明具名函数。
- 函数的每个参数都必须显式指定类型。
- 函数必须声明返回类型。
- 不需要返回值的函数应使用 `unit`。
- `kaesu` 用于结束当前函数并返回结果。
- 非 `unit` 函数必须在所有静态可见的执行路径上返回正确类型的值。
- `unit` 函数可以通过 `kaesu;` 提前结束，也可以在执行到函数体末尾时自动返回。
- 函数支持递归和相互递归。
- 函数声明顺序不要求与调用顺序一致。
- 函数参数和内部局部变量具有独立的词法作用域。
- 数组和 Map 作为函数参数传递时保留共享引用语义。
- 匿名函数可以保存到变量、作为参数传递或作为返回值。
- 闭包可以捕获外层作用域中的变量。
- 泛型函数可以通过类型参数复用相同的函数逻辑。
- 函数声明和代码块结束后不需要额外添加分号，但普通语句需要以分号结束。

此外，Mio 不允许在函数外部使用 `kaesu`。

对于递归函数，应确保存在合理的终止条件，避免无限递归导致运行时错误。
