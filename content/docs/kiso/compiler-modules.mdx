这些是真实存在的工具链开发接口。M18 已于 v2.0.0 通过验收，但公开 koukai 不等于稳定 ABI，也不表示所有 VM 程序都能通过 Native 后端。本页只审计声明及错误协议，不将未执行的开发 API 标记为所有平台或所有输入均已验证。

详细边界见 [V2.0 Native AOT](/docs/v2.0/internals/native-aot)。M18 证明的是 Mochi → Native 的纯 Mio 自编译；从 `.mio` 源码开始的完整工具链仍未完全摆脱 Go。`kiso/aot/*` 的公开声明不构成稳定 ABI 承诺。

## kiso/aot/arm64

编码器以 Instruction 返回 word/error，error 非空时不能发射 word。寄存器、立即数、移位、分支距离有范围检查；Assembler 另记录标签与 fixup，并可能报告重复/缺失标签与远分支错误。delta_words 是指令字数，adr/adrp 则依签名使用字节偏移。

以下为声明资料（未作为独立程序运行）：

## kiso/aot/macho

plan 的 code_size/const_size 是字节数，globals 是槽数；executable 以 ImageSpec 规划最终布局并返回 ImageResult。输出是未签名 Darwin ARM64 Mach-O 字节数组，须检查 error；不是跨平台系统链接器。

以下为声明资料（未作为独立程序运行）：

```text
koukai sentaku MachOError {
    EmptyText;
    TooManyGlobals;
    ImageTooLarge;
    LoadCommandsTooLarge;
    InvalidPatch;
    EncodeFailure;
    WriteFailure;
}

koukai kata AddressTarget { kind: int64; }

koukai waza text_target() -> AddressTarget

koukai waza const_target() -> AddressTarget

koukai waza data_target() -> AddressTarget

koukai kata AddressPatch { at_word: int64; add_at_word: int64; target: AddressTarget; target_offset: int64; register: int64; }

koukai kata Section { segment: string; name: string; file_offset: int64; vm_offset: int64; size: int64; alignment: int64; }

koukai kata Symbol { name: string; section: int64; value: int64; }

koukai kata Relocation { section: int64; offset: int64; symbol: int64; pc_relative: bool; width: int64; }

koukai kata Layout { text_size: int64; const_offset: int64; data_offset: int64; linkedit_offset: int64; file_size: int64; sections: []Section; }

koukai kata ImageSpec { words: []uint32; constants: []uint8; globals: int64; patches: []AddressPatch; }

koukai kata ImageResult { bytes: []uint8; layout: Layout; error: MachOError?; }
```

来源：`bunko/kiso/aot/macho/macho.mio`。

## kiso/aot/lower

compile 接受经验证的 mochi.File 并返回 LowerResult；compile_gc_stress 使用分配入口 GC stress。布局未知、操作数不合法或不支持的 opcode 必须返回 LowerError；error_code/error_detail 用于定位失败。目标 Heap 与执行 Builder 的 Seed Heap 不同。compile_with_heap 的 capacity 以字节计；不能据配置入口声称 A→B 通过。

以下为声明资料（未作为独立程序运行）：

```text
koukai sentaku LowerError {
    UnsupportedConstant;
    UnsupportedOpcode(int64);
    UnsupportedClosure;
    InvalidFunction;
    InvalidOperand(int64);
    FrameTooLarge;
    EncodeFailure;
    UnsafeType(int64);
    UnsupportedNative(int64);
    BranchOutOfRange(int64);
}

koukai kata LowerResult {
    words: []uint32;
    constants: []uint8;
    patches: []macho.AddressPatch;
    globals: int64;
    error: LowerError?;
}

koukai waza error_code(value: LowerError) -> int64

koukai waza error_detail(value: LowerError) -> int64

koukai waza compile(file: mochi.File) -> LowerResult

koukai waza compile_gc_stress(file: mochi.File) -> LowerResult

koukai waza compile_with_heap(file: mochi.File, capacity: int64, gc_stress: bool) -> LowerResult
```

来源：`bunko/kiso/aot/lower/lower.mio`。

## kiso/aot/lower/types

## kiso/aot/lower/nativefs

这是纯 Mio lowering 的 NativeFS MMA bridge，属于内部工具链 ABI。operation 依据包含签名指纹的完整名称识别操作，未识别返回 op_none；parameter_count、parameter_is_root、returns_reference 为发射调用及精确根提供参数/返回约定。entry_label 给出 Runtime 入口标签，emit_runtime 写入 arm64.Assembler，返回 unit；编码错误需结合 Assembler 的错误状态与最终组装结果检查。它不是文件操作的用户 API；用户应使用 kiso/fs。以下声明只核对源码，未作为完整 NativeFS API 验收。

```text
koukai teisu op_none = 0;

koukai teisu op_close = 1;

koukai teisu op_dir_close = 2;

koukai teisu op_dir_is_dir = 3;

koukai teisu op_dir_is_file = 4;

koukai teisu op_dir_name = 5;

koukai teisu op_dir_next = 6;

koukai teisu op_dir_status = 7;

koukai teisu op_file_status = 8;

koukai teisu op_mkdir = 9;

koukai teisu op_open = 10;

koukai teisu op_open_dir = 11;

koukai teisu op_read = 12;

koukai teisu op_stat = 13;

koukai teisu op_write = 14;

koukai waza operation(name: string) -> int64

koukai waza parameter_count(op: int64) -> int64

koukai waza entry_label(op: int64) -> string

koukai waza emit_runtime(code: arm64.Assembler, empty_tagged: int64) -> unit
```

来源：`bunko/kiso/aot/lower/nativefs/nativefs.mio`；调用编号/根约定不能替代 A→B 验收。
