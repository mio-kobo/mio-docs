# Mio v1.0 Beta 语言说明

本文记录 Mio v1.0 Beta 已实现的源码语法与静态类型规则。未在本文列出的语法不能视为可用功能。

## 源文件与词法规则

Mio 源文件使用 UTF-8。标识符由 ASCII 字母或下划线开头，后续可包含 ASCII 字母、数字和下划线。整数字面量使用十进制；除 `0` 外不能带前导零。浮点字面量可使用小数点或十进制科学计数法，例如 `3.14`、`1e3` 和 `2.5e-4`。

字符串使用双引号，支持 `\n`、`\r`、`\t`、`\"` 和 `\\` 转义。字符串不能直接跨行。字符使用单引号，内容必须是一个 Unicode 标量值；支持 Go 风格字符转义，包括 `\n`、`\t`、`\\`、`\'`、`\xNN`、`\uNNNN` 和 `\UNNNNNNNN`。

```mio
// 单行注释
/* 多行注释 */
chant("Mio\n");
```

语句以分号结束。函数声明和代码块本身不加分号。

## 类型

### 固定宽度整数

有符号整数包括 `int8`、`int16`、`int32` 和 `int64`，无符号整数包括 `uint8`、`uint16` 和 `uint32`。它们支持同类型的 `+`、`-`、`*`、`/` 和比较；有符号整数还支持一元负号。整数除法向零截断，除零产生运行时错误。

整数运算采用对应位宽的二进制补码回绕语义。加、减、乘或取负超出类型范围时保留低位；各有符号类型的最小值除以 `-1` 仍得到该最小值。没有明确类型上下文的整数字面量继续推断为 `int64`；带整数期望类型的字面量必须在目标范围内。

整数类型之间不进行隐式转换。`int8(...)`、`int16(...)`、`int32(...)`、`int64(...)`、`uint8(...)`、`uint16(...)` 和 `uint32(...)` 提供显式转换；缩窄、负数转无符号或其他越界转换产生运行时错误。整数与浮点数之间的显式转换同样检查目标整数范围。

### `rune`

`rune` 是 `int32` 的类型别名，没有独立的运行时表示。单引号字符字面量默认推断为 `rune`，`chant('A')` 因而按整数规则输出 `65`。字符字面量和整数字面量一样，可以在明确整数类型上下文中参与范围检查；普通数值之间仍不进行隐式转换。

### `float64`

`float64` 是 IEEE 754 binary64 浮点数。支持 `+`、`-`、`*`、`/`、一元负号和全部数值比较。浮点除零不产生运行时错误：非零值除以正负零产生带符号的 Infinity，零除以零产生 NaN。运算保留正零和负零；两者相等。NaN 与任何值（包括自身）的 `==`、`<`、`<=`、`>` 和 `>=` 都为假，`!=` 为真。

整数和 `float64` 之间没有隐式转换，不能混合算术、比较、赋值或函数传参。浮点数转整数向零截断；NaN、Infinity 或超出目标整数范围的值产生运行时错误。整数转 `float64` 遵循 IEEE 754 舍入规则，可能损失精度。

### `float32`

`float32` 是独立的 IEEE 754 binary32 类型。带 `float32` 期望类型的十进制字面量会直接舍入到 binary32；算术结果也在每一步按 binary32 舍入。它支持变量、数组、结构体字段、函数签名和泛型实参。

`float32`、`float64` 和全部整数类型之间禁止隐式转换。`float32(...)`、`float64(...)` 和整数类型名提供显式转换。

### 编译期常量

`teisu name[: type] = expression;` 声明基础不可变常量。表达式只能包含字面量、常量引用、纯运算和显式数值转换；常量在编译期折叠，不占全局槽位。`koukai teisu` 可以跨包公开常量。

### 数值泛型约束

函数类型参数可使用 `Number`、`Integer`、`Signed` 和 `Float` 约束。`Number` 包含全部整数和浮点类型；`Integer` 只包含整数；`Signed` 包含有符号整数和浮点类型；`Float` 只包含 `float32` 和 `float64`。约束不会引入隐式转换。`abs` 使用 `Signed`，无符号类型不会进入依赖负号语义的数学函数。

### `bool`

布尔值写作 `hai` 和 `iie`。`!` 执行逻辑非，`&&` 和 `||` 执行短路求值。`moshi` 条件必须是 `bool`。

### `string`

`string` 保存 UTF-8 文本。v0.1 支持字符串的 `==` 和 `!=`，不支持拼接或大小比较。

### `mu` 与 `T?`

`mu` 是空值字面量，运行时显示为 `mu`。`T?` 表示值可以是 `T` 或 `mu`。非空 `T` 可以安全赋给 `T?`，反向赋值不允许；`mu` 只能用于具有明确可空类型的变量、参数、数组元素或返回值，`kaku value = mu;` 仍然非法。`unit?` 和 `T??` 不允许。

```mio
kaku age: int64? = mu;
age = 18;
moshi (age != mu) {
    chant(age + 1);
}
```

`value != mu` 的真分支和 `value == mu` 的假分支会把可靠的变量引用收窄为非空类型。赋值和可能修改全局变量的函数调用会使相关事实失效。数组元素可能经由别名修改，因此索引检查不会形成持久收窄。

### `unit`

`unit` 表示函数没有返回值。它只用于函数返回类型，不会进入运行时 Value Stack，也不能保存到变量或传给 `chant`。

### `[]T`

`[]T` 表示元素类型为 `T` 的一维同质数组。数组字面量在运行时按从左到右的顺序计算元素，`values[index]` 读取元素，`values[index] = value;` 修改元素，索引必须是 `int64`。赋值类型必须与元素类型一致，负索引或超过数组长度会产生运行时错误。

```mio
kaku numbers = [10, 20, 30];
chant(numbers[1] + numbers[2]);
```

数组字面量的全部元素必须具有相同类型，空数组 `[]` 不能独立推断类型。数组采用共享引用语义，可用于函数参数和返回类型；变量赋值或参数传递不会复制元素，任一引用的元素修改对其他引用可见。内置函数 `len(array)` 返回 `int64` 长度。当前不支持字符串修改、切片、数组相等比较和多维数组。

`[]T?` 表示数组始终存在但元素可以为 `mu`；`([]T)?` 表示整个数组可以为 `mu`，非空时元素仍必须是 `T`。可空数组必须先通过空值检查收窄，才能索引或传给 `len`。

### 结构体

`kata` 声明具名结构体。用户定义类型名称必须以 ASCII 大写字母开头，以便显式类型参数与索引语法保持无歧义。构造时必须且只能初始化全部字段，字段可以按任意顺序书写。字段读取使用 `.`。

```mio
kata Point { x: int64; y: int64; }
kaku point = Point { y: 22, x: 20 };
chant(point.x + point.y);
```

结构体采用不可变值语义：赋值、传参、返回和放入数组都得到相同的逻辑值，源码不能修改既有结构体字段。实现可以共享不可变后备数据，但不得让共享状态对程序可见。结构体可以嵌套，也可以带普通类型参数。

### 枚举与关联数据

`sentaku` 声明具名枚举，变体可以携带零个或多个值。构造使用 `类型.变体(...)`，`awase` 必须为每个变体提供恰好一个 `baai`，并按声明的关联数据数量绑定名称。

```mio
sentaku Result<T, E> { Ok(T); Err(E); }

waza valueOrZero(result: Result<int64, string>) -> int64 {
    awase (result) {
        baai Ok(value) { kaesu value; }
        baai Err(message) { chant(message); kaesu 0; }
    }
}
```

分支不完整、重复、变体名称错误或绑定数量错误都会在编译期被拒绝。

### 泛型

函数、结构体和枚举可以使用普通类型参数。调用和构造通常从实参、字段或目标类型推断类型参数；方括号提供显式类型参数。

```mio
kata Pair<T> { first: T; second: T; }

waza first<T>(values: []T) -> T? {
    moshi (len(values) == 0) { kaesu mu; }
    kaesu values[0];
}

kaku pair = Pair[int64] { first: 20, second: 22 };
kaku item = first[int64](https://github.com/mio-kobo/mio/blob/29746a65692c73d637510cbc3f4463e68a49d05c/docs/[7, 8]);
```

泛型采用运行时擦除策略：每个泛型函数只有一份字节码，静态检查在调用点完成类型替换，因此递归不会触发编译期无限实例化。本版本不提供 HKT、型变或 trait 约束。

### 函数类型

函数类型写作 `(T, U) -> R`。具名函数和 `waza (...) -> R { ... }` 闭包都可以作为值保存、传参和返回，并可通过普通调用语法调用。闭包按词法作用域捕获变量；多个闭包对同一可变局部变量共享捕获 Cell。具名函数声明仍只能位于文件顶层。

```mio
waza apply<T, U>(value: T, transform: (T) -> U) -> U {
    kaesu transform(value);
}

kaku offset = 1;
kaku addOffset = waza (value: int64) -> int64 {
    kaesu value + offset;
};
```

### `Map<K, V>`

`Map<K, V>` 是共享可变键值集合。当前键类型只允许整数、`bool` 和 `string`，不能把任意运行时值当作可哈希值。泛型签名中的 `Map<K, V>` 会给 `K` 增加内建的可哈希约束，调用点必须推断或显式提供合法键类型。`Map[K, V]()` 显式创建 Map，也可以在 `Map<K, V>` 目标类型下使用 `Map()`。

```mio
kaku entries = Map[string, int64]();
entries["answer"] = 42;
kaku answer = entries["answer"];
moshi (answer != mu) { chant(answer); }
```

索引赋值负责插入和更新。索引读取返回 `V?`；键不存在时返回 `mu`，禁止未经收窄直接当作 `V` 使用。变量赋值和参数传递共享同一 Map，任一引用的更新对其他引用可见。VM 仍会拒绝不可哈希键和明显不一致的运行时键值种类。

## 变量与作用域

`kaku` 从初始化表达式推断变量类型。后续赋值必须保持相同类型。

```mio
kaku count = 1;
count = count + 1;
chant(count);
```

每个 `{}` 代码块创建词法作用域。内层声明可以遮蔽外层变量，赋值会修改名称解析到的既有变量。

```mio
kaku value = 10;
moshi (hai) {
    kaku value = 20;
    chant(value);
}
chant(value);
```

变量必须先声明再使用。同一作用域不能重复声明同名符号。

## 包与导入

一个目录对应一个包，同目录的 `.mio` 文件共享包级声明。`yobu "path";` 显式导入依赖，包成员以路径末段作为默认限定名；只有带 `koukai` 的函数、类型和常量可以从包外访问。依赖按稳定顺序加载，循环导入和越过 Bunko 根目录的路径会被拒绝。标准库的物理根目录是 `bunko/`，公开导入路径以 `kiso/` 开头，例如 `yobu "kiso/math";`。

## 条件分支

```mio
moshi (score >= 60) {
    chant("passed");
} sore {
    chant("failed");
}
```

`sore` 可以省略。`aida (condition) { ... }` 在条件为真时循环；`nukeru` 退出当前循环，`tsuzuku` 继续下一轮。

## 函数

函数只能在文件顶层声明。每个参数必须带类型，函数必须声明返回类型。

```mio
waza add(a: int64, b: int64) -> int64 {
    kaesu a + b;
}

waza show(value: int64) -> unit {
    chant(value);
    kaesu;
}
```

支持在声明前调用、递归和相互递归。非 `unit` 函数必须在所有静态可见路径上返回正确类型；`unit` 函数可使用 `kaesu;`，函数末尾也会隐式返回。

函数可以读取和修改可见的全局变量。函数调用会使可能受副作用影响的全局非空事实失效。闭包表达式可以嵌套并捕获外层局部变量，但具名函数声明不能嵌套。

## 内置函数

`chant(value)` 输出一个值并追加换行。参数可以是整数、浮点数、`bool`、`string` 或 `mu`，返回类型是 `unit`。

```mio
chant(42);
chant(3.14);
chant(hai);
chant("hello");
chant(mu);
```

## 运算符

从高到低的优先级为：

1. 字段读取 `.`、索引 `[]` 与函数调用 `()`
2. 一元 `-`、`!`
3. `*`、`/`
4. `+`、`-`
5. `<`、`<=`、`>`、`>=`
6. `==`、`!=`
7. `&&`
8. `||`

二元运算符左结合。算术和数值比较要求两侧为相同数值类型；相等比较要求两侧类型一致，支持全部整数、浮点数、`bool` 和 `string`。

## 资源限制

VM 的 Value Stack 最多保存 65,536 个值，同时存在的用户函数调用最多 1,024 层。每次执行默认最多运行 10,000,000 条指令，并可通过 Go API 的 `context` 提前取消。超过限制会产生运行时错误。

## 后续版本范围

trait、HKT、型变、反射、异常与 JIT 尚未实现。多维数组、切片、字符串修改以及数组、结构体和枚举的相等比较也不在当前版本范围内。Native AOT、独立 Runtime / GC、LSP 与 VS Code 扩展属于后续规划，不是 v1.0 Beta 的已完成功能。
